இந்த பக்கம் Claude Code-ஐப் பயன்படுத்தி JanVayu-ஐ உருவாக்குவதற்கான அன்றாடப் பணிப்பாய்வை ஆவணப்படுத்துகிறது — அம்சம் உருவாக்கம் முதல் பிழை திருத்தம் மற்றும் ஆவணப்படுத்துதல் வரை.

## அம்சம் உருவாக்கும் பணிப்பாய்வு

### படி 1: அம்சத்தை வரையறுத்தல்

தெளிவான, கட்டுப்பாடுகளை அறிந்த விளக்கத்துடன் தொடங்கவும்:

```
> வார்டு அளவிலான பொறுப்புக்கூறல் சுருக்க அம்சத்தைச் சேர்க்கவும்.
> இது ஒரு Netlify Function (ES module, .mjs) ஆக இருக்க வேண்டும், அது:
> - நகரத்தின் பெயரை உள்ளீடாக எடுத்துக்கொள்ளும்
> - WAQI-லிருந்து நேரடி AQI-ஐப் பெறும்
> - கட்டமைக்கப்பட்ட ப்ராம்ப்ட்டுடன் Groq-ஹோஸ்ட் செய்யப்பட்ட மாடலுக்குத் தரவை அனுப்பும்
> - தற்போதைய நிலை, NCAP இலக்குகள், 5 பொறுப்புக்கூறல் கேள்விகள் அடங்கிய சுருக்கத்தைத் திருப்பித் தரும்
> - Groq-ல் ரேட்-லிமிட் (rate-limited) இருந்தால் மாற்று வழியைக் கொண்டிருக்க வேண்டும்
> தற்போதுள்ள பாணிகளைப் பின்பற்றி index.html-ல் UI பகுதியையும் சேர்க்கவும்.
```

### படி 2: Claude ஆராய்கிறது

Claude Code படிக்கிறது:
- `index.html` — தற்போதுள்ள UI பாணிகள், CSS மாறிகள், JS மரபுகள்

- `netlify.toml` — வரிசைப்படுத்தல் கட்டமைப்பு

### படி 3: Claude செயல்படுத்துகிறது

Claude கோப்புகளை உருவாக்குகிறது/மாற்றுகிறது:

### படி 4: மதிப்பாய்வு செய்து மீண்டும் செய்தல்

```

> சுருக்கம் உருவாக்கப்படும்போது லோடிங் ஸ்பின்னரையும் (loading spinner) சேர்க்கவும்.
```

தொடர்பில்லாத குறியீட்டை மீண்டும் எழுதாமல், Claude குறிப்பிட்ட மாற்றங்களைச் செய்கிறது.

## பிழை திருத்தும் பணிப்பாய்வு

```
> WAQI முடங்கும்போது அனாமலி-செக் (anomaly-check) செயல்பாடு 500-ஐத் திருப்பித் தருகிறது.
> கேச் (cached) செய்யப்பட்ட தரவின் அடிப்படையில் அனாமலி ஃபிளாக்கைக் (anomaly flag) கொண்டு 200-ஐத் திருப்பித் தர வேண்டும்.
```

Claude Code:
1. `anomaly-check.mjs`-ஐப் படிக்கிறது
2. கையாளப்படாத பிழைப் பாதையை அடையாளம் காண்கிறது
3. கேச் செய்யப்பட்ட தரவுக்கு ஃபால்பேக் (fallback) உடன் try/catch-ஐச் சேர்க்கிறது
4. திருத்தத்தை கமிட் செய்கிறது

**முக்கிய கொள்கை:** *குறைந்தபட்ச மாற்றத்தை* செய்ய Claude-க்கு அறிவுறுத்தப்படுகிறது — முழு செயல்பாட்டையும் மாற்றி எழுதுதல் (refactoring) கூடாது.

## சிறப்பாகச் செயல்படும் Prompt Patterns

### புதிய அம்சங்களுக்கு

```
[feature]-ஐச் சேர்க்கவும். தேவைகள்:
- [Constraint 1]
- [Constraint 2]
[reference file]-இல் உள்ள தற்போதைய வடிவமைப்புகளைப் பின்பற்றவும்.
ஏற்கனவே உள்ள எந்தச் செயல்பாட்டையும் மாற்ற வேண்டாம்.
```

### பிழைத் திருத்தங்களுக்கு

```
[condition] ஆக இருக்கும்போது [Function] [error]-ஐத் தருகிறது.
எதிர்பார்த்தது: [correct behaviour].
இதைத் தீர்க்கச் சிறிய மாற்றத்தைச் செய்யவும்.
சுற்றியுள்ள குறியீட்டை மறுசீரமைக்க வேண்டாம்.
```

### ஆவணமாக்கலுக்கு

```
[topic]-க்கான ஆவணங்களை உருவாக்கவும்.
சேர்க்க வேண்டியவை: [specific sections].
ரெப்போவில் (repo) உள்ள உண்மையான குறியீடு மற்றும் அமைப்பைக் குறிப்பிடவும்.
[existing doc file]-இன் அதே நடையைப் பயன்படுத்தவும்.
```

### குறியீடு மதிப்பாய்வுக்கு

```
இவற்றுக்காக [file]-ஐ மதிப்பாய்வு செய்யவும்:
- பாதுகாப்புச் சிக்கல்கள் (குறிப்பாக API key வெளிப்படுதல்)
- CORS கையாளுதல்
- பிழை மீட்பு
- அணுகல்தன்மை
வரி எண்களுடன் குறிப்பிட்ட சிக்கல்களைப் பட்டியலிடவும்.
```

## இந்தச் செயல்முறையைத் திறம்படச் செயல்பட வைப்பது எது

1. **முழு குறியீடு தளச் சூழல் (Full codebase context)** — Claude குறியீடு எழுதுவதற்கு முன் உங்கள் குறியீட்டைப் படிக்கிறது
2. **கட்டுப்பாடுகளுக்கு முன்னுரிமை தரும் Prompts (Constraint-first prompts)** — Claude என்ன செய்ய *கூடாது* என்று கூறுவது, கட்டமைப்பில் வீக்கத்தைத் தடுக்கிறது
3. **தொடர்ச்சியான மேம்பாடு (Iterative refinement)** — ஒரே அமர்வில் மதிப்பாய்வு செய்து, சரிசெய்து, commit செய்யலாம்
4. **Git-native** — கிளைகள் (branches), commits, PR-கள் அனைத்தும் ஒரே கருவிக்குள்ளேயே நடக்கின்றன
5. **பல கோப்பு ஒருங்கிணைப்பு (Multi-file coordination)** — ஒரு prompt-ஆனது செயல்பாடுகள், HTML, CSS, JS மற்றும் ஆவணங்களைத் தொட முடியும்
6. **மறுஉருவாக்கம் செய்யக்கூடியது (Reproducible)** — ஒவ்வொரு அமர்வின் பணியும் தெளிவான செய்திகளுடன் git-இல் commit செய்யப்படுகிறது
