# திறன்கள் மற்றும் AI தூண்டுதல்கள்

இந்த பகுதி JanVayu-ஐ உருவாக்கவும் இயக்கவும் பயன்படுத்தப்படும் AI திறன் கோப்புகளை — system prompts, instruction patterns மற்றும் prompt engineering முடிவுகளை — ஆவணப்படுத்துகிறது.

இவை வெறும் வழிகாட்டுதல்கள் அல்ல. Health advisory, accountability brief மற்றும் anomaly-check prompts ஆகியவை code-base-ல் உள்ளபடியே இங்கு கொடுக்கப்பட்டுள்ளன; Ask JanVayu prompt மிகவும் நீளமானது என்பதால் அது சுருக்கமாகக் கூறப்பட்டுள்ளது. உருவாக்கத்தின் போது பயன்படுத்தப்பட்ட பரந்த prompting முறையையும் இந்தப் பக்கங்கள் விவரிக்கின்றன. நீங்கள் வேறொரு நகரத்திற்கோ அல்லது வேறு சுற்றுச்சூழல் துறைக்கோ JanVayu-ஐ fork செய்தால், இங்கிருந்து தொடங்குங்கள்.

## திறன் கோப்பு (Skill File) என்றால் என்ன?

ஒரு திறன் கோப்பு என்பது ஒரு குறிப்பிட்ட சூழலில் AI model எப்படி செயல்பட வேண்டும் என்று கூறும் ஒரு கட்டமைக்கப்பட்ட system prompt ஆகும். "காற்று தரம் குறித்த கேள்விகளுக்கு பதிலளிக்கவும்" என்பது போன்ற பொதுவான prompt-ஐ எழுதுவதற்குப் பதிலாக, ஒரு திறன் கோப்பு பின்வருவனவற்றை வரையறுக்கிறது:

- model-இன் **பங்கு மற்றும் ஆளுமை (role and persona)**
- சூழலாக அது பெறும் **தரவு**
- அது பின்பற்ற வேண்டிய **output format**
- தொனி, நீளம் மற்றும் தகவல்கள் மீதான **கட்டுப்பாடுகள்**
- தவிர்க்க வேண்டிய **தோல்வி முறைகள் (failure modes)**

JanVayu-வின் நான்கு Groq-ஆல் இயங்கும் அம்சங்களுக்கும் திறன் கோப்புகள் பயன்படுத்தப்படுகின்றன.

> **Update, 2 Oct 2026:** இந்தப் பக்கங்கள் Llama 3.3 70B-க்காக எழுதப்பட்டன, இது 16 Aug 2026 அன்று Groq-ஆல் நிறுத்தப்பட்டது. தற்போது அம்சங்கள் `GROQ_MODEL` அமைப்பின் மூலம் `openai/gpt-oss-120b` (ஒரு Apache-2.0 open-weight model) மூலம் இயங்குகின்றன.

## JanVayu-வில் பயன்படுத்தப்படும் பொதுவான Prompting கொள்கைகள்

அனைத்து திறன் கோப்புகளும் எவ்வாறு எழுதப்பட்டன என்பதை இந்தக் கொள்கைகள் வழிநடத்தின:
1. **உண்மையான தரவுகளை அடிப்படையாகக் கொள்ளுதல்** — ஒவ்வொரு தூண்டுதலுக்கும் (prompt) உண்மையான நேரடி எண்கள் வழங்கப்படுகின்றன. மாடல் (model) நினைவகத்தை மட்டுமே நம்பி எதையும் உருவாக்காது.
2. **வெளியீட்டு வடிவத்தை துல்லியமாக குறிப்பிடவும்** — குறிப்பாக பொறுப்புக்கூறல் சுருக்கத்திற்கு (accountability brief), மாடல் உருவாக்க வேண்டிய சரியான கட்டமைப்பு முன்கூட்டியே கூறப்படும்.
3. **நீளத்தை கட்டுப்படுத்துதல்** — அதிகப்படியான உருவாக்கத்தைத் (over-generation) தடுக்க, அனைத்து தூண்டுதல்களிலும் வார்த்தை அல்லது டோக்கன் (token) வரம்புகள் தெளிவாக சேர்க்கப்பட்டுள்ளன.
4. **தோல்வி முறையை பெயரிடுதல்** — மாடலிடம் என்ன செய்யக்கூடாது என்று தூண்டுதல்கள் தெளிவாகக் கூறும் (உதாரணமாக, "பொதுவான ஆலோசனைகளை வழங்க வேண்டாம்", "தவிர்த்துப் பேச வேண்டாம்").
5. **இயல்பாகவே பன்மொழி** — தேவைப்படும் இடங்களில், பயனரின் மொழியிலேயே பதிலளிக்க மாடலுக்கு அறிவுறுத்தப்படும்.
6. **அழகாக பின்வாங்கவும் (Fallback gracefully)** — API அழைப்பு தோல்வியடைந்தால் மூலத் தரவை (raw data) திருப்பித் தரும் வகையில், ஒவ்வொரு செயல்பாட்டிற்கும் AI அல்லாத ஒரு மாற்று வழி (non-AI fallback) உள்ளது.
