# திறன்: முரண்பாடு விளக்கம்

**பயன்படுத்தப்படுவது:** `netlify/functions/anomaly-check.mjs`  
**மாதிரி:** Groq வழியாக `openai/gpt-oss-120b` (இயல்புநிலை, `GROQ_MODEL` மூலம் அமைக்கப்பட்டது; 16 ஆகஸ்ட் 2026 அன்று Groq ஓய்வு பெறும் வரை Llama 3.3 70B)  
**தூண்டுதல்:** தேவைப்படும்போது அழைக்கப்படும்; ஐந்து முக்கிய நகரங்களை பருவகால அடிப்படை அளவுகளுடன் (seasonal baselines) சரிபார்க்கும்

---

## இந்த திறன் என்ன செய்கிறது

நேரடி அளவீடுகளை, முன்பே வரையறுக்கப்பட்ட பருவகால அடிப்படை அளவுகளுடன் ஒப்பிட்டு ஐந்து முக்கிய நகரங்களில் PM2.5 அதிகரிப்பை இது கண்டறிகிறது. ஒரு அதிகரிப்பு கண்டறியப்படும்போது (அளவு > 2× அடிப்படை அளவு), Groq-ல் உள்ள மாதிரிக்கு (model) மிகவும் சாத்தியமான காரணத்தை ஒரே ஒரு, இந்தியா சார்ந்த வாக்கியத்தில் விளக்கும்படி கேட்கிறது.

நான்கு திறன் கோப்புகளில் இதுவே மிகவும் கட்டுப்படுத்தப்பட்ட ஒன்றாகும் — ஒரு வாக்கியம், ஒரு காரணம், அதிகபட்ச துல்லியம்.

---

## சிஸ்டம் ப்ராம்ப்ட் (ஒவ்வொரு நகரத்திற்கும், துல்லியமானது)

```
In one sentence, explain why PM2.5 in {city} might be {pm25} µg/m³ right now 
— {month}, {hour}. Give the most likely cause. Be specific to the Indian context.
```

குறிப்பு: இது ஒரு **பயனர் செய்தியாக (user message)** அனுப்பப்படுகிறது, சிஸ்டம் அறிவுறுத்தலாக அல்ல. வெளியீடு தெளிவான உண்மையான அமைப்புடன் கூடிய ஒரே வாக்கியமாக இருப்பதால், பயனர்-டர்ன் ப்ராம்ப்ட் போதுமானது — முழு சிஸ்டம் அறிவுறுத்தல் தேவையற்ற சுமையை மட்டுமே சேர்க்கும்.

---

## ஸ்பைக் கண்டறிதல் லாஜிக் (AI-க்கு முன்)

```javascript
const ratio = d.pm25 / baseline;
if (ratio > 2) {
  // spike என குறிக்கவும், பின்னர் Groq மூலம் விளக்கவும்
}
```

வரம்பு: **பருவகால அடிப்படை அளவில் 2×** (இது ஒரு நிலையான முழுமையான எண் அல்ல). இது முக்கியமானது, ஏனெனில்:
- டெல்லியின் குளிர்கால அடிப்படை ~95 µg/m³ — ஜனவரியில் 120 µg/m³ என்ற அளவு முரண்பாடானது அல்ல
- மும்பையின் அடிப்படை ~45 µg/m³ — அங்கு 120 µg/m³ என்பது மிகவும் முரண்பாடானது
- ஒரு நிலையான வரம்பு (உதாரணமாக, "150 µg/m³-க்கு மேல் உள்ள அனைத்தையும் குறிக்கவும்") தவறான நேர்மறைகள் (டெல்லி குளிர்காலம்) மற்றும் தவறான எதிர்மறைகள் (கடலோர நகரங்கள்) இரண்டையும் உருவாக்கும்

**பருவகால அடிப்படை அளவுகள் (தோராயமான JanVayu செயல்பாட்டு அடிப்படை அளவுகள், வெளியிடப்பட்ட CREA அல்லது IQAir புள்ளிவிவரங்கள் அல்ல):**

| நகரம் | அக்டோபர்–மார்ச் (குளிர்காலம்) | ஏப்ரல்–செப்டம்பர் (கோடை/பருவமழை) |
|------|-----------------|--------------------------|
| டெல்லி | 95 µg/m³ | 55 µg/m³ |
| மும்பை | 45 µg/m³ | 45 µg/m³ |
| கொல்கத்தா | 80 µg/m³ | 35 µg/m³ |
| சென்னை | 40 µg/m³ | 40 µg/m³ |
| பெங்களூரு | 40 µg/m³ | 40 µg/m³ |

## முக்கிய வடிவமைப்பு முடிவுகள்

**ஏன் ஒரே ஒரு வாக்கியம்?**
முரண்பாடு விளக்கம் UI-ல் ஒரு டூல்டிப் (tooltip) அல்லது இன்லைன் குறிப்பாகத் தோன்றும். பயனரின் கவனச்சிதறல் இல்லாமல் படிக்கக்கூடிய அதிகபட்ச நீளம் ஒரே ஒரு வாக்கியம் மட்டுமே. இதைவிட நீளமாக இருந்தால் அது ஒரு பத்தியாக மாறிவிடும், அதற்கு வேறுபட்ட UI கையாளுதல் தேவைப்படும்.
**ப்ராம்ப்ட்டில் (prompt) மாதமும் நேரமும் ஏன் சேர்க்கப்படுகிறது?**
மாசுக்கான காரணத்தைக் கண்டறிவது நாளின் நேரம் மற்றும் பருவநிலையை (season) பெரிதும் சார்ந்துள்ளது:
மாடல் (model) என்ன சொல்லலாம் என்பதற்கான விளக்கமான உதாரணங்கள் (இவை மூலத்தைக் கண்டறியும் (source-apportionment) முடிவுகள் அல்ல):
- நவம்பர் மாதத்தில் காலை 7 மணி டெல்லி → பெரும்பாலும் காய்ந்த சருகுகளை எரிப்பது + காலை நேர இன்வெர்ஷன் (morning inversion)
- ஏப்ரல் மாதத்தில் மதியம் 2 மணி டெல்லி → பெரும்பாலும் புழுதிப் புயல்கள்
- நள்ளிரவு மும்பை → பெரும்பாலும் தொழில்துறை/கப்பல் போக்குவரத்து செயல்பாடுகள்
பொதுவான காரணங்களின் பட்டியலைத் தருவதற்குப் பதிலாக, பயனுள்ள விளக்கத்தை வழங்க மாடலுக்கு இந்த நேரச் சூழல் (temporal context) தேவைப்படுகிறது.

**வரலாற்றுத் தரவுகளிலிருந்து கணக்கிடுவதற்குப் பதிலாக ஏன் பேஸ்லைன்களை (baselines) ஹார்ட்கோட் (hardcode) செய்கிறோம்?**
எளிமை மற்றும் நம்பகத்தன்மை. ரோலிங் பேஸ்லைனை (rolling baseline) கணக்கிட ஒரு நிரந்தர டைம்-சீரிஸ் டேட்டாபேஸ் (time-series database) தேவைப்படும் — இது கிடைக்கும் சிறிய துல்லிய அதிகரிப்புக்கு (marginal accuracy gain) தேவையற்ற உள்கட்டமைப்பாகும். ஹார்ட்கோட் செய்யப்பட்ட மதிப்புகள் தோராயமான JanVayu பணி பேஸ்லைன்கள் ஆகும். இவை CREA அல்லது IQAir வெளியிட்ட எண்கள் அல்ல, மேலும் இவை கைமுறையாக (manually) புதுப்பிக்கப்படுகின்றன. ஆண்டுக்கு ஆண்டு மாறுபாடுகள் பெரியதாக இருக்கலாம் (2017 முதல் 2025 வரையிலான IQAir-இன் டெல்லி ஆண்டு சராசரிகள் 84.1 முதல் 113.5 µg/m³ வரை உள்ளன), எனவே பேஸ்லைன்களை தோராயமான வரம்புகளாகக் (rough thresholds) கருதுங்கள்.

**Groq API கால்களை (calls) ஏன் இணையாக (parallel) இயக்குகிறோம் (`Promise.allSettled`)?**
அசாதாரணச் சரிபார்ப்பு (anomaly check) பல நகரங்களில் ஒரே நேரத்தில் ஏற்படும் திடீர் அதிகரிப்புகளைக் (spikes) கண்டறியலாம். வரிசையாக (sequentially) இயங்கினால் 3–5 மடங்கு அதிக நேரம் எடுக்கும். `Promise.allSettled` (அதாவது `Promise.all` அல்ல) பயன்படுத்துவதன் அர்த்தம், ஒரு நகரத்திற்கான விளக்கத்தில் ஏற்படும் தோல்வி மற்றவற்றை ரத்து செய்யாது என்பதாகும்.

## மாற்றுச் செயல்பாடு (Fallback Behaviour)

```javascript
if (!s.explanation) {
  s.explanation = `PM2.5 is ${s.ratio}x above JanVayu's approximate working baseline (not a published figure).`;
}
```

Groq API கிடைக்கவில்லை என்றாலும், பதிலில் திடீர் அதிகரிப்புத் தரவும் (spike data) விகிதமும் (ratio) இருக்கும் — AI உருவாக்கிய காரண வாக்கியம் மட்டுமே இருக்காது.
