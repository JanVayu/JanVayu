# CREA அளவீடுகள் API

செயல்பாட்டு குறிப்பு, 18 செப்டம்பர் 2026. இது இன்னும் எடுக்கப்படாத ஒரு முடிவையும், அதற்கு அடிப்படையான அளவீடுகளையும் பதிவு செய்கிறது, எனவே யாரும் அவற்றை மீண்டும் செய்ய வேண்டியதில்லை.

## நாங்கள் ஏன் தேடினோம்

`data/deweathered-national.json` 44 நகரங்களை உள்ளடக்கியது, ஆனால் 2024-ல் நிற்கிறது, ஏனெனில் XKDR காப்பகத்தின் CPCB தரவு 1 செப்டம்பர் 2025-ல் முடிகிறது (`docs/data-sources/xkdr-air-quality.md`-ஐப் பார்க்கவும்). முறை மற்றும் வானிலை தரவு தற்போதையவை. மாசடர்த்தி தரவு மட்டுமே பழையது. CREA-இன் (Centre for Research on Energy and Clean Air) API இதற்கு வெளிப்படையான மாற்றாகும், மேலும் இதுவே hawakahisab.in இயங்குகிறது.

## CREA என்ன வழங்குகிறது (ஆராய்ந்தபடி)

| | |
|---|---|
| Base | `https://api.energyandcleanair.org` |
| Access | திறந்த, **API key தேவையில்லை**, CSV அல்லது JSON |
| Currency | `/ncap/ncap_latest_available_date` 18 செப் 2026 அன்று `2026-09-17` என்பதைத் திருப்பிக் கொடுத்தது (`2 அக்டோபர் 2026 அன்று மீண்டும் சரிபார்க்கப்பட்டபோது 2026-10-01`) |
| Station daily | `/measurements?city_name=<city>&pollutant=pm25&level=station` |
| Station metadata | `/stations?city_name=<city>`, ஆயத்தொலைவுகள் மற்றும் மூலத்துடன் |
| Their own de-weathering | `/ncap/deweathered_yoy`, 2022 முதல் பயிற்றுவிக்கப்பட்ட ஒரு **gbm** மாடல் |

இரண்டு மூலங்களும் நிலைய அடையாளங்களைப் பகிர்ந்து கொள்கின்றன. XKDR அதன் 558 நிலையங்களில் 553-க்கு `site_<n>`-ஐப் பயன்படுத்துகிறது (`cpcb_caaqm`), மற்றும் CREA அதே `site_<n>` அடையாளங்களைத் தருகிறது. டெல்லிக்கு, 39 அடையாளங்கள் இரண்டிலும் தோன்றும் மற்றும் **35 ஒன்றுக்கொன்று 500 மீ-க்குள்** உள்ளன. நான்கு இல்லை, மேலும் தீர்க்கப்படும் வரை அவை விலக்கப்பட வேண்டும்: `site_5395` (லோதி ரோடு) 0.67 கிமீ வித்தியாசத்திலும், `site_107` (பூசா) 2.67 கிமீ வித்தியாசத்திலும், `site_1563` 2.68 கிமீ வித்தியாசத்திலும் மற்றும் `site_105` 6.53 கிமீ வித்தியாசத்திலும் உள்ளன. இவை 2 அக்டோபர் 2026 அன்று மீண்டும் சரிபார்க்கப்பட்டன, மேலும் 18 செப்-க்குப் பிறகு CREA-இன் ஆயத்தொலைவுகள் மாறியிருக்கலாம்.

CREA-இன் நிலைய JSON ஆயத்தொலைவுகளை (lon, lat) என்றும், XKDR-ஐ (lat, lon) என்றும் எழுதுகிறது. வரம்பின் அடிப்படையில் முடிவு செய்யுங்கள், ஒருபோதும் நிலையத்தின் இடத்தின் அடிப்படையில் அல்ல.

## ஒரு இணைப்பைத் தடுத்த கண்டுபிடிப்பு

நிலைய அளவில் CREA `station_day_mad`-ஐ மட்டுமே வழங்குகிறது. `/processes`-இன் கீழ் ஒரு `station_day_absolute` தொடர் பட்டியலிடப்பட்டுள்ளது, ஆனால் இந்த நிலையங்களுக்கு எந்த வரிசைகளையும் திருப்பிக் கொடுக்கவில்லை, மேலும் மணிநேரத் தொடர் எதுவும் இல்லை. "mad" என்பது ஒரு அவுட்லையர் ஃபில்டர் (`mad_percentile` 0.7, `mad_multiplier` 15), எனவே XKDR அனுமதிக்கும் திடீர் ஏற்றங்களை CREA நிராகரிக்கிறது.

2024-ல் டெல்லியில், 13,735 பகிரப்பட்ட நிலைய-நாட்களில், இரண்டும் நெருக்கமாக ஒத்துப்போகின்றன: இடைநிலை வேறுபாடு **0.000 µg/m³**, 95.7% 0.1-க்குள் மற்றும் 99.4% 1-க்குள் உள்ளன. ஆனால் கருத்து வேறுபாடு ஒரு வழியில் மட்டுமே செல்கிறது. CREA ஒருபோதும் அதிகமாக இல்லை.

எனவே நாம் ஸ்ப்ளைஸ் (splice) செய்யக்கூடாது. 2025 செப்டம்பர் 1-க்கு முன் உள்ள XKDR-ஐ, அதற்குப் பின் உள்ள CREA-உடன் இணைத்தால், அந்த தேதியில் தரவரிசையில் ஒரு திசைப் படி (one-way step) உருவாகும். பெரிய ட்ரெண்டுகளைக் கொண்ட நகரங்களில் (மீரட், வாரணாசி, லக்னோ) இந்த படி, ஒரு வருட ட்ரெண்டில் 3%-க்கும் குறைவாகவே இருக்கும், அதனால் எந்த பாதிப்பும் இல்லை. ஹைதராபாத்தில் இது நகரத்தின் மொத்த வருடாந்திர ட்ரெண்டை விட கிட்டத்தட்ட இரண்டு மடங்கு அதிகம், மேலும் இது முன்னேற்றத்தைக் குறிக்கிறது. ஒரு பொதுவான ஸ்ப்ளைஸ், உண்மையான ட்ரெண்ட் மிகச் சிறியதாக இருக்கும் இடத்திலேயே முன்னேற்றத்தை செயற்கையாக உருவாக்குகிறது.

டெல்லியின் சார்பு (bias) குளிர்காலத்தில் அல்லாமல், ஜூன் மாதத்தில் (−0.50) அதிகமாக உள்ளது, எனவே இது ஒரு பருவகால அமைப்பைப் போல செயல்படவில்லை. இது டெல்லியின் முடிவு மட்டுமே, மற்ற நகரங்களுக்குப் பொருந்தாது.

## அதற்குப் பதிலாக என்ன செய்ய வேண்டும்

2018 முதல் இன்று வரையிலான முழுத் தரவரிசையையும் CREA-ஐ மட்டும் வைத்து மீண்டும் உருவாக்கவும், மேலும் XKDR-ஐ ஒரு சுயாதீனமான சரிபார்ப்பாக (cross-check) வைத்துக்கொள்ளவும், அதுவே முதுகெலும்பாக இருக்கக்கூடாது. ஒரே ஒரு ஆதாரம் இருக்கும்போது எந்தப் படியும் (step) இருக்காது, மேலும் இந்த ஓவர்லேப் (overlap) இலவசமாக ஒரு சரிபார்ப்புத் தொகுப்பை (validation set) தருகிறது. CPCB புல்லட்டின் இணைப்பும் இதே முறையில்தான் வேலை செய்தது: 671 பகிரப்பட்ட நகரம்-நாட்களில் 671 நாட்களிலும் இரண்டு தரவுகளும் ஒத்துப்போனதுதான் அவற்றை இணைப்பதை நியாயப்படுத்தியது.

ஒரு தடை இன்னும் உள்ளது. `city_name=Meerut` என்று தேடினால், ஜனவரி 2018 மற்றும் 2019-க்கான CREA-வில் **பூஜ்ஜியம்** (zero) வரிசைகள் கிடைக்கின்றன, ஆனால் XKDR-ல் மீரட் முழுவதும் உள்ளது, எனவே CREA-வின் நகரப் பெயரிடல் நமது நகரப் பட்டியலை உள்ளடக்கவில்லை. அதற்குப் பதிலாக ஸ்டேஷன் ஐடி (station id) மூலம் தேடுங்கள், இது நம்பகமானது, ஏனெனில் அடையாளங்காட்டிகள் பகிரப்பட்டுள்ளன. உறுதிப்படுத்துவதற்கு முன், 44 நகரங்களுக்கும் ஒரு ஸ்டேஷன் மற்றும் ஒரு வருடத்திற்கான கவரேஜ் (coverage) சரிபார்க்கப்பட வேண்டும்.

## அங்கீகாரம்

CREA-வின் தொகுப்பு இதைச் சாத்தியமாக்குகிறது, மேலும் hawakahisab.in செய்வது போல, இது எங்கு பயன்படுத்தப்பட்டாலும் இதற்கு உரிய அங்கீகாரம் வழங்கப்பட வேண்டும். பெரிய அளவில் தரவுகளைச் சேர்ப்பதற்கு முன் அவர்களின் உரிம விதிமுறைகளை (licence terms) வெளிப்படையாகச் சரிபார்க்கவும்.
