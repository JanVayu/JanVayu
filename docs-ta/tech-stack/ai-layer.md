# AI Layer — OpenAI gpt-oss-120B via Groq

JanVayu-இன் AI அம்சங்கள் **OpenAI gpt-oss-120B** மூலம் இயங்குகின்றன. இது Netlify Functions-லிருந்து **Groq API** (OpenAI-compatible REST API) வழியாக வழங்கப்படும் ஒரு open-source LLM ஆகும்.

---

## Groq வழியாக OpenAI gpt-oss-120B-ஐ ஏன் தேர்வு செய்தோம்?

| அளவுகோல் | தேர்வு |
|-----------|--------|
| **செலவு** | இலவச அடுக்கு (Groq Console) — கட்டணம் தேவையில்லை |
| **வேகம்** | Groq-இன் ஹோஸ்ட் செய்யப்பட்ட inference சேவையிலிருந்து வழங்கப்படுகிறது (latency இங்கே அளவிடப்படவில்லை) |
| **Rate limits** | தாராளமான இலவச அடுக்கு — பொது நல தளத்திற்கு போதுமானது |
| **பன்மொழி** | வலுவான இந்தி ஆதரவு (JanVayu-இன் பயனர்களுக்கு மிகவும் முக்கியமானது) |
| **தரம்** | தரவு அடிப்படையிலான உண்மையான பதில்களுக்கு போதுமானது (கிரியேட்டிவ் எழுத்துக்கு அல்ல) |
| **Open source** | OpenAI gpt-oss-120B ஒரு open model (OpenAI), இது வெளிப்படைத்தன்மை மற்றும் மறுஉருவாக்கத்தை உறுதி செய்கிறது |

### ஏற்றுக்கொள்ளப்பட்ட சமரசங்கள்

- **GPT-4 / Claude அல்ல** — Groq-இன் இலவச அடுக்கு மற்றும் open-source மாடல் ஆகியவை இதன் தனிச்சிறப்பு. JanVayu முழுவதுமாக பூஜ்ஜிய பட்ஜெட்டில் இயங்குகிறது.
- **Output token cap** — ஒவ்வொரு function-க்கும் output 512 முதல் 1,024 `max_tokens` வரை கட்டுப்படுத்தப்பட்டுள்ளது (air-query 700, accountability-brief 1,024, health-advisory 768, anomaly-check 512). Reasoning மாடல்கள் அந்த வரம்பின் ஒரு பகுதியை reasoning-க்கு செலவிடுகின்றன, எனவே இந்த வரம்பு முழு பதிலையும் கட்டுப்படுத்துகிறது, தெரியும் உரையை மட்டும் அல்ல.
- **Fine-tuning இல்லை** — Prompt engineering மட்டுமே. ஒவ்வொரு திறனும் ஒரு system prompt ஆகும், fine-tuned மாடல் அல்ல.

## Integration Architecture

```
Browser (client)
    │
    │ POST /.netlify/functions/air-query
    │ POST /.netlify/functions/health-advisory
    │ POST /.netlify/functions/accountability-brief
    │ GET  /.netlify/functions/anomaly-check
    │
    ▼
Netlify Function (server-side)
    │
    │ 1. Parse user input
    │ 2. Fetch live AQI data from WAQI
    │ 3. Construct prompt with real data
    │ 4. Call Groq API
    │ 5. Return response (or fallback to raw data)
    │
    ▼
Groq API
    │
    │ openai/gpt-oss-120b model
    │ max_tokens: 512-1,024 (per function)
    │
    ▼
Structured response → Browser
```

**முக்கிய பாதுகாப்பு விதி:** `GROQ_API_KEY` ஒருபோதும் client-ஐத் தொடாது. அனைத்து AI அழைப்புகளும் Netlify Functions வழியாக server-side-ல் செய்யப்படுகின்றன.

## நான்கு AI அம்சங்கள்

### 1. Ask JanVayu (`air-query.mjs`)
- **Input:** நகரத்தின் பெயர் + free-text கேள்வி
- **Context injected:** WAQI-லிருந்து நேரடி PM2.5 மற்றும் AQI
- **Output:** உண்மையான அளவீடுகளின் அடிப்படையில்
- **Languages:** கேள்வியின் மொழியிலேயே பதில்கள்; Ask JanVayu UI 10 மொழிகளில் கிடைக்கிறது
- **Fallback:** Groq rate-limited ஆக இருந்தால், raw AQI தரவை வழங்குகிறது
### 2. சுகாதார ஆலோசனை (`health-advisory.mjs`)
- **உள்ளீடு:** நகரம் + வயது + உடல்நலக் குறைபாடுகள் + வெளிப்புறச் செலவிடும் நேரம்
- **சேர்க்கப்படும் தரவு:** அந்த நகரத்தின் தற்போதைய AQI
- **வெளியீடு:** நிறக் குறியிடப்பட்ட ஆபத்து நிலை + உறுதியான பரிந்துரைகள்
- **மாற்று வழி:** பொதுவான WHO-வழிகாட்டுதல் ஆலோசனை

### 3. பொறுப்புக்கூறல் அறிக்கை (`accountability-brief.mjs`)
- **உள்ளீடு:** நகரத்தின் பெயர்
- **சேர்க்கப்படும் தரவு:** தற்போதைய AQI + பருவகால அடிப்படை அளவுகள் + GRAP நிலைகள்
- **வெளியீடு:** கட்டமைக்கப்பட்ட அறிக்கை (தற்போதைய நிலை, NCAP இலக்குகள், 5 பொறுப்புக்கூறல் கேள்விகள்)
- **அதிகபட்ச டோக்கன்கள்:** 1,024
- **மாற்று வழி:** மூல தரவு அட்டவணையைத் தரும்

### 4. முரண்பாடு கண்டறிதல் (`anomaly-check.mjs`)
- **உள்ளீடு:** எதுவும் இல்லை (5 பெருநகரங்களை தானாகவே கண்காணிக்கும்)
- **வரம்பு:** 2× பருவகால அடிப்படை அளவு = முரண்பாடு
- **வெளியீடு:** ஒவ்வொரு முரண்பாட்டிற்கும் ஒரு வாக்கிய AI விளக்கம்
- **கேச்:** 10-நிமிட HTTP `Cache-Control` header (Netlify Blobs அல்ல)
- **மாற்று வழி:** AI விளக்கம் இல்லாமல் முரண்பாடு கொடியைத் தரும்

## விகித வரம்பு உத்தி

இலவச அடுக்கு Groq வரம்புகள் (மாற்றத்திற்கு உட்பட்டது — தற்போதைய மதிப்புகளுக்கு [console.groq.com](https://console.groq.com) ஐப் பார்க்கவும்):

| வரம்பு | மதிப்பு (openai/gpt-oss-120b, Groq இலவசத் திட்டம், 2 அக்டோபர் 2026 அன்று சரிபார்க்கப்பட்டது) |
|-------|-------|
| ஒரு நிமிடத்திற்கு கோரிக்கைகள் | 30 |
| ஒரு நாளைக்கு கோரிக்கைகள் | 1,000 |
| ஒரு நிமிடத்திற்கு டோக்கன்கள் | 8,000 |
| ஒரு நாளைக்கு டோக்கன்கள் | 200,000 |

ஆதாரம்: [Groq rate limits](https://console.groq.com/docs/rate-limits). நீண்ட air-query சிஸ்டம் ப்ராம்ப்ட்டிற்கு எதிராக 8,000 டோக்கன்கள்-ஒரு-நிமிட வரம்பு இறுக்கமாக இருப்பதால், 429 பதில்களைக் கண்காணிப்பது மதிப்புமிக்கது.

JanVayu இந்த பட்ஜெட்டை அம்சங்களில் விநியோகிக்கிறது (Netlify பதிவுகளிலிருந்து அளவிடப்படாத மதிப்பீடுகள்):
- முரண்பாடு சரிபார்ப்பு: ~144/நாள் (கேச் செய்யப்பட்டது, பக்கத்தை ஏற்றும்போது இயங்கும்)
- காற்று வினவல்: ~50/நாள் (பயனர் தொடங்குவது)
- சுகாதார ஆலோசனை: ~30/நாள் (பயனர் தொடங்குவது)
- பொறுப்புக்கூறல் அறிக்கை: ~20/நாள் (பயனர் தொடங்குவது)

வரம்புகள் எட்டப்பட்டால், ஒவ்வொரு செயல்பாடும் மூல தரவுக்குத் திரும்பும். பயனர் எப்போதும் ஒரு பதிலை பெறுவார் — AI பகுப்பாய்வு இல்லாமல் மட்டுமே.

## ப்ராம்ப்ட் இன்ஜினியரிங்

அனைத்து ப்ராம்ப்ட்களும் இந்தக் கொள்கைகளைப் பின்பற்றுகின்றன:

1. **எப்போதும் உண்மையான தரவைச் சேர்க்கவும்** — மாடல் ஒருபோதும் நினைவகத்திலிருந்து உருவாக்காது
2. **சரியான வெளியீட்டு வடிவத்தைக் குறிப்பிடவும்** — குறிப்பாக கட்டமைக்கப்பட்ட அறிக்கைகளுக்கு
3. **சொல் எண்ணிக்கையைக் கட்டுப்படுத்தவும்** — ஒவ்வொரு ப்ராம்ப்ட்டிலும் வெளிப்படையான வரம்புகள்
4. **தோல்வி முறைகளைக் குறிப்பிடவும்** — "பொதுவான ஆலோசனையை வழங்க வேண்டாம்", "தெளிவற்ற பதில்களைத் தவிர்க்கவும்"
5. **பல்மொழி அறிவுறுத்தல்** — "கேள்வியின் மொழியில் பதிலளிக்கவும்"
6. **தடையற்ற மாற்று வழி** — ஒவ்வொரு செயல்பாட்டிற்கும் AI அல்லாத மாற்று வழி உள்ளது
