# स्किल: पब्लिक हेल्थ एडवाइज़र

**इस्तेमाल:** `netlify/functions/health-advisory.mjs`  
**मॉडल:** Groq के ज़रिए `openai/gpt-oss-120b` (डिफ़ॉल्ट, `GROQ_MODEL` द्वारा सेट; 16 अगस्त 2026 को Groq द्वारा रिटायर किए जाने तक Llama 3.3 70B)  
**ट्रिगर:** यूज़र एक प्रोफ़ाइल (उम्र, स्वास्थ्य स्थितियां, बाहर बिताए गए घंटे) + एक शहर सबमिट करता है

---

## यह स्किल क्या करती है

यह व्यक्ति की वल्नरेबिलिटी प्रोफ़ाइल और शहर के वर्तमान PM2.5 रीडिंग के आधार पर एक व्यक्तिगत, कार्रवाई योग्य (actionable) स्वास्थ्य सलाह (health advisory) जनरेट करती है। सबसे महत्वपूर्ण बात यह है कि यह टालमटोल नहीं करती। यह एक ठोस सलाह देती है — "दोपहर 2 बजे तक घर के अंदर रहें" बजाय इसके कि "बाहर जाने से बचने पर विचार करें।"

---

## सिस्टम प्रॉम्प्ट (सटीक)

```
आप भारत में वायु प्रदूषण के संपर्क से संबंधित एक पब्लिक हेल्थ एडवाइज़र हैं। 
किसी व्यक्ति की प्रोफ़ाइल और वर्तमान वायु गुणवत्ता डेटा के आधार पर, एक विशिष्ट, 
कार्रवाई योग्य सलाह (advisory) जनरेट करें। ठोस रहें: 'बाहर जाने से बचने पर विचार करें' 
के बजाय 'दोपहर 2 बजे तक घर के अंदर रहें' कहें। वास्तविक PM2.5 मान का संदर्भ दें। 
यदि व्यक्ति को कोई स्वास्थ्य समस्या है, तो उसे सीधे संबोधित करें। टालमटोल न करें — 
एक स्पष्ट सलाह दें। अधिकतम 3-4 वाक्य। अंग्रेजी में जवाब दें।
```

## प्री-एआई रिस्क कैलकुलेशन

Groq API कॉल से पहले, फ़ंक्शन सादे JavaScript में एक `riskLevel` की गणना करता है — इसे हमेशा AI सलाह के साथ वापस किया जाता है, ताकि UI AI के जवाब का इंतज़ार किए बिना रिस्पॉन्स को कलर-कोड कर सके:

```javascript
function getRiskLevel(pm25, conditions) {
  const hasSensitive = conditions && conditions.some(c => c !== "none");
  if (pm25 <= 12) return "low";
  if (pm25 <= 35) return hasSensitive ? "moderate" : "low";
  if (pm25 <= 55) return hasSensitive ? "high" : "moderate";
  if (pm25 <= 150) return hasSensitive ? "severe" : "high";
  return "severe";
}
```

थ्रेशोल्ड 2012 के US EPA PM2.5 ब्रेकपॉइंट्स (12.0, 35.4, 55.4, 150.4 µg/m³) का पालन करते हैं, जिन्हें EPA ने 2024 में संशोधित किया था (Good अब 9.0 तक, Unhealthy 55.5 से 125.4 तक); कोड को 2024 के मानों में अपडेट नहीं किया गया है। सेंसिटिविटी को पहले से मौजूद स्थितियों वाले लोगों को एक बैंड ऊपर ले जाकर संभाला जाता है।

## प्रमुख डिज़ाइन निर्णय
**"हेजिंग" (do not hedge) क्यों नहीं?**
हमारा मानना है कि सीधे सुझाव ("Y तक X करें") की तुलना में घुमा-फिरा कर दिए गए सुझाव ("आप शायद इस पर विचार करना चाहें...") पर लोग कम अमल करते हैं। अस्थमा या हृदय रोग वाले लोगों के लिए एक पब्लिक हेल्थ टूल के तौर पर, हेजिंग तटस्थ नहीं है — यह सक्रिय रूप से सुरक्षात्मक व्यवहार को कम करता है।

**अधिकतम 3-4 वाक्य ही क्यों?**
हाई-पॉल्यूशन इमरजेंसी के दौरान कोई भी व्यक्ति ऐसी हेल्थ एडवाइजरी नहीं पढ़ेगा जिसे समझने में मेहनत लगे। इसे 10 सेकंड से भी कम समय में आसानी से पढ़ा जा सकना चाहिए।

**मॉडल पर निर्भर रहने के बजाय JavaScript में `riskLevel` क्यों कैलकुलेट करें?**
विश्वसनीयता। रिस्क लेवल UI कलर-कोडिंग और फॉलबैक मैसेजिंग को चलाता है। इसे LLM पर छोड़ने से अनिश्चितता आ जाती है। रूल-बेस्ड फंक्शन हमेशा एक जैसा परिणाम देता है, चाहे AI उपलब्ध हो या न हो।

**प्रॉम्प्ट में कंडीशंस की लिस्ट क्यों शामिल करें?**
"सीधे संबोधित करें" मॉडल को एक सामान्य प्रतिक्रिया देने के बजाय यह कहने के लिए मजबूर करता है कि "अस्थमा वाले किसी व्यक्ति के लिए, इस स्तर पर PM2.5 का मतलब है..."। यह पर्सनलाइजेशन का मुख्य तरीका है।

## फॉलबैक बिहेवियर (Fallback Behaviour)

```
AI analysis unavailable. Raw data: {pm25} µg/m³ PM2.5 (AQI {aqi}).
```

`riskLevel` अभी भी JavaScript फंक्शन से कैलकुलेट और रिटर्न किया जाता है, इसलिए AI टेक्स्ट के बिना भी UI परिणाम को कलर-कोड कर सकता है।

## अन्य डोमेन के लिए ढालना (Adapting for Other Domains)

यह स्किल पैटर्न — प्रोफाइल + लाइव डेटा → ठोस सलाह — इनके लिए भी इस्तेमाल किया जा सकता है:

- **हीट एडवाइजरी (Heat advisory):** उम्र + स्थितियां + तापमान/हीट इंडेक्स → बाहर की गतिविधियों और हाइड्रेशन पर ठोस सलाह
- **वाटर कंटामिनेशन अलर्ट (Water contamination alert):** स्थान + कंटामिनेंट लेवल + डेमोग्राफिक → पीने/इस्तेमाल की सलाह
- **नॉइज़ एक्सपोज़र (Noise exposure):** प्रोफाइल + डेसिबल रीडिंग + अवधि → सुनने की सुरक्षा की सलाह
