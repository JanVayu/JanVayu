# AI लेयर — Groq के माध्यम से OpenAI gpt-oss-120B

JanVayu के AI फ़ीचर्स **OpenAI gpt-oss-120B** द्वारा संचालित हैं, जो Netlify Functions से **Groq API** (OpenAI-कम्पैटिबल REST API) के ज़रिए सर्व किया जाने वाला एक ओपन-सोर्स LLM है।

---

## Groq के माध्यम से OpenAI gpt-oss-120B ही क्यों?

| मापदंड | विकल्प |
|-----------|--------|
| **लागत** | फ्री टियर (Groq Console) — किसी बिलिंग की ज़रूरत नहीं |
| **गति** | Groq की होस्टेड इन्फरेंस सर्विस से सर्व किया जाता है (यहाँ लेटेंसी नहीं मापी गई है) |
| **रेट लिमिट** | जेनेरस फ्री टियर — पब्लिक इंटरेस्ट प्लेटफ़ॉर्म के लिए पर्याप्त |
| **मल्टीलिंगुअल** | बेहतरीन हिंदी सपोर्ट (JanVayu के दर्शकों के लिए महत्वपूर्ण) |
| **गुणवत्ता** | डेटा-आधारित तथ्यात्मक जवाबों के लिए पर्याप्त (क्रिएटिव राइटिंग के लिए नहीं) |
| **ओपन सोर्स** | OpenAI gpt-oss-120B एक ओपन मॉडल (OpenAI) है, जो पारदर्शिता और रीप्रोड्यूसिबिलिटी सुनिश्चित करता है |

### स्वीकार किए गए ट्रेड-ऑफ़

- **GPT-4 / Claude नहीं** — Groq के फ्री टियर के साथ ओपन-सोर्स मॉडल का इस्तेमाल ही हमारी खासियत है। JanVayu शून्य बजट पर चलता है।
- **आउटपुट टोकन कैप** — हर फ़ंक्शन के लिए आउटपुट को 512 से 1,024 `max_tokens` तक सीमित किया गया है (air-query 700, accountability-brief 1,024, health-advisory 768, anomaly-check 512)। रीज़निंग मॉडल्स इस कैप का कुछ हिस्सा रीज़निंग में खर्च करते हैं, इसलिए यह कैप पूरी प्रतिक्रिया को सीमित करता है, न कि केवल दिखने वाले टेक्स्ट को।
- **कोई फाइन-ट्यूनिंग नहीं** — केवल प्रॉम्प्ट इंजीनियरिंग का उपयोग किया गया है। हर स्किल एक सिस्टम प्रॉम्प्ट है, कोई फाइन-ट्यून्ड मॉडल नहीं।

## इंटीग्रेशन आर्किटेक्चर

```
Browser (client)
    │
    │ POST /.netlify/functions/air-query
    │ POST /.netlify/functions/health-advisory
    │ POST /.netlify/functions/accountability-brief
    │ GET  /.netlify/functions/anomaly-check
    │
    ▼
Netlify Function (server-side)
    │
    │ 1. Parse user input
    │ 2. Fetch live AQI data from WAQI
    │ 3. Construct prompt with real data
    │ 4. Call Groq API
    │ 5. Return response (or fallback to raw data)
    │
    ▼
Groq API
    │
    │ openai/gpt-oss-120b model
    │ max_tokens: 512-1,024 (per function)
    │
    ▼
Structured response → Browser
```

**मुख्य सुरक्षा सिद्धांत:** `GROQ_API_KEY` कभी भी क्लाइंट तक नहीं पहुँचता। सभी AI कॉल्स Netlify Functions के ज़रिए सर्वर-साइड पर की जाती हैं।

## चार AI फ़ीचर्स

### 1. Ask JanVayu (`air-query.mjs`)
- **इनपुट:** शहर का नाम + फ्री-टेक्स्ट सवाल
- **इंजेक्ट किया गया कॉन्टेक्स्ट:** WAQI से लाइव PM2.5 और AQI
- **आउटपुट:** वास्तविक रीडिंग पर आधारित
- **भाषाएँ:** जवाब सवाल की भाषा में; Ask JanVayu UI 10 भाषाओं में उपलब्ध है
- **फ़ॉलबैक:** अगर Groq पर रेट लिमिट लग जाए, तो यह रॉ AQI डेटा लौटाता है
### 2. स्वास्थ्य परामर्श (`health-advisory.mjs`)
- **इनपुट:** शहर + उम्र + स्वास्थ्य स्थितियाँ + बाहर बिताए गए घंटे
- **संदर्भ जोड़ा गया:** उस शहर का लाइव AQI
- **आउटपुट:** रंग-कोडित जोखिम स्तर + ठोस सुझाव
- **फ़ॉलबैक:** सामान्य WHO-दिशा-निर्देशों की सलाह

### 3. जवाबदेही ब्रीफ़ (`accountability-brief.mjs`)
- **इनपुट:** शहर का नाम
- **संदर्भ जोड़ा गया:** लाइव AQI + मौसमी बेसलाइन + GRAP चरण
- **आउटपुट:** स्ट्रक्चर्ड ब्रीफ़ (वर्तमान स्थिति, NCAP लक्ष्य, 5 जवाबदेही प्रश्न)
- **अधिकतम टोकन:** 1,024
- **फ़ॉलबैक:** रॉ डेटा टेबल देता है

### 4. विसंगति पहचान (`anomaly-check.mjs`)
- **इनपुट:** कोई नहीं (स्वचालित रूप से 5 मेट्रो की निगरानी करता है)
- **थ्रेशोल्ड:** 2× मौसमी बेसलाइन = विसंगति
- **आउटपुट:** हर विसंगति के लिए एक वाक्य में AI स्पष्टीकरण
- **कैश:** 10-मिनट का HTTP `Cache-Control` हेडर (Netlify Blobs नहीं)
- **फ़ॉलबैक:** AI स्पष्टीकरण के बिना विसंगति फ़्लैग देता है

## रेट लिमिटिंग रणनीति

फ़्री-टियर Groq सीमाएँ (बदलने के अधीन — वर्तमान मानों के लिए [console.groq.com](https://console.groq.com) चेक करें):

| सीमा | मान (openai/gpt-oss-120b, Groq फ़्री प्लान, 2 अक्टूबर 2026 को चेक किया गया) |
|-------|-------|
| प्रति मिनट अनुरोध | 30 |
| प्रति दिन अनुरोध | 1,000 |
| प्रति मिनट टोकन | 8,000 |
| प्रति दिन टोकन | 200,000 |

स्रोत: [Groq रेट लिमिट्स](https://console.groq.com/docs/rate-limits)। लंबे एयर-क्वेरी सिस्टम प्रॉम्प्ट के कारण 8,000 टोकन-प्रति-मिनट की सीमा काफी कम है, इसलिए 429 रिस्पॉन्स पर नज़र रखना ज़रूरी है।

JanVayu इस बजट को फ़ीचर्स के बीच बांटता है (ये अनुमान हैं, Netlify लॉग से नहीं मापे गए):
- विसंगति जांच: ~144/दिन (कैश किया हुआ, पेज लोड होने पर चलता है)
- एयर क्वेरी: ~50/दिन (यूज़र द्वारा शुरू किया गया)
- स्वास्थ्य परामर्श: ~30/दिन (यूज़र द्वारा शुरू किया गया)
- जवाबदेही ब्रीफ़: ~20/दिन (यूज़र द्वारा शुरू किया गया)

अगर सीमा पार हो जाती है, तो हर फ़ंक्शन आराम से रॉ डेटा पर वापस आ जाता है। यूज़र को हमेशा जवाब मिलता है — बस AI विश्लेषण के बिना।

## प्रॉम्प्ट इंजीनियरिंग

सभी प्रॉम्प्ट इन सिद्धांतों का पालन करते हैं:

1. **हमेशा असली डेटा जोड़ें** — मॉडल कभी भी मेमोरी से नहीं बनाता
2. **सटीक आउटपुट फ़ॉर्मेट बताएं** — विशेष रूप से स्ट्रक्चर्ड ब्रीफ़ के लिए
3. **शब्दों की संख्या सीमित करें** — हर प्रॉम्प्ट में स्पष्ट सीमाएं
4. **विफलता के तरीकों का नाम दें** — "सामान्य सलाह न दें", "गोल-मोल बातें न करें"
5. **बहुभाषी निर्देश** — "सवाल की भाषा में जवाब दें"
6. **ग्रेसफुल डिग्रेडेशन** — हर फ़ंक्शन का एक नॉन-AI फ़ॉलबैक रास्ता होता है

पूरी प्रॉम्प्ट दस्तावेज़ के लिए [Skills & AI Prompts](../skills/README.md) सेक्शन देखें।
