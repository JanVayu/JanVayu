# AI Layer — OpenAI gpt-oss-120B via Groq

JanVayu के AI फीचर्स **OpenAI gpt-oss-120B** से चलते हैं, जो Netlify Functions से **Groq API** (OpenAI-compatible REST API) के ज़रिए सर्व किया जाने वाला एक ओपन-सोर्स LLM है।

---

## Groq के ज़रिए OpenAI gpt-oss-120B ही क्यों?

| क्राइटेरिया | विकल्प |
|-----------|--------|
| **लागत (Cost)** | Groq Console; प्लान और बिलिंग अकाउंट पर सेट होते हैं |
| **स्पीड** | Groq की होस्टेड इन्फरेंस सर्विस से सर्व किया जाता है (यहाँ लेटेंसी नहीं मापी गई है) |
| **रेट लिमिट्स** | नीचे दी गई टेबल में बेस लिमिट्स |
| **मल्टीलिंगुअल** | बेहतरीन हिंदी सपोर्ट (JanVayu के यूज़र्स के लिए बहुत ज़रूरी) |
| **क्वालिटी** | डेटा पर आधारित तथ्यात्मक जवाबों के लिए पर्याप्त (क्रिएटिव राइटिंग के लिए नहीं) |
| **ओपन सोर्स** | OpenAI gpt-oss-120B एक ओपन मॉडल (OpenAI) है, जो पारदर्शिता और रीप्रोड्यूसिबिलिटी सुनिश्चित करता है |

### स्वीकार किए गए ट्रेड-ऑफ़्स

- **GPT-4 / Claude नहीं** — JanVayu लागत और स्पीड के लिए Groq द्वारा सर्व किए जाने वाले एक ओपन-वेट मॉडल का इस्तेमाल करता है।
- **आउटपुट टोकन कैप** — आउटपुट को हर फ़ंक्शन के हिसाब से 512 से 1,024 `max_tokens` तक सीमित किया गया है (air-query 700, accountability-brief 1,024, health-advisory 768, anomaly-check 512)। रीज़निंग मॉडल्स इस कैप का कुछ हिस्सा रीज़निंग में खर्च करते हैं, इसलिए यह कैप पूरे रिस्पॉन्स को सीमित करता है, न कि सिर्फ़ दिखने वाले टेक्स्ट को।
- **कोई फाइन-ट्यूनिंग नहीं** — केवल प्रॉम्प्ट इंजीनियरिंग। हर स्किल एक सिस्टम प्रॉम्प्ट है, कोई फाइन-ट्यून्ड मॉडल नहीं।

## इंटीग्रेशन आर्किटेक्चर

```
Browser (client)
    │
    │ POST /.netlify/functions/air-query
    │ POST /.netlify/functions/health-advisory
    │ POST /.netlify/functions/accountability-brief
    │ GET  /.netlify/functions/anomaly-check
    │
    ▼
Netlify Function (server-side)
    │
    │ 1. Parse user input
    │ 2. Fetch live AQI data from WAQI
    │ 3. Construct prompt with real data
    │ 4. Call Groq API
    │ 5. Return response (or fallback to raw data)
    │
    ▼
Groq API
    │
    │ openai/gpt-oss-120b model
    │ max_tokens: 512-1,024 (per function)
    │
    ▼
Structured response → Browser
```

**मुख्य सुरक्षा सिद्धांत:** `GROQ_API_KEY` कभी भी क्लाइंट तक नहीं पहुँचती। सभी AI कॉल्स Netlify Functions के ज़रिए सर्वर-साइड पर होती हैं।

## चार AI फीचर्स

### 1. Ask JanVayu (`air-query.mjs`)
- **इनपुट:** शहर का नाम + फ्री-टेक्स्ट सवाल
- **इंजेक्ट किया गया कॉन्टेक्स्ट:** WAQI से लाइव PM2.5 और AQI
- **आउटपुट:** वास्तविक रीडिंग पर आधारित
- **भाषाएं:** सवाल की भाषा में जवाब; Ask JanVayu UI 10 भाषाओं में उपलब्ध है
- **फ़ॉलबैक:** अगर Groq रेट-लिमिटेड हो तो रॉ AQI डेटा रिटर्न करता है
### 2. हेल्थ एडवाइज़री (`health-advisory.mjs`)
- **इनपुट:** शहर + उम्र + स्वास्थ्य स्थितियाँ + बाहर बिताए गए घंटे
- **इंजेक्ट किया गया कॉन्टेक्स्ट:** उस शहर का लाइव AQI
- **आउटपुट:** कलर-कोडेड जोखिम स्तर + ठोस सुझाव
- **फ़ॉलबैक:** सामान्य WHO-गाइडलाइन सलाह

### 3. अकाउंटेबिलिटी ब्रीफ़ (`accountability-brief.mjs`)
- **इनपुट:** शहर का नाम
- **इंजेक्ट किया गया कॉन्टेक्स्ट:** लाइव AQI + सीज़नल बेसलाइन + GRAP स्टेज
- **आउटपुट:** स्ट्रक्चर्ड ब्रीफ़ (वर्तमान स्थिति, NCAP लक्ष्य, 5 अकाउंटेबिलिटी सवाल)
- **अधिकतम टोकन:** 1,024
- **फ़ॉलबैक:** रॉ डेटा टेबल लौटाता है

### 4. एनोमली डिटेक्शन (`anomaly-check.mjs`)
- **इनपुट:** None (स्वचालित रूप से 5 मेट्रो की निगरानी करता है)
- **थ्रेशोल्ड:** 2× सीज़नल बेसलाइन = एनोमली
- **आउटपुट:** प्रति एनोमली एक वाक्य का AI स्पष्टीकरण
- **कैश:** 10-मिनट का HTTP `Cache-Control` हेडर (Netlify Blobs नहीं)
- **फ़ॉलबैक:** AI स्पष्टीकरण के बिना एनोमली फ़्लैग लौटाता है

## रेट लिमिटिंग स्ट्रैटेजी

Groq की प्रकाशित बेस लिमिट (परिवर्तन के अधीन; अकाउंट के अपने प्लान की लिमिट के लिए [console.groq.com](https://console.groq.com) चेक करें):

| लिमिट | वैल्यू (openai/gpt-oss-120b, Groq द्वारा प्रकाशित बेस लिमिट, 25 Oct 2026 को चेक की गई) |
|-------|-------|
| प्रति मिनट रिक्वेस्ट | 30 |
| प्रति दिन रिक्वेस्ट | 1,000 |
| प्रति मिनट टोकन | 8,000 |
| प्रति दिन टोकन | 200,000 |

स्रोत: [Groq रेट लिमिट](https://console.groq.com/docs/rate-limits). 8,000 टोकन-प्रति-मिनट की लिमिट लंबे एयर-क्वेरी सिस्टम प्रॉम्प्ट के हिसाब से काफी कम है, इसलिए 429 रिस्पॉन्स की निगरानी करना ज़रूरी है।

JanVayu इस बजट को फ़ीचर्स के बीच बाँटता है (ये अनुमान हैं, Netlify लॉग्स से मापे गए नहीं):
- एनोमली चेक: ~144/दिन (कैश किया हुआ, पेज लोड होने पर ट्रिगर होता है)
- एयर क्वेरी: ~50/दिन (यूज़र द्वारा शुरू की गई)
- हेल्थ एडवाइज़री: ~30/दिन (यूज़र द्वारा शुरू की गई)
- अकाउंटेबिलिटी ब्रीफ़: ~20/दिन (यूज़र द्वारा शुरू की गई)

अगर लिमिट पूरी हो जाती है, तो हर फ़ंक्शन आसानी से रॉ डेटा पर फ़ॉलबैक हो जाता है। यूज़र को हमेशा एक रिस्पॉन्स मिलता है — बस बिना AI एनालिसिस के।

## प्रॉम्प्ट इंजीनियरिंग

सभी प्रॉम्प्ट इन सिद्धांतों का पालन करते हैं:

1. **हमेशा असली डेटा इंजेक्ट करें** — मॉडल कभी भी मेमोरी से जनरेट नहीं करता
2. **सटीक आउटपुट फ़ॉर्मेट बताएं** — ख़ासकर स्ट्रक्चर्ड ब्रीफ़ के लिए
3. **शब्दों की संख्या सीमित करें** — हर प्रॉम्प्ट में स्पष्ट लिमिट
4. **फ़ेलियर मोड का नाम दें** — "सामान्य सलाह न दें", "गोलमोल बातें न करें"
5. **मल्टीलिंगुअल निर्देश** — "सवाल की भाषा में जवाब दें"
6. **ग्रेसफ़ुल डिग्रेडेशन** — हर फ़ंक्शन में एक नॉन-AI फ़ॉलबैक पाथ होता है
