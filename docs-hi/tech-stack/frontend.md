# फ्रंटएंड स्टैक
## HTML/CSS/JavaScript (Vanilla)
फ्रंटएंड बिना किसी बिल्ड स्टेप और बिना किसी बंडलर के वैनिला HTML, CSS और JavaScript है। यह **एकल फ़ाइल नहीं** है, और यह पेज लंबे समय तक यही कहता रहा जिससे कोई गुमराह हो सकता था: `index.html` लगभग 6,500 लाइनें है, `styles.css` लगभग 3,800, `app.js` लगभग 10,200 है, और `panels/` में 19 पैनल फ्रैगमेंट्स हैं जो रनटाइम पर पेज में लोड होते हैं।
### इसकी संरचना
| फ़ाइल | यह क्या है |
|---|---|
| `index.html` | सिंगल-पेज ऐप: बार, पैनल कंटेनर, और फर्स्ट पेंट के लिए `styles.css` का एक इनलाइन **क्रिटिकल-CSS** सबसेट |
| `styles.css` | डिज़ाइन सिस्टम। हर टोकन, दोनों थीम, और साझा कंपोनेंट्स (`.bar`, `.ctl`, `.card`, `.container`) |
| `app.js` | पैनल रूटिंग, डेटा फेचिंग, चार्ट्स, रोल और भाषा तंत्र |
| `js/chrome.js` | थीम प्रेफरेंस और उन पेजों के लिए एक छोटा बार जो SPA नहीं हैं |
| `js/air-sources.js` | वह एकमात्र जगह जो तय करती है कि किसी जगह की हवा के बारे में क्या कहना है: एक लाइव WAQI स्टेशन, फिर CPCB का दैनिक बुलेटिन, फिर एक मॉडल अनुमान, हर एक लेबल किया हुआ |
| `panels/*.html` | `index.html` में इंजेक्ट किए गए फ्रैगमेंट्स; वे इसकी स्टाइलिंग को इनहेरिट करते हैं |
| स्टैंडअलोन पेज | `/pm25/`, `/try.html`, `/docs/`, `/blog/`, `/ask/`, `/bulletins/`, `/delhi/`, वॉकथ्रू, एम्बेड्स, जनरेटेड ब्लॉग पोस्ट पेज और बाकी |
**हर स्टैंडअलोन पेज `styles.css` लोड करता है।** `scripts/check-design-system.py` ने 21 नवंबर 2026 को उनमें से 78 गिने (जब नियम पेश किया गया था तब 19 थे)। यह 2026-09-22 तक सच नहीं था: हर एक में एक निजी `<style>` ब्लॉक था जो समान टोकन नामों को फिक्स्ड लाइट-थीम लिटरल के साथ फिर से परिभाषित करता था, इसलिए एक टोकन परिवर्तन एक पेज तक पहुँचता था और बाकी किसी ने भी थीम कंट्रोल का पालन नहीं किया।
`scripts/check-design-system.py` उस पेज को फेल कर देता है जो फिर से बाहर हो जाता है।
### बिल्ड स्टेप क्यों नहीं
1. **कोई बिल्ड स्टेप नहीं** — रिपॉजिटरी ही डिप्लॉय आर्टिफैक्ट है
2. **योगदानकर्ता के अनुकूल** — `python3 -m http.server` पूरा डेवलपमेंट सेटअप है
3. **सोर्स और आउटपुट के बीच पुराना होने के लिए कुछ नहीं**
इसका नुकसान यह है कि कैश-बस्टिंग मैन्युअल है। `/styles.css` और `/app.js` को `package.json` में मौजूद वर्ज़न से बने `?v=<stamp>` क्वेरी के साथ रिक्वेस्ट किया जाता है, क्योंकि `sw.js` सेम-ओरिजिन एसेट्स को **बिना किसी रीवैलिडेशन के कैश-फर्स्ट** सर्व करता है। दो गार्ड इसे एक साथ संभालते हैं: `check-asset-stamps.py` (हर स्टैम्प्ड URL में मौजूदा स्टैम्प होता है) और `check-asset-freshness.py` (जब वर्ज़न स्थिर था तब कोई स्टैम्प्ड फ़ाइल नहीं बदली)। दूसरा गार्ड इसलिए मौजूद है क्योंकि पहले गार्ड के पास पास होने के बावजूद, बिना बदले URL के तहत `app.js` बदल गया था।

### CSS आर्किटेक्चर
- **कस्टम प्रॉपर्टीज़ की तीन लेयर्स।** एक रॉ रैंप (`--w-0`…`--w-900` लाइट के लिए वॉर्म न्यूट्रल्स, `--d-950`…`--d-50` डार्क के लिए), एक सिमेंटिक लेयर जो इसे पॉइंट करती है, और कंपोनेंट्स जो केवल सिमेंटिक लेयर को रेफरेंस करते हैं।
- **कोई प्रीप्रोसेसर नहीं** (कोई Sass, Less, या PostCSS नहीं)
- मीडिया क्वेरीज़ के साथ **मोबाइल-फर्स्ट** रिस्पॉन्सिव डिज़ाइन
- **WCAG AA** कंट्रास्ट, जिसे CI में दोनों थीम्स में हर पैनल और हर पेज पर Playwright स्वीप द्वारा गेट किया जाता है

सिमेंटिक लेयर, जिसके आधार पर आपको कोड लिखना चाहिए:
```css
:root {
  --bg: var(--paper);          /* the page */
  --bg-section: var(--warm-white);
  --bg-card: var(--w-0);
  --text: var(--ink);
  --text-2: var(--ink-secondary);
  --text-3: var(--ink-tertiary);
  --accent: var(--green-700);
  --border: var(--w-300);
}
[data-theme="dark"] {
  --bg: var(--d-950);
  --bg-section: var(--d-900);
  --bg-card: var(--d-850);
  --text: var(--d-50);
  --accent: #4ADE80;
  --border: var(--d-700);
}
```
इनके साथ इंक टोकन्स भी हैं — `--ink-red`, `--ink-blue`, `--ink-teal` और बाकी — जो इसलिए मौजूद हैं क्योंकि एक सैचुरेटेड ह्यू जो सफेद रंग पर टेक्स्ट के रूप में दिखता है, वह `#0e0e0c` पर टेक्स्ट के रूप में नहीं दिखता। JavaScript या `style=` एट्रिब्यूट में एक लिटरल के रूप में लिखा गया रंग यह नहीं जान सकता कि वह किस थीम में आया है, इसलिए इसे एक टोकन मिलता है और CSS स्विचिंग का काम करता है।

### थीमिंग
`<html&gt;` पर `data-theme="dark"`, जिसे `js/chrome.js` सेट करता है और `janvayu-theme` के तहत स्टोर किया जाता है। हर पेज के `<head>` में एक छोटा इनलाइन स्क्रिप्ट होता है जो पहले पेंट से पहले स्टोर की गई वैल्यू को अप्लाई करता है, ताकि कोई पेज कभी लाइट पेंट न करे और फिर फ्लिप न हो। `prefers-color-scheme` ब्लॉक न जोड़ें: चार पेजों में पहले यह होता था, जिसका मतलब था कि वे ऑपरेटिंग सिस्टम का पालन करते थे और साइट के अपने कंट्रोल को नज़रअंदाज़ करते थे।

### JavaScript पैटर्न्स
  
[/tech-stack/frontend.md]
- **अधिकतम ES2022**: `eslint.config.mjs` में सेट किया गया `ecmaVersion`

## Chart.js
**Version:** 4.x (4.5.1) पर पिन किया गया, SRI के साथ jsDelivr से लोड किया गया और lazy-loaded
**इस्तेमाल:**
- मेट्रो बनाम क्षेत्रीय AQI तुलना के बार चार्ट
- PM2.5 ट्रेंड लाइन्स
- हेल्थ इम्पैक्ट डेटा विज़ुअलाइज़ेशन
- सीज़नल बेसलाइन तुलनाएँ
**Chart.js क्यों:**
- छोटा फुटप्रिंट (~70 KB gzipped, ~60 KB Brotli)
- बिना बिल्ड स्टेप के काम करता है (CDN स्क्रिप्ट टैग)
- Canvas-आधारित रेंडरिंग (मोबाइल पर परफ़ॉर्मेंट)
- इन-बिल्ट responsive/accessibility फ़ीचर्स

## Leaflet.js + OpenStreetMap
**Version:** 1.9.4, SRI के साथ unpkg से लोड किया गया
**इस्तेमाल:**
- 160 शहरों (157 भारतीय, साथ ही बीजिंग, लंदन और सिंगापुर) का इंटरैक्टिव मैप, जिसमें AQI स्टेशन मार्कर्स हैं
- AQI गंभीरता के अनुसार कलर-कोडेड मार्कर्स (हरे/पीले/नारंगी/लाल/बैंगनी)
- स्टेशन की डिटेल्स देखने के लिए क्लिक करें
**Leaflet + OSM क्यों:**
- मुफ़्त और ओपन सोर्स (किसी Google Maps API key की ज़रूरत नहीं)
- हल्का (~40 KB gzipped)
- OpenStreetMap डेटा मुफ़्त है, लेकिन इसके tile servers बेस्ट-एफर्ट और पॉलिसी-लिमिटेड हैं ([usage policy](https://operations.osmfoundation.org/policies/tiles/)); भारी इस्तेमाल के लिए कमर्शियल या सेल्फ-होस्टेड tile source की ज़रूरत होती है। साइट Carto basemap tiles का भी इस्तेमाल करती है

## Multilingual Support
JanVayu क्लाइंट-साइड लैंग्वेज टॉगल के ज़रिए 5 भाषाओं का समर्थन करता है:
| Language | Code |
|----------|------|
| English | `en` |
| Hindi | `hi` |
| Tamil | `ta` |
| Marathi | `mr` |
| Bengali | `bn` |
**Implementation:** लैंग्वेज स्ट्रिंग्स को JS ऑब्जेक्ट्स के रूप में स्टोर किया जाता है और टॉगल करने पर DOM एलिमेंट्स में स्वैप किया जाता है। कोई i18n लाइब्रेरी नहीं — बस एक साधारण key-value लुकअप।

## Accessibility
- सभी इंटरैक्टिव एलिमेंट्स के लिए कीबोर्ड नेविगेशन
- जहाँ सिमेंटिक HTML कमज़ोर पड़े, वहाँ ARIA roles
- WCAG AA (टेक्स्ट के लिए 4.5:1) को पूरा करने वाला कलर कंट्रास्ट
- CI (`accessibility.yml`) में axe-core स्वीप्स रन होते हैं
- इंटरैक्टिव एलिमेंट्स पर फोकस इंडिकेटर्स
