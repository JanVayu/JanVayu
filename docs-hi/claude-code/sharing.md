# इस सेटअप को शेयर और रेप्लिकेट करना
यह पेज बताता है कि अपनी टीम के साथ JanVayu के Claude Code वर्कफ़्लो को कैसे शेयर करें या अपने खुद के प्रोजेक्ट के लिए इसे कैसे रेप्लिकेट करें।
---
## अपनी टीम के लिए
### डॉक्स शेयर करें
यह डॉक्यूमेंटेशन JanVayu की अपनी साइट [`/docs/`](/docs/ ':ignore') पर होस्ट किया गया है, जो एक सिंगल-पेज Docsify शेल है और रिपॉजिटरी से सीधे मार्कडाउन पढ़ता है। यह URL किसी भी ऐसे व्यक्ति को भेजें जिसे यह समझने की ज़रूरत है:
- JanVayu कैसे बनाया गया है
- Claude Code का उपयोग करके कैसे योगदान दें
- किसी दूसरे शहर या डोमेन के लिए JanVayu को फोर्क कैसे करें
### एक नए योगदानकर्ता को ऑनबोर्ड करें
1. **रिपो को क्लोन करें** — `git clone https://github.com/JanVayu/JanVayu.git`
2. **डॉक्स पढ़ें**: [`/docs/`](/docs/ ':ignore') से शुरुआत करें, खासकर:
   - [Tech Stack Overview](../tech-stack/overview.md)
   - [Architecture](../technical/architecture.md)
   - [Local Development](../technical/local-development.md)
3. **Claude Code इंस्टॉल करें** — `npm install -g @anthropic-ai/claude-code`
4. **एक सेशन शुरू करें** — `cd JanVayu && claude`
5. **वर्कफ़्लो फॉलो करें** — [Workflow](workflow.md) में बताया गया है
---
## अपने खुद के प्रोजेक्ट के लिए
### स्टेप 1: कंस्ट्रेंट-फर्स्ट अप्रोच अपनाएं
JanVayu से सीखा जा सकने वाला सबसे उपयोगी सबक **कंस्ट्रेंट-फर्स्ट प्रॉम्प्टिंग** है। Claude Code से कुछ भी बनाने के लिए कहने से पहले:
1. तय करें कि आपका प्रोजेक्ट किन चीज़ों (फ्रेमवर्क, बिल्ड टूल आदि) का *उपयोग नहीं* करेगा
2. अपनी कोड स्टाइल और नियमों को तय करें
3. अपने डिप्लॉयमेंट टारगेट को तय करें
4. इन्हें अपनी रिपॉजिटरी के रूट में एक `CLAUDE.md` फ़ाइल में डालें
### स्टेप 2: स्किल फ़ाइलें बनाएं
अगर आपका प्रोजेक्ट AI फ़ीचर्स (कोई भी मॉडल — Groq, OpenAI, Claude API) का उपयोग करता है, तो हर AI इंटरेक्शन को एक स्किल फ़ाइल के रूप में डॉक्यूमेंट करें:
```markdown
# Skill: [Feature Name]
## Role
[मॉडल क्या भूमिका निभाता है]
## Data Context
[प्रॉम्प्ट में कौन सा असली डेटा इंजेक्ट किया जाता है]
## Output Format
[अपेक्षित सटीक संरचना]
## Constraints
[शब्द सीमा, टोन, भाषा, क्या नहीं करना है]
## Fallback
[अगर AI कॉल फेल हो जाए तो क्या होगा]
```
### स्टेप 3: Git Hooks सेट अप करें
इन नियमों को लागू करने के लिए JanVayu के git hooks (`.githooks/`) को कॉपी करें:
- कमिट मैसेज के नियम
- कमिट्स में कोई सीक्रेट्स नहीं
- कोई debug स्टेटमेंट नहीं
### स्टेप 4: बनाते समय डॉक्यूमेंटेशन बनाएं
अपने कोड के साथ Docsify (या कोई भी मार्कडाउन-आधारित) डॉक्स बनाएं। Claude Code आपके कोडबेस से डॉक्यूमेंटेशन जनरेट कर सकता है — इसका उपयोग करें।

## किसी दूसरे शहर के लिए JanVayu को फोर्क करना
JanVayu का कोड MIT-लाइसेंस प्राप्त है (इसकी सामग्री CC BY-NC-SA 4.0 है)। इसे किसी दूसरे शहर या देश के लिए फोर्क करने के लिए:
1. **GitHub पर रेपो को फोर्क करें**
2. `app.js` में **शहरों की सूची अपडेट करें** और Netlify फंक्शन्स में `CITIES` टेबल्स को अपडेट करें
3. `anomaly-check.mjs` में **मौसमी बेसलाइन्स अपडेट करें**
4. अपने क्षेत्र के लिए **WAQI स्टेशन आईडी अपडेट करें**
5. स्थानीय भाषाओं के लिए **स्ट्रिंग्स ट्रांसलेट करें**
6. एनवायरनमेंट वेरिएबल्स के साथ **अपनी खुद की Netlify साइट सेट अप करें**
7. **वैकल्पिक:** डिफ़ॉल्ट Groq मॉडल (`openai/gpt-oss-120b`) को किसी अन्य मॉडल से बदलें (स्किल फाइल्स मॉडल-एग्नोस्टिक हैं)
Claude Code इन सभी चरणों में मदद कर सकता है।

## इस डॉक्यूमेंटेशन को एक्सपोर्ट करना
### एक स्टैंडअलोन साइट के रूप में
डॉक्यूमेंट्स पहले से ही एक स्टैंडअलोन साइट हैं। किसी भी पाठक को [`https://www.janvayu.in/docs/`](https://www.janvayu.in/docs/) पर भेजें।
### Markdown के रूप में
रॉ Markdown फाइलें रेपो में `docs/` (अंग्रेज़ी) और `docs-{lang}/` (हिंदी, बंगाली, मराठी, तमिल) में हैं। इन्हें सीधे शेयर करें या कहीं भी होस्ट करें जो Markdown को रेंडर करता हो — GitHub, Notion, HackMD, अपनी खुद की Docsify या MkDocs साइट।
### PDF के रूप में
Docsify में अपना खुद का इन-बिल्ट PDF एक्सपोर्ट नहीं है। लाइव डॉक्स को PDF में बदलने के लिए, `https://www.janvayu.in/docs/` को PDF में रेंडर करने के लिए `wkhtmltopdf` या Puppeteer जैसे हेडलेस-Chrome टूल का उपयोग करें।

## Docs Stack
JanVayu के डॉक्स Docsify पर चलते हैं — इसे चुना गया क्योंकि इसमें कोई बिल्ड स्टेप, कोई सर्वर और कोई थर्ड-पार्टी होस्टिंग बिल नहीं है।
### मल्टीलिंगुअल सेटअप कैसे काम करता है
अंग्रेज़ी Markdown `docs/` में रहता है। प्रत्येक ट्रांसलेट की गई भाषा `docs-{lang}/` में रहती है। `/docs/index.html` पर एक सिंगल Docsify शेल एक एलियास मैप घोषित करता है जो हैश पाथ्स को सही डायरेक्टरी में रूट करता है, ताकि विज़िटर्स यहाँ पहुँच सकें:
| भाषा | URL | सोर्स डायरेक्टरी |
|----------|-----|------------------|
| अंग्रेज़ी (डिफ़ॉल्ट) | [`/docs/`](/docs/ ':ignore') | `docs/` |
| हिंदी | [`/docs/#/hi/`](/docs/#/hi/ ':ignore') | `docs-hi/` |
| बंगाली | [`/docs/#/bn/`](/docs/#/bn/ ':ignore') | `docs-bn/` |
| मराठी | [`/docs/#/mr/`](/docs/#/mr/ ':ignore') | `docs-mr/` |
| तमिल | [`/docs/#/ta/`](/docs/#/ta/ ':ignore') | `docs-ta/` |
ट्रांसलेट की गई ट्रीज़ को एक CI ऑटो-ट्रांसलेट जॉब (`.github/workflows/translations.yml`, जिसे Sarvam API key की आवश्यकता है) द्वारा रिफ्रेश किया जाता है और यह अंग्रेज़ी डॉक्स से पीछे हो सकती हैं। 21 नवंबर 2026 को, 74 अंग्रेज़ी Markdown पेजों में से, 70 का हिंदी वर्ज़न था, 68 का बंगाली, 70 का मराठी और 71 का तमिल वर्ज़न था। ज़्यादातर जो पेज गायब हैं, वे डेटेड फैक्ट-चेक रिपोर्ट्स हैं।
### प्लगइन्स
| प्लगइन | उद्देश्य |
|--------|---------|
| `docsify-themeable` | ब्रांड-रंग थीम (JanVayu हरा) और डार्क मोड टॉगल |
| `docsify-pagination` | पेजों के बीच पिछला/अगला नेविगेशन |
| `docsify-copy-code` | हर कोड ब्लॉक पर वन-क्लिक कॉपी बटन |
| `docsify-footer-enh` | कॉपीराइट और लाइसेंस के साथ फ़ुटर लाइन |
| `docsify` सर्च | सभी 5 भाषा ट्रीज़ में बिल्ट-इन क्लाइंट-साइड सर्च |
| Prism.js | bash, JS, JSON, YAML, TOML, Markdown के लिए सिंटैक्स हाइलाइटिंग |
| Docsify ज़ूम-इमेज | इमेजेस पर क्लिक-टू-ज़ूम |
