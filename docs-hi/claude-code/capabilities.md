# Claude Code Setup — Full Capabilities Reference

यह पेज JanVayu Claude Code सेटअप की सभी क्षमताओं की एक विस्तृत जानकारी देता है — जिसमें डेवलपमेंट टूल्स, एन्फोर्समेंट मैकेनिज्म, AI फीचर्स, CI/CD ऑटोमेशन, डिप्लॉयमेंट इंफ्रास्ट्रक्चर और डॉक्यूमेंटेशन वर्कफ़्लो शामिल हैं।

---

## 1. Core Development Capabilities

### File Operations
- रिपॉजिटरी की **किसी भी फ़ाइल को पढ़ें** — `index.html`, Netlify Functions, कॉन्फ़िग्स, डॉक्यूमेंटेशन
- **नई फ़ाइलें लिखें** — Netlify Functions, डॉक्यूमेंटेशन पेज, कॉन्फ़िग फ़ाइलें बनाएँ
- **मौजूदा फ़ाइलों को एडिट करें** — बिना गैर-ज़रूरी कोड को दोबारा लिखे, सीधे और सटीक बदलाव करें
- **फ़ाइल के नाम के पैटर्न से खोजें** — ग्लोब मैचिंग (जैसे, `**/*.mjs`, `docs/**/*.md`)
- **कंटेंट के ज़रिए खोजें** — पूरे कोडबेस में regex-आधारित फुल-टेक्स्ट सर्च

### Shell & Terminal Access
- डिपेंडेंसीज़ को मैनेज करने के लिए `npm install` रन करें
- लोकल डेवलपमेंट सर्वर के लिए `netlify dev` रन करें
- कोई भी नॉन-डिस्ट्रक्टिव शेल कमांड चलाएँ
- `git`, `gh` (GitHub CLI), `ls`, `mkdir` तक एक्सेस
- **कन्वेंशन के अनुसार ब्लॉक**: `rm -rf`, `git push --force`, `git reset --hard`

### Multi-File Coordination
एक सिंगल Claude Code सेशन एक ही बार में इन सभी को संभाल सकता है:
- `index.html` (मार्कअप), `app.js` (लॉजिक) और `styles.css` (स्टाइलिंग)
- Netlify Functions (`netlify/functions/*.mjs` या `*.js`)
- कॉन्फ़िगरेशन फ़ाइलें (`netlify.toml`, `package.json`, `.editorconfig`)
- डॉक्यूमेंटेशन (`docs/**/*.md`, `CHANGELOG.md`, `README.md`)
- Git हुक्स (`.githooks/pre-commit`, `.githooks/commit-msg`)
- GitHub वर्कफ़्लो (`.github/workflows/*.yml`)

## 2. Git Workflow Capabilities

### Branching & Commits
- फीचर ब्रांच बनाएँ (जैसे, `claude/feature-name`)
- विशिष्ट फ़ाइलों को स्टेज करें (इससे `.env` या सीक्रेट्स के गलती से शामिल होने से बचाव होता है)
- लागू किए गए प्रीफिक्स कन्वेंशन का पालन करते हुए मैसेज के साथ कमिट करें:
  - `Add:` — नया फीचर या फ़ाइल
  - `Fix:` — बग फिक्स
  - `Update:` — मौजूदा फीचर में सुधार
  - `Translate:` — ट्रांसलेशन का काम
  - `Docs:` — डॉक्यूमेंटेशन में बदलाव
  - `Refactor:` — कोड का रीस्ट्रक्चरिंग (बिहेवियर में कोई बदलाव नहीं)
  - `Test:` — टेस्ट जोड़ना
  - `CI:` — CI/CD पाइपलाइन में बदलाव
  - `Chore:` — मेंटेनेंस के काम
- 72 कैरेक्टर से ज़्यादा के सब्जेक्ट लाइन पर हुक एक चेतावनी देता है (ब्लॉक नहीं); `Merge` भी एक मान्य प्रीफिक्स है

### Pull Request Management
- स्ट्रक्चर्ड टाइटल, समरी और टेस्ट प्लान के साथ PRs बनाएँ
- मल्टी-PR वर्कफ़्लो को मैनेज करें (जैसे, पहले बैकएंड, फिर फ्रंटएंड, फिर डॉक्स)
- PR डिफ्स को रिव्यू करें और बदलावों का सुझाव दें
- कमेंट्स जोड़ें और रिव्यू फीडबैक का जवाब दें
### Git Hook Enforcement
इस सेटअप में दो कस्टम git hooks शामिल हैं जो अपने आप रन होते हैं:

**Pre-commit hook** (`.githooks/pre-commit`):
| Check | Action |
|-------|--------|
| `.env`, `.env.local`, `.env.production` | **Block commit** |
| `credentials.json`, `*.pem`, `*.key` | **Block commit** |
| `debugger` statements, `breakpoint()` | **Block commit** |
| Merge conflict markers (`<<<<<<<`, `>>>>>>>`) | **Block commit** |
| `console.log`, `console.debug`, `console.warn` | **Warn** (`// keep` के साथ बायपास करें) |
| 500 KB से बड़ी फाइलें | **Warn** |

**Commit message hook** (`.githooks/commit-msg`):
| Check | Action |
|-------|--------|
| जरूरी प्रीफिक्स का न होना | **Block commit** |
| सब्जेक्ट लाइन 72 कैरेक्टर से ज्यादा | **Warn** |
| Merge/revert/fixup कमिट्स | **Skip enforcement** |

## 3. AI-Powered Features (Groq-hosted model)

> **Update, 2 Oct 2026: Groq ने 16 Aug 2026 को Llama 3.3 70B को बंद कर दिया (Groq deprecations page); फंक्शन्स अब डिफ़ॉल्ट रूप से `openai/gpt-oss-120b` का इस्तेमाल करते हैं, जिसे `GROQ_MODEL` environment variable से बदला जा सकता है।**

इस सेटअप में चार प्रोडक्शन AI फीचर्स शामिल हैं, जिनमें से हर एक को एक स्ट्रक्चर्ड स्किल फाइल के साथ Netlify Function के रूप में इम्प्लीमेंट किया गया है:

### 3.1 Air Quality Assistant (`air-query.mjs`)
- **Input**: शहर का नाम + नेचुरल लैंग्वेज में सवाल
- **Output**: ग्राउंडेड जवाब (लगभग 150 शब्दों का), जिसमें असली AQI नंबरों का हवाला दिया गया हो
- **Languages**: अंग्रेज़ी के अलावा नौ भारतीय भाषाएं (हिंदी, तमिल, बंगाली, मराठी, तेलुगु, गुजराती, कन्नड़, मलयालम, पंजाबी)
- **Key constraint**: इसमें असली डेटा का हवाला देना ज़रूरी है — कोई जेनेरिक सलाह नहीं
- **Fallback**: अगर Groq पर रेट लिमिट लग जाए, तो यह रॉ AQI डेटा वापस करता है
- **Skill file**: `docs/skills/air-quality-assistant.md`

### 3.2 Health Advisory (`health-advisory.mjs`)
- **Input**: शहर + उम्र + स्वास्थ्य की स्थितियां + बाहर बिताए गए घंटे
- **Output**: कलर-कोडेड रिस्क लेवल + ठोस सुझाव (3-4 वाक्य)
- **Key constraint**: सीधा सुझाव, कोई गोलमोल बात नहीं — "घर के अंदर रहें" न कि "घर के अंदर रहने पर विचार करें"
- **Pre-AI step**: AI के जवाब आने से पहले, एक JavaScript फंक्शन तुरंत UI कलर-कोडिंग के लिए रिस्क लेवल कैलकुलेट करता है
- **Fallback**: अगर AI की व्याख्या फेल भी हो जाए, तब भी रिस्क लेवल दिखाई देता है
- **Skill file**: `docs/skills/health-advisory.md`
### 3.3 जवाबदेही ब्रीफ (`accountability-brief.mjs`)
- **इनपुट**: शहर + वार्ड/इलाका + समय अवधि
- **आउटपुट**: आठ लेबल वाले सेक्शन के साथ स्ट्रक्चर्ड ब्रीफ (इलाका, अवधि, वर्तमान PM2.5, स्थिति, डेटा क्या दिखाता है, संभावित स्रोत, स्थानीय लोग क्या कर सकते हैं, डेटा की सीमा)
- **अधिकतम आउटपुट**: 1,024 टोकन
- **लक्षित दर्शक**: वार्ड पार्षद, स्थानीय पत्रकार, RWAs (रेजिडेंट वेलफेयर एसोसिएशन)
- **मुख्य विशेषता**: इसमें विशिष्ट स्थानीय नियामक तंत्र (GRAP, RTI और नगर निगम शिकायत लाइनें) शामिल हैं
- **फॉलबैक**: बिना AI विश्लेषण के कच्चा डेटा लौटाता है
- **स्किल फ़ाइल**: `docs/skills/accountability-brief.md`

### 3.4 विसंगति का पता लगाना (`anomaly-check.mjs`)
- **इनपुट**: स्वचालित — दिल्ली, मुंबई, कोलकाता, चेन्नई, बेंगलुरु की निगरानी करता है
- **थ्रेशोल्ड**: PM2.5 > 2× मौसमी बेसलाइन = विसंगति
- **आउटपुट**: हर स्पाइक के लिए एक वाक्य का स्पष्टीकरण
- **मौसमी बेसलाइन**: हार्डकोडेड अनुमानित JanVayu वर्किंग बेसलाइन, प्रकाशित CREA या IQAir के आंकड़े नहीं (डायनामिक रूप से गणना नहीं की जाती)
- **फॉलबैक**: AI स्पष्टीकरण के बिना विसंगति फ़्लैग लौटाता है
- **स्किल फ़ाइल**: `docs/skills/anomaly-explainer.md`

### साझा AI आर्किटेक्चर
सभी चार फ़ीचर में ये चीज़ें शामिल हैं:
- केवल सर्वर-साइड निष्पादन (क्लाइंट पर कोई API कीज़ एक्सपोज़ नहीं की गई हैं)
- CORS प्रीफ़्लाइट हैंडलिंग (OPTIONS → 204)
- उचित स्टेटस कोड के साथ JSON रिस्पॉन्स
- हर बाहरी कॉल पर try/catch
- ग्रेसफुल डिग्रेडेशन — हर AI फ़ीचर में एक नॉन-AI फॉलबैक है

## 4. Netlify Functions (28 सर्वरलेस हैंडलर)

नीचे दी गई टेबल मुख्य फ़ंक्शन्स को सूचीबद्ध करती हैं। रिपॉजिटरी में 28 हैंडलर फ़ाइलें और एक साझा हेल्पर (`blob-store.js`) है; इनमें से पाँच हैंडलर शेड्यूल्ड हैं।

| फ़ंक्शन | शेड्यूल | उद्देश्य |

| `daily-digest.mjs` | रोज़ सुबह 8:00 बजे IST | Resend API के ज़रिए सब्सक्राइबर्स को AQI ईमेल डाइजेस्ट भेजता है |

### ऑन-डिमांड फ़ंक्शन्स (AI)
| फ़ंक्शन | मेथड | उद्देश्य |

### ऑन-डिमांड फंक्शन्स (डेटा)
| फंक्शन | मेथड | उद्देश्य |

| `instagram-feed.js` | GET | कैश्ड Instagram पोस्ट |
| `news-proxy.js` | GET | कैश्ड न्यूज़ आर्टिकल |
| `subscribe.js` | POST | ईमेल सब्सक्रिप्शन मैनेजमेंट |
| `feed-status.js` | GET | फीड फ्रेशनेस हेल्थ चेक |

### साझा उपयोगिता
| फंक्शन | उद्देश्य |
|----------|---------|
| `blob-store.js` | Netlify Blobs स्टोर इनिशियलाइज़ेशन (अन्य फंक्शन्स द्वारा इम्पोर्ट किया गया) |

### स्टैंडर्ड फंक्शन पैटर्न
हर फंक्शन इस टेम्पलेट का पालन करता है:

2. `try/catch` में रैप किया गया कोर लॉजिक
3. CORS हेडर्स के साथ JSON रिस्पॉन्स बॉडी
4. एरर पर ग्रेसफुल फॉलबैक (कभी भी खाली बॉडी के साथ `500` रिटर्न नहीं करता)

## 6. डिप्लॉयमेंट और इंफ्रास्ट्रक्चर

### होस्टिंग — Netlify CDN
- Let's Encrypt के साथ ऑटोमैटिक HTTPS
- ग्लोबल CDN डिस्ट्रीब्यूशन
- नॉन-www → www रीडायरेक्ट (कैनोनिकल डोमेन)
- SPA फॉलबैक: सभी रूट्स → `/index.html`
- `/robots.txt` और `/sitemap.xml` के लिए विशेष रूट्स
### सिक्योरिटी हेडर
| हेडर | वैल्यू | उद्देश्य |
|--------|-------|---------|
| `X-Frame-Options` | `DENY` | क्लिकजैकिंग को रोकता है |
| `X-Content-Type-Options` | `nosniff` | MIME स्निफिंग को रोकता है |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | रेफरर जानकारी को कंट्रोल करता है |

### कैशिंग — Netlify Blobs
- स्ट्रॉन्ग कंसिस्टेंसी मॉडल
- शेड्यूल्ड फंक्शन द्वारा सोशल फीड और न्यूज़ को पहले से कैश करने के लिए उपयोग किया जाता है
- ऑन-डिमांड फंक्शन पहले कैश से पढ़ते हैं, और ज़रूरत पड़ने पर लाइव डेटा लाते हैं
- `@netlify/blobs` पैकेज के ज़रिए एक्सेस किया जाता है

### ईमेल — Resend API
- डेली डाइजेस्ट (`daily-digest.mjs`) और अन्य सर्वर-साइड मेलर्स (`health-monitor.mjs`, `terra-collab.mjs`, `workshop-submit.mjs`) के लिए ईमेल डिलीवरी; `subscribe.js` ईमेल नहीं भेजता है
- केवल सर्वर-साइड (Netlify Functions के ज़रिए)

### ज़रूरी एनवायरनमेंट वेरिएबल्स
| वेरिएबल | उद्देश्य | कहाँ उपयोग होता है |
