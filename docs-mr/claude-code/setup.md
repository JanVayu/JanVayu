# JanVayu साठी Claude Code सेटअप
हे पृष्ठ Claude Code वापरून JanVayu विकसित करण्यासाठी वापरल्या जाणाऱ्या अचूक कॉन्फिगरेशनची नोंद ठेवते — ज्यामध्ये CLAUDE.md फाईल, परमिशन सेटिंग्स आणि MCP इंटिग्रेशन्स समाविष्ट आहेत.
---
## CLAUDE.md — प्रोजेक्ट सूचना
JanVayu च्या रिपॉझिटरी रूटमध्ये एक छोटी `CLAUDE.md` फाईल आहे. ती या पृष्ठांकडे, `CONTRIBUTING.md` आणि `FORKING.md` कडे, आणि `.claude/engineering-standards.md` मधील सामायिक इंजिनिअरिंग स्टँडर्डकडे निर्देश करते. ती `scripts/` मधील CI चेक्सची नावे देते आणि कमिट्स पुश करणाऱ्या शेड्युल्ड वर्कफ्लोबद्दल इशारा देते. ती नियमांची पुनरावृत्ती करत नाही, जे खालील गोष्टींद्वारे लागू केले जातात:
1. **Git hooks** (`.githooks/pre-commit` आणि `.githooks/commit-msg`) — कमिट मेसेज फॉरमॅट आपोआप लागू करतात आणि संवेदनशील फाईल्स ब्लॉक करतात
2. **`.editorconfig`** — इंडेंटेशन आणि एन्कोडिंग प्रमाणित करते
3. **`.gitmessage`** — कमिट मेसेज टेम्पलेट
4. **इनलाईन डॉक्युमेंटेशन** — README.md, CONTRIBUTING.md, आणि कोड कमेंट्स
### फोर्क्ससाठी सुचवलेले CLAUDE.md
जर तुम्ही JanVayu फोर्क केले आणि तुम्हाला Claude Code ला प्रोजेक्ट-विशिष्ट सूचना द्यायच्या असतील, तर रिपो रूटमधील `CLAUDE.md` तुमच्या स्वतःच्या फाईलने बदला. या रिपॉझिटरीमधील फाईलपेक्षा अधिक सविस्तर सुरुवातीचा बिंदू:
```markdown
# CLAUDE.md — JanVayu प्रोजेक्ट सूचना
## आर्किटेक्चर
- फ्रंट एंड: index.html (मार्कअप), app.js (लॉजिक), styles.css (स्टायलिंग), games.js, js/ आणि panels/
- कोणतेही फ्रेमवर्क्स नाहीत, बिल्ड स्टेप नाही, क्लायंटवर npm डिपेंडन्सीज नाहीत
- सर्व्हर-साइड लॉजिकसाठी Netlify Functions (ES मॉड्यूल्स, .mjs)
- कॅशिंगसाठी Netlify Blobs (स्ट्रॉंग कन्सिस्टन्सी)
## कोड स्टाईल
- फक्त व्हॅनिला जावास्क्रिप्ट (ES2022, eslint.config.mjs मध्ये सेट केल्याप्रमाणे)
- थीमिंगसाठी CSS कस्टम प्रॉपर्टीज
- 2-स्पेस इंडेंटेशन (HTML, CSS, JS, JSON)
- TypeScript नाही, प्रीप्रोसेसर्स नाहीत
## कमिट मेसेजेस
यांनी सुरू झाले पाहिजेत: Add, Fix, Update, Translate, Docs, Refactor, Test, CI, Chore, Merge
## Netlify Functions पॅटर्न
- CORS प्रीफ्लाइट हँडल करा (OPTIONS → 204)
- योग्य स्टेटस कोड्ससह JSON रिटर्न करा
- प्रत्येक बाह्य कॉलवर try/catch वापरा
- सिक्रेट्स कधीही हार्डकोड करू नका — process.env वापरा
- बाह्य API फेल झाल्यास ग्रेसफुल फॉलबॅक
## AI फीचर्स
- मॉडेल: Groq द्वारे openai/gpt-oss-120b (डिफॉल्ट; GROQ_MODEL एन्व्हायर्नमेंट व्हेरिएबलसह ओव्हरराइड करा)
- सर्व AI कॉल्स सर्व्हर-साइड (Netlify Functions)
- प्रत्येक AI फीचरसाठी नॉन-AI फॉलबॅक आहे
- आउटपुट टोकन मर्यादा: प्रति रिस्पॉन्स 512 ते 1,024 (max_tokens)
## करू नका
- फ्रेमवर्क्स जोडू नका (React, Vue, Angular, Svelte)
- बिल्ड स्टेप जोडू नका (Webpack, Vite, Rollup)
- TypeScript जोडू नका
- क्लायंट साइडवर npm पॅकेजेस इम्पोर्ट करू नका
- क्लायंट कोडमध्ये API कीज उघड करू नका
```

## स्किल फाइल्स
स्किल फाइल्स या स्ट्रक्चर्ड सिस्टीम प्रॉम्प्ट्स असतात, ज्या AI मॉडेल्स कसे काम करतील हे ठरवतात. JanVayu त्यांच्या Groq-होस्टेड AI फीचर्ससाठी त्यांचा वापर करते, पण हीच संकल्पना Claude Code वर्कफ्लोलाही लागू होते.
[Skills section](../skills/README.md) मध्ये डॉक्युमेंट केलेल्या स्किल फाइल्स खालीलप्रमाणे काम करतात:
1. **Groq system prompts** — Netlify Functions मध्ये एम्बेड केलेले ( `air-query.mjs` मधील Ask JanVayu प्रॉम्प्ट, ते डॉक्युमेंट करणाऱ्या पेजपेक्षा खूप मोठा आहे)
2. **Development reference** — AI फीचर्समध्ये बदल करताना Claude Code ला मार्गदर्शन करणे
3. **Reusable templates** — इतर डोमेन्ससाठी JanVayu फोर्क करणाऱ्या कोणासाठीही
### स्किल फाइल स्ट्रक्चर
प्रत्येक स्किल फाइल या फॉरमॅटचे पालन करते:
```markdown
# Skill: [Name]

## Role
मॉडेलने कशी भूमिका बजावावी.
## Context
त्याला कोणता डेटा मिळेल.
## Output Format
रिस्पॉन्सची अचूक रचना.
## Constraints
शब्दांची मर्यादा, टोन, भाषा, फेल्युअर मोड्स.
## Examples
सॅम्पल इनपुट्स आणि अपेक्षित आउटपुट्स.
```

## MCP Server Integrations
Claude Code विस्तारित टूल ॲक्सेससाठी Model Context Protocol (MCP) सर्व्हर्सना सपोर्ट करते. JanVayu सारख्या प्रोजेक्टसोबत खालील MCP इंटिग्रेशन्स वापरले जाऊ शकतात (डेव्हलपमेंट दरम्यान कोणते वापरले गेले हे रिपॉझिटरीमध्ये रेकॉर्ड केलेले नाही):
### Notion MCP
- **उद्देश:** प्रोजेक्ट प्लॅनिंग, टास्क ट्रॅकिंग, मीटिंग नोट्स
- **टूल्स:** पेजेस तयार करणे, डेटाबेसमधून क्वेरी करणे, सर्च करणे, पेजेस अपडेट करणे
- **युज केस:** फीचर डेव्हलपमेंट ट्रॅक करणे, प्रोजेक्ट रोडमॅप मेंटेन करणे
### Gmail MCP
- **उद्देश:** कम्युनिकेशन कॉन्टेक्स्ट
- **टूल्स:** मेसेजेस सर्च करणे, थ्रेड्स वाचणे, ड्राफ्ट्स तयार करणे
- **युज केस:** फीचर्स किंवा पार्टनरशिप्सबद्दलच्या ईमेल चर्चांचा संदर्भ घेणे
### Figma MCP
- **उद्देश:** डिझाईन-टू-कोड वर्कफ्लो
- **टूल्स:** डिझाईन कॉन्टेक्स्ट मिळवणे, स्क्रीनशॉट्स, मेटाडेटा
- **युज केस:** JanVayu UI सेक्शन्ससाठी डिझाईन मॉकअप्सचे HTML/CSS मध्ये रूपांतर करणे
### Google Calendar MCP
- **उद्देश:** शेड्युलिंग कॉन्टेक्स्ट
- **टूल्स:** इव्हेंट्सची लिस्ट पाहणे, इव्हेंट्स तयार करणे, फ्री वेळ शोधणे
- **युज केस:** डेव्हलपमेंट सेशन्स आणि रिलीजच्या तारखांचे प्लॅनिंग करणे
### Excalidraw MCP
- **उद्देश:** आर्किटेक्चर डायग्राम्स
- **टूल्स:** व्ह्यूज तयार करणे, चेकपॉइंट्स सेव्ह करणे
- **युज केस:** सिस्टीम आर्किटेक्चर आणि डेटा फ्लो व्हिज्युअलाईझ करणे

## परमिशन कॉन्फिगरेशन
Claude Code कॉन्फिगरेबल परमिशन्ससह काम करते. JanVayu डेव्हलपमेंटसाठी:
### रेकमेंडेड परमिशन्स
```json
{
  "permissions": {
    "allow": [
      "Read",
      "Glob",
      "Grep",
      "Write",
      "Edit",
      "Bash(npm install)",
      "Bash(netlify dev)",
      "Bash(git *)",
      "Bash(gh pr *)",
      "Bash(ls *)",
      "Bash(mkdir *)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push --force *)",
      "Bash(git reset --hard *)"
    ]
  }
}
```
### या परवानग्या का?
- **Read/Write/Edit/Glob/Grep** — मुख्य विकास साधने
- **npm install** — अवलंबित्वे स्थापित करणे
- **netlify dev** — स्थानिक विकास सर्व्हर चालवणे
- **git** — आवृत्ती नियंत्रण कार्यप्रवाह
- **gh pr** — पुल रिक्वेस्ट तयार करणे आणि व्यवस्थापित करणे
- **विनाशकारी कमांड्स नाकारणे** — चुकून होणाऱ्या डेटा नुकसानीपासून संरक्षण

## विकासासाठी पर्यावरण
क्लॉड कोड शेल पर्यावरण वारशाने प्राप्त करतो. JanVayu साठी:
```bash
# आवश्यक
export GROQ_API_KEY=your_key
export WAQI_TOKEN=your_token
export RESEND_API_KEY=your_key
export NETLIFY_SITE_ID=your_site_id
# ऐच्छिक (स्थानिक विकासात Netlify Blobs साठी)
export BLOB_TOKEN=your_token
```
स्थानिक विकासादरम्यान `netlify dev` द्वारे हे `.env` मधून वाचले जातात.
