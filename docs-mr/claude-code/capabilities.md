# Claude Code सेटअप — संपूर्ण क्षमता संदर्भ

ही पृष्ठे JanVayu Claude Code सेटअप करू शकणाऱ्या सर्व गोष्टींचा एक सर्वसमावेशक आणि सविस्तर संदर्भ आहे — ज्यामध्ये डेव्हलपमेंट टूल्स, अंमलबजावणी यंत्रणा, AI वैशिष्ट्ये, CI/CD ऑटोमेशन, डिप्लॉयमेंट इन्फ्रास्ट्रक्चर आणि डॉक्युमेंटेशन वर्कफ्लो समाविष्ट आहेत.

## १. मुख्य डेव्हलपमेंट क्षमता

### फाईल ऑपरेशन्स
- रिपॉझिटरीमधील **कोणतीही फाईल वाचणे** — `index.html`, Netlify Functions, कॉन्फिग्स, डॉक्युमेंटेशन
- **नवीन फाईल्स लिहिणे** — Netlify Functions, डॉक्युमेंटेशन पृष्ठे, कॉन्फिग फाईल्स तयार करणे
- **अस्तित्वात असलेल्या फाईल्स संपादित करणे** — असंबंधित कोड पुन्हा न लिहिता अचूक इनलाईन एडिट्स करणे
- **फाईलनेम पॅटर्ननुसार शोधणे** — ग्लोब मॅचिंग (उदा., `**/*.mjs`, `docs/**/*.md`)
- **कंटेंटनुसार शोधणे** — कोडबेसमध्ये regex-आधारित फुल-टेक्स्ट शोध

### शेल आणि टर्मिनल ॲक्सेस
- डिपेंडन्सीज व्यवस्थापित करण्यासाठी `npm install` रन करणे
- लोकल डेव्हलपमेंट सर्व्हरसाठी `netlify dev` रन करणे
- कोणताही नॉन-डिस्ट्रक्टिव्ह शेल कमांड एक्झिक्युट करणे
- `git`, `gh` (GitHub CLI), `ls`, `mkdir` चा ॲक्सेस
- **परंपरेनुसार ब्लॉक केलेले**: `rm -rf`, `git push --force`, `git reset --hard`

### मल्टी-फाईल को-ऑर्डिनेशन
एकच Claude Code सेशन एकाच वेळी या सर्वांना स्पर्श करू शकते:
- `index.html` (मार्कअप), `app.js` (लॉजिक) आणि `styles.css` (स्टायलिंग)
- Netlify Functions (`netlify/functions/*.mjs` किंवा `*.js`)
- कॉन्फिगरेशन फाईल्स (`netlify.toml`, `package.json`, `.editorconfig`)
- डॉक्युमेंटेशन (`docs/**/*.md`, `CHANGELOG.md`, `README.md`)
- Git हुक्स (`.githooks/pre-commit`, `.githooks/commit-msg`)
- GitHub वर्कफ्लो (`.github/workflows/*.yml`)

## २. Git वर्कफ्लो क्षमता

### ब्रांचिंग आणि कमिट्स
- फीचर ब्रांचेस तयार करणे (उदा., `claude/feature-name`)
- विशिष्ट फाईल्स स्टेज करणे (यामुळे `.env` किंवा सिक्रेट्स चुकून समाविष्ट होणे टळते)
- सक्तीच्या प्रीफिक्स परंपरेनुसार मेसेजेससह कमिट करणे:
  - `Add:` — नवीन फीचर किंवा फाईल
  - `Fix:` — बग फिक्स
  - `Update:` — अस्तित्वात असलेल्या फीचरमध्ये सुधारणा
  - `Translate:` — भाषांतराचे काम
  - `Docs:` — डॉक्युमेंटेशनमधील बदल
  - `Refactor:` — कोड रिस्ट्रक्चरिंग (कोणताही बिहेविअर बदल नाही)
  - `Test:` — टेस्ट ॲडिशन्स
  - `CI:` — CI/CD पाईपलाईन बदल
  - `Chore:` — मेंटेनन्सची कामे
- ७२ अक्षरांपेक्षा जास्त असलेल्या सब्जेक्ट लाईन्समुळे हुककडून वॉर्निंग येते (ब्लॉक नाही); `Merge` हा देखील एक अनुमत प्रीफिक्स आहे

### पुल रिक्वेस्ट (PR) व्यवस्थापन
- स्ट्रक्चर्ड शीर्षक, सारांश आणि टेस्ट प्लॅनसह PRs तयार करणे
- मल्टी-PR वर्कफ्लो व्यवस्थापित करणे (उदा., आधी बॅकएंड, नंतर फ्रंटएंड, नंतर डॉक्युमेंटेशन)
- PR डिफ्स तपासून बदल सुचवणे
- कमेंट्स ॲड करणे आणि रिव्ह्यू फीडबॅकला प्रतिसाद देणे
### Git Hook Enforcement
या सेटअपमध्ये दोन कस्टम git hooks समाविष्ट आहेत जे आपोआप रन होतात:

**Pre-commit hook** (`.githooks/pre-commit`):
| तपासणी | कृती |
|-------|--------|
| `.env`, `.env.local`, `.env.production` | **कमिट ब्लॉक करा** |
| `credentials.json`, `*.pem`, `*.key` | **कमिट ब्लॉक करा** |
| `debugger` स्टेटमेंट्स, `breakpoint()` | **कमिट ब्लॉक करा** |
| मर्ज कॉन्फ्लिक्ट मार्कर्स (`<<<<<<<`, `>>>>>>>`) | **कमिट ब्लॉक करा** |
| `console.log`, `console.debug`, `console.warn` | **इशारा** (`// keep` वापरून बायपास करा) |
| 500 KB पेक्षा मोठ्या फाइल्स | **इशारा** |

**Commit message hook** (`.githooks/commit-msg`):
| तपासणी | कृती |
|-------|--------|
| आवश्यक प्रीफिक्स नसणे | **कमिट ब्लॉक करा** |
| सब्जेक्ट लाईन > 72 कॅरेक्टर्स | **इशारा** |
| मर्ज/रिव्हर्ट/फिक्सअप कमिट्स | **नियम लागू करू नका** |

## 3. AI-Powered Features (Groq-hosted model)

> **अपडेट, 2 ऑक्टोबर 2026: Groq ने 16 ऑगस्ट 2026 रोजी Llama 3.3 70B बंद केले (Groq डेप्रिकेशन्स पेज); आता फंक्शन्स बायडिफॉल्ट `openai/gpt-oss-120b` वापरतात, जे `GROQ_MODEL` एन्व्हायर्नमेंट व्हेरिएबल वापरून बदलता येते.**

या सेटअपमध्ये चार प्रोडक्शन AI फीचर्स समाविष्ट आहेत, जे प्रत्येकी स्ट्रक्चर्ड स्किल फाइलसह Netlify Function म्हणून इम्प्लिमेंट केले आहेत:

### 3.1 Air Quality Assistant (`air-query.mjs`)
- **इनपुट**: शहराचे नाव + नैसर्गिक भाषेतील प्रश्न
- **आउटपुट**: प्रत्यक्ष AQI नंबरचा संदर्भ देणारे उत्तर (सुमारे 150 शब्दांचे)
- **भाषा**: इंग्रजी आणि नऊ भारतीय भाषा (हिंदी, तमिळ, बंगाली, मराठी, तेलगू, गुजराती, कन्नड, मल्याळम, पंजाबी)
- **मुख्य अट**: खऱ्या डेटाचा संदर्भ देणे आवश्यक आहे — कोणतीही सामान्य माहिती नको
- **फॉल-बॅक**: जर Groq रेट-लिमिटेड असेल तर रॉ (raw) AQI डेटा रिटर्न करते
- **स्किल फाइल**: `docs/skills/air-quality-assistant.md`

### 3.2 Health Advisory (`health-advisory.mjs`)
- **इनपुट**: शहर + वय + आरोग्याच्या समस्या + बाहेर घालवलेले तास
- **आउटपुट**: कलर-कोडेड रिस्क लेव्हल + ठोस शिफारसी (3-4 वाक्ये)
- **मुख्य अट**: थेट सल्ला, कोणतीही संदिग्धता नको — "घरातच राहा" असे म्हणावे, "घरात राहण्याचा विचार करा" असे नाही
- **AI च्या आधीची स्टेप**: JavaScript फंक्शन AI रिस्पॉन्स येण्यापूर्वी लगेच UI कलर-कोडिंगसाठी रिस्क लेव्हल कॅल्क्युलेट करते
- **फॉल-बॅक**: AI स्पष्टीकरण फेल झाले तरी रिस्क लेव्हल दिसते
- **स्किल फाइल**: `docs/skills/health-advisory.md`
### 3.3 अकाउंटेबिलिटी ब्रीफ (`accountability-brief.mjs`)
- **इनपुट**: शहर + प्रभाग/भाग + कालावधी
- **आउटपुट**: आठ लेबल केलेल्या विभागांसह (भाग, कालावधी, सध्याचे PM2.5, स्थिती, डेटा काय सांगतो, संभाव्य स्रोत, स्थानिक घटक काय करू शकतात, डेटाची मर्यादा) स्ट्रक्चर्ड ब्रीफ
- **कमाल आउटपुट**: 1,024 टोकन्स
- **प्रेक्षक**: प्रभाग नगरसेवक, स्थानिक पत्रकार, RWAs (निवासी कल्याण संस्था)
- **मुख्य वैशिष्ट्य**: विशिष्ट स्थानिक नियामक यंत्रणांचा समावेश (GRAP, RTI आणि महानगरपालिकेच्या तक्रार क्रमांक)
- **फॉल-बॅक**: AI विश्लेषणाशिवाय कच्चा डेटा (raw data) परत करतो
- **स्किल फाईल**: `docs/skills/accountability-brief.md`

### 3.4 ॲनोमली डिटेक्शन (`anomaly-check.mjs`)
- **इनपुट**: स्वयंचलित — दिल्ली, मुंबई, कोलकाता, चेन्नई, बेंगळुरूवर लक्ष ठेवते
- **थ्रेशोल्ड**: PM2.5 > 2× हंगामी बेसलाइन = ॲनोमली
- **आउटपुट**: प्रत्येक स्पाइकमध्ये एका वाक्याचे स्पष्टीकरण
- **हंगामी बेसलाइन्स**: हार्डकोड केलेले अंदाजे JanVayu वर्किंग बेसलाइन्स, प्रकाशित CREA किंवा IQAir आकडे नाहीत (डायनॅमिकली मोजले जात नाहीत)
- **फॉल-बॅक**: AI स्पष्टीकरणाशिवाय ॲनोमली फ्लॅग परत करतो
- **स्किल फाईल**: `docs/skills/anomaly-explainer.md`

### सामायिक AI आर्किटेक्चर
सर्व चार वैशिष्ट्यांमध्ये खालील गोष्टी सामायिक आहेत:
- फक्त सर्व्हर-साइड अंमलबजावणी (क्लायंटला कोणतीही API की उघड केली जात नाही)
- CORS प्रीफ्लाइट हाताळणी (OPTIONS → 204)
- योग्य स्टेटस कोडसह JSON प्रतिसाद
- प्रत्येक बाह्य कॉलवर try/catch
- ग्रेसफुल डिग्रेडेशन — प्रत्येक AI वैशिष्ट्यामध्ये नॉन-AI फॉल-बॅक आहे

### स्टँडर्ड फंक्शन पॅटर्न
प्रत्येक फंक्शन या टेम्पलेटचे पालन करते:
1. CORS प्रीफ्लाइट हँडलिंग (`OPTIONS` → `204`)
2. `try/catch` मध्ये रॅप केलेले मुख्य लॉजिक
3. CORS हेडर्ससह JSON रिस्पॉन्स बॉडी
4. एरर आल्यास ग्रेसफुल फॉलबॅक (रिकाम्या बॉडीसह कधीही `500` रिटर्न करत नाही)

**ट्रान्सलेशन सिंक** (`translations.yml`):

**Dependabot** (`dependabot.yml`):
- **व्याप्ती**: GitHub Actions डिपेंडन्सीज आणि npm (2 ऑक्टोबर 2026 रोजी npm जोडले)

- **कमाल ओपन PRs**: प्रति इकोसिस्टम 2; npm मायनर आणि पॅच अपडेट्स एकत्र केले जातात

### सिक्युरिटी हेडर्स
| हेडर | व्हॅल्यू | उद्देश |
|--------|-------|---------|
| `X-Frame-Options` | `DENY` | क्लिकजॅकिंग टाळते |
| `X-Content-Type-Options` | `nosniff` | MIME स्निफिंग टाळते |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | रेफरर माहिती नियंत्रित करते |

### कॅशिंग — Netlify Blobs
- स्ट्रॉंग कन्सिस्टन्सी मॉडेल
- शेड्युल्ड फंक्शन्सद्वारे सोशल फीड्स आणि बातम्या प्री-कॅश करण्यासाठी वापरले जाते
- ऑन-डिमांड फंक्शन्स आधी कॅशमधून वाचतात आणि गरज पडल्यास लाईव्ह डेटा आणतात
- `@netlify/blobs` पॅकेजद्वारे ॲक्सेस केले जाते

### ईमेल — Resend API
- डेली डायजेस्ट (`daily-digest.mjs`) आणि इतर सर्व्हर-साइड मेलर्स (`health-monitor.mjs`, `terra-collab.mjs`, `workshop-submit.mjs`) साठी ईमेल डिलिव्हरी; `subscribe.js` ईमेल पाठवत नाही
- फक्त सर्व्हर-साइड (Netlify Functions द्वारे)

### आवश्यक एन्व्हायर्नमेंट व्हेरिएबल्स
| व्हेरिएबल | उद्देश | कुठे वापरले जाते |
