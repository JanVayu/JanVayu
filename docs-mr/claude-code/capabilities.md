# Claude Code सेटअप — संपूर्ण क्षमता संदर्भ

ही पृष्ठ JanVayu Claude Code सेटअपच्या सर्व क्षमतांची सविस्तर माहिती देते — यामध्ये डेव्हलपमेंट टूल्स, अंमलबजावणी यंत्रणा, AI वैशिष्ट्ये, CI/CD ऑटोमेशन, डिप्लॉयमेंट इन्फ्रास्ट्रक्चर आणि डॉक्युमेंटेशन वर्कफ्लो यांचा समावेश आहे.

---

## 1. मुख्य डेव्हलपमेंट क्षमता

### फाईल ऑपरेशन्स
- रिपॉझिटरीमधील **कोणतीही फाईल वाचणे** — `index.html`, Netlify Functions, कॉन्फिग्स, डॉक्युमेंटेशन
- **नवीन फाईल्स तयार करणे** — Netlify Functions, डॉक्युमेंटेशन पृष्ठे, कॉन्फिग फाईल्स
- **विद्यमान फाईल्स एडिट करणे** — असंबंधित कोड पुन्हा न लिहिता अचूक इनलाईन बदल
- **फाईलनेम पॅटर्नने शोधणे** — ग्लोब मॅचिंग (उदा., `**/*.mjs`, `docs/**/*.md`)
- **कंटेंटने शोधणे** — कोडबेसमध्ये regex-आधारित फुल-टेक्स्ट शोध

### शेल आणि टर्मिनल ॲक्सेस
- डिपेंडन्सीज व्यवस्थापित करण्यासाठी `npm install` रन करणे
- लोकल डेव्हलपमेंट सर्व्हरसाठी `netlify dev` रन करणे
- कोणतीही नॉन-डिस्ट्रक्टिव्ह शेल कमांड एक्झिक्युट करणे
- `git`, `gh` (GitHub CLI), `ls`, `mkdir` चा ॲक्सेस
- **परंपरेनुसार ब्लॉक केलेले**: `rm -rf`, `git push --force`, `git reset --hard`

### मल्टी-फाईल को-ऑर्डिनेशन
एकच Claude Code सेशन एकाच वेळी या सर्वांवर काम करू शकते:
- `index.html` (मार्कअप), `app.js` (लॉजिक) आणि `styles.css` (स्टायलिंग)
- Netlify Functions (`netlify/functions/*.mjs` किंवा `*.js`)
- कॉन्फिगरेशन फाईल्स (`netlify.toml`, `package.json`, `.editorconfig`)
- डॉक्युमेंटेशन (`docs/**/*.md`, `CHANGELOG.md`, `README.md`)
- Git hooks (`.githooks/pre-commit`, `.githooks/commit-msg`)
- GitHub workflows (`.github/workflows/*.yml`)

## 2. Git वर्कफ्लो क्षमता

### ब्रांचिंग आणि कमिट्स
- फीचर ब्रांचेस तयार करणे (उदा., `claude/feature-name`)
- विशिष्ट फाईल्स स्टेज करणे (अनावधानाने `.env` किंवा सिक्रेट्स समाविष्ट होणे टाळते)
- लागू केलेल्या प्रीफिक्स परंपरेनुसार मेसेजेससह कमिट करणे:
  - `Add:` — नवीन फीचर किंवा फाईल
  - `Fix:` — बग फिक्स
  - `Update:` — विद्यमान फीचरमधील सुधारणा
  - `Translate:` — भाषांतर कार्य
  - `Docs:` — डॉक्युमेंटेशन बदल
  - `Refactor:` — कोडची पुनर्रचना (वर्तनात बदल नाही)
  - `Test:` — टेस्ट ॲडिशन्स
  - `CI:` — CI/CD पाईपलाईन बदल
  - `Chore:` — देखभाल कार्ये
- 72 पेक्षा जास्त अक्षरे असलेल्या सब्जेक्ट लाईन्स हुकमधून वॉर्निंग ट्रिगर करतात (ब्लॉक नाही); `Merge` हा देखील एक परवानगी असलेला प्रीफिक्स आहे

### पुल रिक्वेस्ट मॅनेजमेंट
- स्ट्रक्चर्ड शीर्षक, सारांश आणि टेस्ट प्लॅनसह PRs तयार करणे
- मल्टी-PR वर्कफ्लो व्यवस्थापित करणे (उदा., आधी बॅकएंड, नंतर फ्रंटएंड, नंतर डॉक्युमेंट्स)
- PR डिफ्स रिव्ह्यू करणे आणि बदलांचे सुचवणे
- कमेंट्स जोडणे आणि रिव्ह्यू फीडबॅकला प्रतिसाद देणे
### Git Hook Enforcement
या सेटअपमध्ये दोन कस्टम git hooks समाविष्ट आहेत जे आपोआप रन होतात:

**Pre-commit hook** (`.githooks/pre-commit`):
| चेक | ॲक्शन |
|-------|--------|
| `.env`, `.env.local`, `.env.production` | **कमिट ब्लॉक करा** |
| `credentials.json`, `*.pem`, `*.key` | **कमिट ब्लॉक करा** |
| `debugger` स्टेटमेंट्स, `breakpoint()` | **कमिट ब्लॉक करा** |
| मर्ज कॉन्फ्लिक्ट मार्कर्स (`<<<<<<<`, `>>>>>>>`) | **कमिट ब्लॉक करा** |
| `console.log`, `console.debug`, `console.warn` | **चेतावणी** ( `// keep` वापरून बायपास करा) |
| 500 KB पेक्षा मोठ्या फाइल्स | **चेतावणी** |

**Commit message hook** (`.githooks/commit-msg`):
| चेक | ॲक्शन |
|-------|--------|
| आवश्यक प्रीफिक्स नसणे | **कमिट ब्लॉक करा** |
| सब्जेक्ट लाईन > 72 कॅरेक्टर्स | **चेतावणी** |
| मर्ज/रिव्हर्ट/फिक्सअप कमिट्स | **एन्फोर्समेंट स्किप करा** |

## 3. AI-Powered Features (Groq-hosted model)

> **अपडेट, 2 Oct 2026: Groq ने 16 Aug 2026 रोजी Llama 3.3 70B बंद केले (Groq deprecations page); आता फंक्शन्स बाय-डिफॉल्ट `openai/gpt-oss-120b` वर सेट होतात, जे `GROQ_MODEL` एन्व्हायर्नमेंट व्हेरिएबल वापरून बदलता येते.**

या सेटअपमध्ये चार प्रोडक्शन AI फीचर्स समाविष्ट आहेत, ज्यापैकी प्रत्येक Netlify Function म्हणून स्ट्रक्चर्ड स्किल फाइलसह इम्प्लिमेंट केले आहे:

### 3.1 Air Quality Assistant (`air-query.mjs`)
- **इनपुट**: शहराचे नाव + नैसर्गिक भाषेतील प्रश्न
- **आउटपुट**: अचूक उत्तर (सुमारे 150 शब्दांचे), ज्यामध्ये प्रत्यक्ष AQI नंबर दिले आहेत
- **भाषा**: इंग्रजी आणि नऊ भारतीय भाषा (हिंदी, तमिळ, बंगाली, मराठी, तेलुगू, गुजराती, कन्नड, मल्याळम, पंजाबी)
- **मुख्य मर्यादा**: यात खरा डेटा असणे आवश्यक आहे — कोणतेही सामान्य सल्ले नाही
- **फॉल-बॅक**: जर Groq वर रेट-लिमिट आले, तर हे रॉ AQI डेटा रिटर्न करते
- **स्किल फाइल**: `docs/skills/air-quality-assistant.md`

### 3.2 Health Advisory (`health-advisory.mjs`)
- **इनपुट**: शहर + वय + आरोग्याच्या समस्या + बाहेर घालवलेले तास
- **आउटपुट**: कलर-कोडेड रिस्क लेव्हल + ठोस शिफारसी (3-4 वाक्ये)
- **मुख्य मर्यादा**: थेट सल्ला, गोल-गोल बोलणे नाही — "घरातच राहा" असे सांगा, "घरात राहण्याचा विचार करा" असे नाही
- **प्री-AI स्टेप**: AI रिस्पॉन्स येण्यापूर्वीच JavaScript फंक्शन रिस्क लेव्हल कॅल्क्युलेट करून UI साठी कलर-कोडिंग करते
- **फॉल-बॅक**: AI चे स्पष्टीकरण फेल झाले तरी रिस्क लेव्हल दिसतेच
- **स्किल फाइल**: `docs/skills/health-advisory.md`
### 3.3 अकाउंटेबिलिटी ब्रीफ (`accountability-brief.mjs`)
- **इनपुट**: शहर + प्रभाग/भाग + कालावधी
- **आउटपुट**: आठ नामांकित विभागांसह (भाग, कालावधी, सध्याचे PM2.5, स्थिती, डेटा काय दर्शवतो, संभाव्य स्रोत, स्थानिक घटक काय करू शकतात, डेटाची मर्यादा) स्ट्रक्चर्ड ब्रीफ
- **कमाल आउटपुट**: 1,024 टोकन्स
- **प्रेक्षक**: प्रभाग नगरसेवक, स्थानिक पत्रकार, RWAs (निवासी कल्याण संस्था)
- **मुख्य वैशिष्ट्य**: विशिष्ट स्थानिक नियामक यंत्रणांचा (GRAP, RTI आणि महानगरपालिका तक्रार क्रमांक) समावेश
- **फॉल-बॅक**: AI विश्लेषणाशिवाय कच्चा डेटा परत करते
- **स्किल फाईल**: `docs/skills/accountability-brief.md`

### 3.4 ॲनोमली डिटेक्शन (`anomaly-check.mjs`)
- **इनपुट**: स्वयंचलित — दिल्ली, मुंबई, कोलकाता, चेन्नई, बेंगळुरूवर लक्ष ठेवते
- **थ्रेशोल्ड**: PM2.5 > 2× सीझनल बेसलाईन = ॲनोमली
- **आउटपुट**: प्रत्येक स्पाइकसाठी एक वाक्यातील स्पष्टीकरण
- **सीझनल बेसलाईन्स**: हार्डकोडेड अंदाजित JanVayu वर्किंग बेसलाईन्स, प्रकाशित CREA किंवा IQAir आकडेवारी नाही (डायनॅमिकली मोजले जात नाहीत)
- **फॉल-बॅक**: AI स्पष्टीकरणाशिवाय ॲनोमली फ्लॅग परत करते
- **स्किल फाईल**: `docs/skills/anomaly-explainer.md`

### सामायिक AI आर्किटेक्चर
सर्व चार वैशिष्ट्यांमध्ये हे सामायिक आहे:
- केवळ सर्व्हर-साईड एक्झिक्यूशन (क्लायंटला कोणतेही API कीज दाखवले जात नाहीत)
- CORS प्रीफ्लाइट हँडलिंग (OPTIONS → 204)
- योग्य स्टेटस कोड्ससह JSON रिस्पॉन्स
- प्रत्येक बाह्य कॉलवर try/catch
- ग्रेसफुल डिग्रेडेशन — प्रत्येक AI वैशिष्ट्यामध्ये नॉन-AI फॉल-बॅक आहे

## 4. Netlify फंक्शन्स (28 सर्व्हरलेस हँडलर्स)

| फंक्शन | उद्देश |
|----------|---------|

### स्टँडर्ड फंक्शन पॅटर्न
प्रत्येक फंक्शन या टेम्पलेटचे पालन करते:
1. CORS प्रीफ्लाइट हँडलिंग (`OPTIONS` → `204`)
2. `try/catch` मध्ये गुंडाळलेले मुख्य लॉजिक
3. CORS हेडर्ससह JSON रिस्पॉन्स बॉडी
4. एरर आल्यास ग्रेसफुल फॉलबॅक (रिकाम्या बॉडीसह कधीही `500` रिटर्न करत नाही)

## 5. CI/CD आणि ऑटोमेशन

### GitHub Actions वर्कफ्लोज

**लिंक चेकिंग** (`ci.yml`):
- **ट्रिगर्स**: `main` वर पुश, `main` वर PRs
- **टूल**: Lychee लिंक चेकर
- **वगळलेले**: localhost, सोशल मीडिया प्लॅटफॉर्म्स, रेट-लिमिटेड डोमेन्स, आणि `docs/` व `docs-*/` डिरेक्टरीज
- **कॉन्फिग**: 30-सेकंदांचा टाइमआउट, प्रत्येक लिंकसाठी 2 रिट्राय

**ट्रान्सलेशन सिंक** (`translations.yml`):
- **ट्रिगर्स**: `docs/`, `docs-hi/`, `docs-bn/`, `docs-mr/`, `docs-ta/` मधील बदल
- **चेक्स**: 4 भाषांमधील ट्रान्सलेशन फाईल कव्हरेज, SUMMARY.md ची समानता, जुन्या ट्रान्सलेशनचा शोध
- **रिपोर्ट्स**: प्रत्येक भाषेनुसार कव्हरेज टक्केवारी

**ImpactMojo ट्रान्सलेशन सिंक** (`impactmojo-translations.yml`):
- `docs-impactmojo/` डिरेक्टरीजसाठी वरीलप्रमाणेच लॉजिक

**Dependabot** (`dependabot.yml`):
- **स्कोप**: GitHub Actions डिपेंडन्सीज आणि npm (npm 2 ऑक्टोबर 2026 रोजी जोडले)
- **वारंवारता**: मासिक
- **जास्तीत जास्त ओपन PRs**: प्रति इकोसिस्टम 2; npm मायनर आणि पॅच अपडेट्स एकत्र केले जातात

### Netlify ऑटो-डिप्लॉय

- फंक्शन्स डिरेक्टरी: `netlify/functions/`
- Node.js 22 रनटाइम (`netlify.toml` मधील `NODE_VERSION`)

|--------|-------|---------|

| `X-Content-Type-Options` | `nosniff` | MIME स्निफिंगला प्रतिबंध करते |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | रेफरर माहिती नियंत्रित करते |

### कॅशिंग — Netlify Blobs
- स्ट्रॉंग कन्सिस्टन्सी मॉडेल
- शेड्युल्ड फंक्शन्सद्वारे सोशल फीड्स आणि बातम्या प्री-कॅश करण्यासाठी वापरले जाते
- ऑन-डिमांड फंक्शन्स आधी कॅशमधून वाचतात, आणि आवश्यक असल्यास लाईव्ह डेटा आणतात
- `@netlify/blobs` पॅकेजद्वारे ॲक्सेस केले जाते

### ईमेल — Resend API
- डेली डायजेस्ट (`daily-digest.mjs`) आणि इतर सर्व्हर-साइड मेलर्स (`health-monitor.mjs`, `terra-collab.mjs`, `workshop-submit.mjs`) साठी ईमेल डिलिव्हरी; `subscribe.js` ईमेल पाठवत नाही
- फक्त सर्व्हर-साइड (Netlify Functions द्वारे)

### आवश्यक एन्व्हायर्नमेंट व्हेरिएबल्स
| व्हेरिएबल | उद्देश | कुठे वापरले जाते |
|----------|---------|------------|
| `GROQ_API_KEY` | Groq-होस्टेड AI फीचर्स (पर्यायी `GROQ_MODEL` द्वारे मॉडेल सेट केले जाते, डिफॉल्ट `openai/gpt-oss-120b`) | `air-query.mjs`, `health-advisory.mjs`, `accountability-brief.mjs`, `anomaly-check.mjs` |

| `RESEND_FROM` | पाठवणाऱ्याचा ईमेल ॲड्रेस | `daily-digest.mjs` |
| `BLOB_TOKEN` | Netlify Blobs ॲक्सेस | `blob-store.js` (कॅशिंग फंक्शन्सद्वारे इम्पोर्ट केलेले) |
| `NETLIFY_SITE_ID` | साईट आयडेंटिफायर | Blobs स्टोअर इनिशियलायझेशन |
| `WAQI_TOKEN` | हवेच्या गुणवत्तेचा डेटा (सर्व्हर-साइड, सार्वजनिक नाही) | `waqi-proxy` आणि फंक्शन्स, `netlify/functions/lib/waqi-token.mjs` द्वारे |
