# Claude Code डेव्हलपमेंट वर्कफ्लो

या पेजवर JanVayu बनवण्यासाठी Claude Code ची रोजची वर्कफ्लो दिली आहे — फीचर डेव्हलपमेंटपासून ते बग फिक्स आणि डॉक्युमेंटेशनपर्यंत.

---

## फीचर डेव्हलपमेंट वर्कफ्लो

### पायरी 1: फीचर ठरवा

स्पष्ट आणि मर्यादा लक्षात ठेवून केलेल्या वर्णनाने सुरुवात करा:

```
> वॉर्ड-लेव्हल अकाउंटेबिलिटी ब्रीफ फीचर ॲड करा.
> हे एक Netlify Function (ES module, .mjs) असावे जे:
> - इनपुट म्हणून शहराचे नाव घेईल
> - WAQI कडून लाईव्ह AQI आणेल
> - स्ट्रक्चर्ड प्रॉम्प्टसह Groq-होस्टेड मॉडेलला डेटा पाठवेल
> - खालील गोष्टींसह एक ब्रीफ रिटर्न करेल: सध्याची स्थिती, NCAP टार्गेट्स, 5 अकाउंटेबिलिटी प्रश्न
> - Groq वर रेट-लिमिट असल्यास फॉलबॅक असावा
> सध्याच्या पॅटर्ननुसार index.html मध्ये UI सेक्शन देखील ॲड करा.
```

### पायरी 2: Claude एक्सप्लोर करते

Claude Code वाचते:
- `index.html` — सध्याचे UI पॅटर्न, CSS व्हेरिएबल्स, JS पद्धती
- सध्याचे Netlify Functions — कोड स्टाईल, CORS हँडलिंग, एरर पॅटर्न
- `package.json` — उपलब्ध डिपेंडन्सीज
- `netlify.toml` — डिप्लॉयमेंट कॉन्फिगरेशन

### पायरी 3: Claude इम्प्लिमेंट करते

Claude फाईल्स तयार/बदलते:
1. `netlify/functions/accountability-brief.mjs` — सर्व्हरलेस फंक्शन
2. `index.html` — नवीन HTML सेक्शन, CSS स्टाईल्स, JS फेच लॉजिक

### पायरी 4: रिव्ह्यू आणि इटरेट करा

```
> ब्रीफ खूप लांब आहे. मॉडेल आउटपुट 1,024 टोकन्सपर्यंत (max_tokens) मर्यादित ठेवा.
> ब्रीफ जनरेट होत असताना लोडिंग स्पिनर देखील ॲड करा.
```

Claude इतर कोड न बदलता आवश्यक ते बदल करते.

### पायरी 5: कमिट आणि PR

```
> हे "Add ward-level accountability brief feature" मेसेजसह कमिट करा
> आणि PR तयार करा
```

Claude `git add`, `git commit`, `git push`, आणि `gh pr create` रन करते.

## बग फिक्स वर्कफ्लो

```
> WAQI डाऊन असताना anomaly-check फंक्शन 500 रिटर्न करते.
> कॅश केलेल्या डेटावर आधारित ॲनोमली फ्लॅगसह त्याने 200 रिटर्न केले पाहिजे.
```

Claude Code:
1. `anomaly-check.mjs` वाचते
2. हँडल न केलेला एरर पाथ ओळखते
3. कॅश केलेल्या डेटाच्या फॉलबॅकसह try/catch ॲड करते
4. फिक्स कमिट करते

**मुख्य तत्त्व:** Claude ला *किमान बदल* करण्याचे निर्देश दिले जातात — संपूर्ण फंक्शनचे रिफॅक्टरिंग करायचे नाही.

## डॉक्युमेंटेशन वर्कफ्लो

```
> JanVayu साठी टेक स्टॅक,
> Claude Code सेटअप आणि AI फीचर्स कव्हर करणारे Docsify डॉक्युमेंटेशन तयार करा. एक SUMMARY.md समाविष्ट करा.
```

Claude Code:
1. सर्व सध्याचे डॉक्स, कॉन्फिग्स आणि सोर्स कोड वाचते
2. डिरेक्टरी स्ट्रक्चर तयार करते
3. अचूक आणि कोड-रेफरन्स असलेल्या कंटेंटसह प्रत्येक पेज लिहिते
4. प्रत्येक भाषेसाठी `SUMMARY.md` आणि Docsify `_sidebar.md` अपडेट करते

## बदल नोंद (Changelog) आणि रिलीज वर्कफ्लो

```
> नवीन AI फीचर्ससाठी v25.1 बदल नोंद (changelog entry) जोडा.
> सध्याच्या CHANGELOG.md फॉरमॅटचे पालन करा.
```

Claude:
1. फॉरमॅट समजण्यासाठी सध्याची CHANGELOG.md वाचते
2. सर्व नवीन फीचर्स (functions, UI sections) वाचते
3. एक सविस्तर बदल नोंद (changelog entry) लिहिते
4. अपडेटसह एक PR तयार करते

## मल्टी-PR वर्कफ्लो

मोठ्या फीचर्ससाठी, Claude Code अनेक PRs हाताळते:

```
PR #1: AI इंटिग्रेशन जोडा (फक्त functions; v25.1 ला Gemini 2.5 Flash वर लाँच केले आणि नंतर Groq वर हलवले)
PR #2: AI फीचर्ससाठी फ्रंटएंड UI जोडा
PR #3: CHANGELOG आणि व्हर्जन हिस्ट्री अपडेट करा
PR #4: About सेक्शनमधील व्हर्जन लाईन अपडेट करा
```

प्रत्येक PR स्वयंपूर्ण, रिव्ह्यू करण्यायोग्य आणि स्वतंत्रपणे मर्ज करण्यायोग्य आहे.

## प्रभावीपणे काम करणारे प्रॉम्प्ट पॅटर्न

### नवीन फीचर्ससाठी

```
[feature] जोडा. आवश्यकता:
- [Constraint 1]
- [Constraint 2]
[reference file] मधील सध्याच्या पॅटर्नचे पालन करा.
कोणत्याही सध्याच्या कार्यक्षमतेत बदल करू नका.
```

### बग फिक्सेससाठी

```
[condition] असताना [Function] हे [error] देते.
अपेक्षित: [correct behaviour].
हे ठीक करण्यासाठी कमीत कमी बदल करा.
आजूबाजूच्या कोडचे रिफॅक्टरिंग करू नका.
```

### डॉक्युमेंटेशनसाठी

```
[topic] साठी डॉक्युमेंटेशन तयार करा.
समाविष्ट करा: [specific sections].
रिपॉझिटरीमधील प्रत्यक्ष कोड आणि कॉन्फिगरेशनचा संदर्भ द्या.
[existing doc file] सारखाच टोन वापरा.
```

### कोड रिव्ह्यूसाठी

```
खालील गोष्टींसाठी [file] चा रिव्ह्यू करा:
- सिक्युरिटी इश्यूज (विशेषतः API key एक्सपोजर)
- CORS हँडलिंग
- एरर रिकव्हरी
- ॲक्सेसिबिलिटी
लाईन रेफरन्ससह विशिष्ट इश्यूजची यादी करा.
```

## हा वर्कफ्लो प्रभावी का आहे

1. **संपूर्ण कोडबेस संदर्भ** — Claude कोड लिहिण्यापूर्वी तुमचा कोड वाचते
2. **कन्स्ट्रेंट-फर्स्ट प्रॉम्प्ट्स** — Claude ला काय *नको* ते सांगल्याने फ्रेमवर्क फुगणे टळते
3. **इटरेटिव्ह रिफायनमेंट** — एकाच सेशनमध्ये रिव्ह्यू, ॲडजस्ट आणि कमिट
4. **Git-नेटिव्ह** — ब्रांचेस, कमिट्स, PRs एकाच टूलमध्ये होतात
5. **मल्टी-फाईल को-ऑर्डिनेशन** — एकाच प्रॉम्प्टमध्ये functions, HTML, CSS, JS आणि डॉक्स हाताळता येतात
6. **रिप्रॉड्युसिबल** — प्रत्येक सेशनचे काम स्पष्ट मेसेजेससह git मध्ये कमिट केले जाते
