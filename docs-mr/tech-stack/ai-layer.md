# AI लेयर — Groq द्वारे OpenAI gpt-oss-120B

JanVayu ची AI वैशिष्ट्ये **OpenAI gpt-oss-120B** द्वारे चालवली जातात, जे Netlify Functions मधून **Groq API** (OpenAI-compatible REST API) द्वारे सर्व्ह केले जाणारे एक ओपन-सोर्स LLM आहे.

---

## Groq द्वारे OpenAI gpt-oss-120B का?

| निकष | निवड |
|-----------|--------|
| **खर्च** | Groq Console; प्लॅन आणि बिलिंग खात्यावर सेट केले जाते |
| **वेग** | Groq च्या होस्टेड इन्फरन्स सर्व्हिसवरून सर्व्ह केले जाते (लॅटेन्सी येथे मोजली जात नाही) |
| **रेट लिमिट्स** | खालील टेबलमधील बेस लिमिट्स |
| **बहुभाषिक** | मजबूत हिंदी सपोर्ट (JanVayu च्या प्रेक्षकांसाठी महत्त्वाचे) |
| **गुणवत्ता** | डेटा-आधारित तथ्यात्मक प्रतिसादांसाठी पुरेसे (क्रिएटिव्ह रायटिंगसाठी नाही) |
| **ओपन सोर्स** | OpenAI gpt-oss-120B हे एक ओपन मॉडेल आहे (OpenAI), जे पारदर्शकता आणि पुनरुत्पादनक्षमता सुनिश्चित करते |

### स्वीकारलेले ट्रेड-ऑफ्स

- **GPT-4 / Claude नाही** — JanVayu Groq द्वारे सर्व्ह केलेले ओपन-वेट मॉडेल वापरते, जे खर्च आणि वेगासाठी निवडले आहे.
- **आउटपुट टोकन कॅप** — आउटपुट प्रति फंक्शन 512 ते 1,024 `max_tokens` पर्यंत मर्यादित आहे (air-query 700, accountability-brief 1,024, health-advisory 768, anomaly-check 512). रिझनिंग मॉडेल्स या कॅपचा काही भाग रिझनिंगवर खर्च करतात, त्यामुळे हा कॅप संपूर्ण प्रतिसादाला मर्यादित करतो, केवळ दृश्यमान मजकुराला नाही.
- **फायन-ट्युनिंग नाही** — फक्त प्रॉम्प्ट इंजिनिअरिंग. प्रत्येक स्किल एक सिस्टीम प्रॉम्प्ट आहे, फायन-ट्युन केलेले मॉडेल नाही.

## इंटिग्रेशन आर्किटेक्चर

```
Browser (client)
    │
    │ POST /.netlify/functions/air-query
    │ POST /.netlify/functions/health-advisory
    │ POST /.netlify/functions/accountability-brief
    │ GET  /.netlify/functions/anomaly-check
    │
    ▼
Netlify Function (server-side)
    │
    │ 1. Parse user input
    │ 2. Fetch live AQI data from WAQI
    │ 3. Construct prompt with real data
    │ 4. Call Groq API
    │ 5. Return response (or fallback to raw data)
    │
    ▼
Groq API
    │
    │ openai/gpt-oss-120b model
    │ max_tokens: 512-1,024 (per function)
    │
    ▼
Structured response → Browser
```

**मुख्य सुरक्षा तत्त्व:** `GROQ_API_KEY` कधीही क्लायंटच्या संपर्कात येत नाही. सर्व AI कॉल्स Netlify Functions द्वारे सर्व्हर-साइडवर केले जातात.

## चार AI वैशिष्ट्ये

### 1. Ask JanVayu (`air-query.mjs`)
- **इनपुट:** शहराचे नाव + मुक्त-मजकूर प्रश्न
- **इंजेक्ट केलेला संदर्भ:** WAQI कडून लाइव्ह PM2.5 आणि AQI
- **आउटपुट:** वास्तविक वाचनावर आधारित
- **भाषा:** प्रश्नाच्या भाषेत उत्तरे; Ask JanVayu UI 10 भाषांमध्ये उपलब्ध आहे
- **फॉलबॅक:** जर Groq ला रेट-लिमिट असेल तर रॉ AQI डेटा परत करतो
### 2. हेल्थ ॲडव्हायझरी (`health-advisory.mjs`)
- **इनपुट:** शहर + वय + आरोग्याच्या समस्या + बाहेर घालवलेले तास
- **इंजेक्ट केलेला संदर्भ:** त्या शहराचा लाईव्ह AQI
- **आउटपुट:** रंगानुसार रिस्क लेव्हल + ठोस शिफारसी
- **फॉल-बॅक:** सामान्य WHO-मार्गदर्शक तत्त्वांचा सल्ला

### 3. अकाउंटेबिलिटी ब्रीफ (`accountability-brief.mjs`)
- **इनपुट:** शहराचे नाव
- **इंजेक्ट केलेला संदर्भ:** लाईव्ह AQI + हंगामी बेसलाईन्स + GRAP टप्पे
- **आउटपुट:** स्ट्रक्चर्ड ब्रीफ (सध्याची स्थिती, NCAP उद्दिष्टे, 5 अकाउंटेबिलिटी प्रश्न)
- **कमाल टोकन्स:** 1,024
- **फॉल-बॅक:** रॉ डेटा टेबल रिटर्न करते

### 4. अ‍ॅनोमली डिटेक्शन (`anomaly-check.mjs`)
- **इनपुट:** काहीही नाही (5 मेट्रो शहरांवर आपोआप लक्ष ठेवते)
- **थ्रेशोल्ड:** 2× हंगामी बेसलाईन = अ‍ॅनोमली
- **आउटपुट:** प्रत्येक अ‍ॅनोमलीसाठी एक वाक्याचे AI स्पष्टीकरण
- **कॅशे:** 10-मिनिटांचे HTTP `Cache-Control` हेडर (Netlify Blobs नाही)
- **फॉल-बॅक:** AI स्पष्टीकरणाशिवाय अ‍ॅनोमली फ्लॅग रिटर्न करते

## रेट लिमिटिंग स्ट्रॅटेजी

Groq च्या प्रकाशित बेस लिमिट्स (बदलण्यायोग्य; अकाउंटच्या स्वतःच्या प्लॅनवरील लिमिट्ससाठी [console.groq.com](https://console.groq.com) तपासा):

| लिमिट | मूल्य (openai/gpt-oss-120b, Groq ने प्रकाशित केलेल्या बेस लिमिट्स, 25 ऑक्टोबर 2026 रोजी तपासले) |
|-------|------------------------------------------------------------------------------------------------|
| प्रति मिनिट रिक्वेस्ट्स | 30 |
| प्रति दिवस रिक्वेस्ट्स | 1,000 |
| प्रति मिनिट टोकन्स | 8,000 |
| प्रति दिवस टोकन्स | 200,000 |

स्रोत: [Groq रेट लिमिट्स](https://console.groq.com/docs/rate-limits). लांब एअर-क्वेरी सिस्टीम प्रॉम्प्टमुळे 8,000 टोकन्स-प्रति-मिनिट लिमिट कडक आहे, त्यामुळे 429 रिस्पॉन्सवर लक्ष ठेवणे महत्त्वाचे आहे.

JanVayu हे बजेट फीचर्समध्ये विभागते (अंदाजे आकडेवारी, Netlify लॉग्सवरून मोजलेले नाही):
- अ‍ॅनोमली चेक: ~144/दिवस (कॅश केलेले, पेज लोड झाल्यावर चालते)
- एअर क्वेरी: ~50/दिवस (वापरकर्त्याद्वारे सुरू केलेले)
- हेल्थ ॲडव्हायझरी: ~30/दिवस (वापरकर्त्याद्वारे सुरू केलेले)
- अकाउंटेबिलिटी ब्रीफ: ~20/दिवस (वापरकर्त्याद्वारे सुरू केलेले)

जर लिमिट्स संपले, तर प्रत्येक फंक्शन व्यवस्थितपणे रॉ डेटावर फॉल-बॅक होते. वापरकर्त्याला नेहमी रिस्पॉन्स मिळतो — फक्त AI विश्लेषणाशिवाय.

## प्रॉम्प्ट इंजिनिअरिंग

सर्व प्रॉम्प्ट्स या तत्त्वांचे पालन करतात:

1. **नेहमी रिअल डेटा इंजेक्ट करा** — मॉडेल कधीही मेमरीमधून जनरेट करत नाही
2. **नेमके आउटपुट फॉरमॅट सांगा** — विशेषतः स्ट्रक्चर्ड ब्रीफ्ससाठी
3. **शब्दांची मर्यादा ठरवा** — प्रत्येक प्रॉम्प्टमध्ये स्पष्ट मर्यादा
4. **फेल्युअर मोड्सची नावे द्या** — "सामान्य सल्ला देऊ नका", "गोष्टी गोलमाल सांगू नका"
5. **बहुभाषिक सूचना** — "प्रश्नाच्या भाषेत उत्तर द्या"
6. **ग्रेसफुल डिग्रेडेशन** — प्रत्येक फंक्शनचा एक नॉन-AI फॉल-बॅक मार्ग असतो
संपूर्ण प्रॉम्प्ट डॉक्युमेंटेशनसाठी [Skills & AI Prompts](../skills/README.md) विभाग पहा.
