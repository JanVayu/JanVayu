# फ्रंटएंड स्टॅक

## HTML/CSS/JavaScript (Vanilla)

फ्रंटएंड हे व्हॅनिला HTML, CSS आणि JavaScript आहे ज्यामध्ये कोणतीही बिल्ड स्टेप आणि बंडलर नाही. हे **एकच फाईल नाही**, आणि या पेजवर बऱ्याच काळापासून तेच म्हटले जात होते ज्यामुळे कोणाचीही दिशाभूल होऊ शकते: `index.html` सुमारे 6,600 ओळींची आहे, `styles.css` सुमारे 3,700 ची, `app.js` सुमारे 10,000 ची, आणि `panels/` मध्ये 19 पॅनेल फ्रॅगमेंट्स आहेत जे रनटाइमला पेजमध्ये लोड केले जातात.

### याची रचना

| फाईल | ती काय आहे |
|---|---|
| `index.html` | सिंगल-पेज ॲप: बार, पॅनेल कंटेनर, आणि फर्स्ट पेंटसाठी `styles.css` चा इनलाइन **क्रिटिकल-CSS** सबसेट |
| `styles.css` | डिझाईन सिस्टीम. प्रत्येक टोकन, दोन्ही थीम्स, आणि शेअर्ड कंपोनंट्स (`.bar`, `.ctl`, `.card`, `.container`) |
| `app.js` | पॅनेल राउटिंग, डेटा फेचिंग, चार्ट्स, रोल आणि लँग्वेज मशिनरी |
| `js/chrome.js` | थीम प्रेफरन्स आणि SPA नसलेल्या पेजेससाठी एक कट-डाऊन बार |
| `panels/*.html` | `index.html` मध्ये इंजेक्ट केलेले फ्रॅगमेंट्स; ते त्याचे स्टायलिंग इनहेरिट करतात |
| 18 स्टँडअलोन पेजेस | `/pm25/`, `/try.html`, `/docs/`, `/blog/`, `/ask/`, वॉकथ्रू, एम्बेड्स, आणि बाकीचे |

**सर्व 19 स्टँडअलोन डॉक्युमेंट्स `styles.css` लोड करतात.** 2026-09-22 पर्यंत हे खरे नव्हते: प्रत्येकामध्ये एक प्रायव्हेट `<style>` ब्लॉक होता जो त्याच टोकन नावांना फिक्स्ड लाईट-थीम लिटरल्ससह पुन्हा डिफाईन करत असे, त्यामुळे टोकनमधील बदल एका पेजवर दिसायचा आणि इतर कोणत्याही पेजला थीम कंट्रोलचे पालन व्हायचे नाही.
`scripts/check-design-system.py` अशा पेजला फेल करते जे पुन्हा ड्रॉप आऊट होते.

### बिल्ड स्टेप का नाही

1. **बिल्ड स्टेप नाही** — रिपो हा डिप्लॉय आर्टिफॅक्ट आहे
2. **योगदानकर्त्यांसाठी सोपे** — `python3 -m http.server` हे संपूर्ण डेव्ह सेटअप आहे
3. **सोर्स आणि आउटपुटमध्ये काहीही जुने होत नाही**

याची किंमत म्हणजे कॅशे-बस्टिंग मॅन्युअल आहे. `/styles.css` आणि `/app.js` ची रिक्वेस्ट `package.json` मधील व्हर्जनवरून घेतलेल्या `?v=<stamp>` क्वेरीसह केली जाते, कारण `sw.js` सेम-ओरिजिन ॲसेट्स **कोणत्याही रि-व्हॅलिडेशनशिवाय कॅशे-फर्स्ट** सर्व्ह करते. दोन गार्ड्स हे एकत्र ठेवतात: `check-asset-stamps.py` (प्रत्येक स्टॅम्प केलेल्या URL वर सध्याचा स्टॅम्प असतो) आणि `check-asset-freshness.py` (व्हर्जन स्थिर असताना कोणताही स्टॅम्प केलेली फाईल बदलत नाही). दुसरा अस्तित्वात आहे कारण पहिल्याने पास केले तर `app.js` न बदललेल्या URL अंतर्गत बदलला.

### CSS आर्किटेक्चर
- **कस्टम प्रॉपर्टीजचे तीन स्तर.** एक रॉ रॅम्प (`--w-0`…`--w-900` प्रकाशासाठी वॉर्म न्यूट्रल्स, `--d-950`…`--d-50` गडद रंगासाठी), एक सिमेंटिक स्तर जो त्याच्याकडे निर्देशित करतो, आणि असे घटक जे फक्त सिमेंटिक स्तराचा संदर्भ देतात.
- **कोणताही प्रीप्रोसेसर नाही** (Sass, Less, किंवा PostCSS नाही)
- मीडिया क्वेरीजसह **मोबाईल-फर्स्ट** रिस्पॉन्सिव्ह डिझाइन
- **WCAG AA** कॉन्ट्रास्ट, दोन्ही थीम्समधील प्रत्येक पॅनेल आणि प्रत्येक पेजवरील Playwright स्वीपद्वारे CI मध्ये गेट केलेले

सिमेंटिक स्तर, ज्याच्या आधारे तुम्ही कोडिंग केले पाहिजे:

```css
:root {
  --bg: var(--paper);          /* the page */
  --bg-section: var(--warm-white);
  --bg-card: var(--w-0);
  --text: var(--ink);
  --text-2: var(--ink-secondary);
  --text-3: var(--ink-tertiary);
  --accent: var(--green-700);
  --border: var(--w-300);
}

[data-theme="dark"] {
  --bg: var(--d-950);
  --bg-section: var(--d-900);
  --bg-card: var(--d-850);
  --text: var(--d-50);
  --accent: #4ADE80;
  --border: var(--d-700);
}
```

यांच्यासोबत इंक टोकन्स आहेत — `--ink-red`, `--ink-blue`, `--ink-teal` आणि इतर — जे अस्तित्वात आहेत कारण पांढऱ्या रंगावर मजकूर म्हणून वाचला जाणारा सॅच्युरेटेड रंग `#0e0e0c` वर मजकूर म्हणून वाचला जात नाही. JavaScript मध्ये किंवा `style=` ॲट्रिब्यूटमध्ये लिटरल्स म्हणून लिहिलेला रंग तो कोणत्या थीममध्ये आला आहे हे जाणून घेऊ शकत नाही, त्यामुळे त्याला एक टोकन मिळतो आणि CSS फ्लिपिंगचे काम करते.

### थीमिंग

`<html>` वर `data-theme="dark"`, जे `js/chrome.js` द्वारे सेट केले जाते आणि `janvayu-theme` अंतर्गत स्टोअर केले जाते. प्रत्येक पेजमध्ये `<head>` मध्ये एक लहान इनलाइन स्क्रिप्ट असते जी पहिल्या पेंटपूर्वी स्टोअर केलेली व्हॅल्यू लागू करते, जेणेकरून पेज कधीही आधी लाईट पेंट होत नाही आणि नंतर फ्लिप होत नाही. `prefers-color-scheme` ब्लॉक जोडू नका: चार पेजेसमध्ये आधी असा एक ब्लॉक होता, ज्याचा अर्थ असा होता की ते ऑपरेटिंग सिस्टीमचे पालन करत होते आणि साइटच्या स्वतःच्या नियंत्रणाकडे दुर्लक्ष करत होते.

### JavaScript पॅटर्न

- **ES2020** — ब्राउझर सुसंगतता राखण्यासाठी कोणतेही नवीन फीचर्स नाहीत
- सर्व HTTP कॉल्ससाठी **Fetch API** (axios नाही)
- `document.getElementById` / `querySelector` द्वारे **DOM मॅनिप्युलेशन**
- **कोणताही मॉड्यूल बंडलर नाही** — सर्व JS `<script>` टॅग्समध्ये आहे
- लाईव्ह AQI डेटासाठी **10-मिनिटांचे ऑटो-रिफ्रेश**

## Chart.js

**व्हर्जन:** पिन्ड 4.x (4.4.7), SRI सह jsDelivr वरून लोड केलेले आणि लेझी-लोडेड
**यासाठी वापरले जाते:**
- मेट्रो विरुद्ध प्रादेशिक AQI तुलना बार चार्ट्स
- PM2.5 ट्रेंड लाईन्स
- हेल्थ इम्पॅक्ट डेटा व्हिज्युअलायझेशन्स
- सीझनल बेसलाईन तुलना

**Chart.js का:**
- लहान फूटप्रिंट (~70 KB gzipped, ~60 KB Brotli)
- बिल्ड स्टेपशिवाय काम करते (CDN स्क्रिप्ट टॅग)
- कॅनव्हास-आधारित रेंडरिंग (मोबाईलवर परफॉर्मंट)
- इन-बिल्ट रिस्पॉन्सिव्ह/अॅक्सेसिबिलिटी फीचर्स
## Leaflet.js + OpenStreetMap

**आवृत्ती:** 1.9.4, unpkg वरून SRI सह लोड केले
**यासाठी वापरले:**
- AQI स्टेशन मार्कर्ससह १६० शहरांचा (१५७ भारतीय, तसेच बीजिंग, लंडन आणि सिंगापूर) इंटरॅक्टिव्ह नकाशा
- AQI तीव्रतेनुसार रंग-कोडित मार्कर्स (हिरवा/पिवळा/नारंगी/लाल/जांभळा)
- स्टेशनचे तपशील पाहण्यासाठी क्लिक करा

**Leaflet + OSM का:**
- विनामूल्य आणि ओपन सोर्स (Google Maps API की ची आवश्यकता नाही)
- हलके (~40 KB gzipped)
- OpenStreetMap डेटा विनामूल्य आहे, परंतु त्याचे टाइल सर्व्हर्स बेस्ट-एफर्ट आणि धोरणात्मक मर्यादा असलेले आहेत ([वापर धोरण](https://operations.osmfoundation.org/policies/tiles/)); जास्त वापरासाठी व्यावसायिक किंवा स्वयंपोहोस्टेड टाइल स्त्रोत आवश्यक आहे. साइट Carto बेसमॅप टाइल्स देखील वापरते

## बहुभाषिक समर्थन

JanVayu क्लायंट-साइड लँग्वेज टॉगलद्वारे ५ भाषांना समर्थन देते:

| भाषा | कोड |
|----------|------|
| इंग्रजी | `en` |
| हिंदी | `hi` |
| तमिळ | `ta` |
| मराठी | `mr` |
| बंगाली | `bn` |

**अंमलबजावणी:** भाषा स्ट्रिंग्स JS ऑब्जेक्ट्स म्हणून साठवल्या जातात आणि टॉगल केल्यावर DOM घटकांमध्ये बदलल्या जातात. कोणतीही i18n लायब्ररी नाही — फक्त एक साधा की-व्हॅल्यू लूकअप.
