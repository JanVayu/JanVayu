# Skill: Anomaly Explainer

**Used in:** `netlify/functions/anomaly-check.mjs`  
**Model:** `openai/gpt-oss-120b` via Groq (default, set by `GROQ_MODEL`; 16 Aug 2026 रोजी Groq ने ते बंद करेपर्यंत Llama 3.3 70B)  
**Trigger:** मागणीनुसार चालवले जाते; पाच प्रमुख शहरांची हंगामी बेसलाइन्सशी तपासणी करते

---

## हे Skill काय करते

पाच प्रमुख शहरांमधील PM2.5 ची वाढ ओळखण्यासाठी, हे लाईव्ह रीडिंग्सची तुलना हार्डकोडेड हंगामी बेसलाइन्सशी करते. जेव्हा वाढ ओळखली जाते (रीडिंग > 2× बेसलाइन), तेव्हा ते Groq-होस्टेड मॉडेलला एकाच, भारत-विशिष्ट वाक्यात सर्वात संभाव्य कारण स्पष्ट करण्यास सांगते.

चारही स्किल फाइल्सपैकी हे सर्वात मर्यादित आहे — एक वाक्य, एक कारण, आणि जास्तीत जास्त विशिष्टता.

---

## System Prompt (प्रत्येक शहरासाठी, अचूक)

```
In one sentence, explain why PM2.5 in {city} might be {pm25} µg/m³ right now 
— {month}, {hour}. Give the most likely cause. Be specific to the Indian context.
```

टीप: हे **user message** म्हणून पाठवले जाते, system instruction म्हणून नाही. आउटपुट हे स्पष्ट तथ्यात्मक रचनेसह एकच वाक्य असल्यामुळे, user-turn प्रॉम्प्ट पुरेसा आहे — पूर्ण system instruction मुळे कोणताही फायदा न होता अतिरिक्त ओव्हरहेड वाढेल.

---

## Spike Detection Logic (AI च्या आधी)

```javascript
const ratio = d.pm25 / baseline;
if (ratio > 2) {
  // flag as spike, then explain via Groq
}
```

थ्रेशोल्ड: **हंगामी बेसलाइनच्या 2×** (कोणतीही निश्चित संख्या नाही). हे महत्त्वाचे आहे कारण:
- दिल्लीची हिवाळी बेसलाइन ~95 µg/m³ आहे — जानेवारीत 120 µg/m³ चे रीडिंग विसंगत नाही
- मुंबईची बेसलाइन ~45 µg/m³ आहे — तिथे 120 µg/m³ हे अत्यंत विसंगत आहे
- निश्चित थ्रेशोल्ड (उदा. "150 µg/m³ पेक्षा जास्त असल्यास फ्लॅग करा") वापरल्यास फॉल्स पॉझिटिव्ह (दिल्लीचा हिवाळा) आणि फॉल्स निगेटिव्ह (किनारी शहरे) दोन्ही मिळतील

**हंगामी बेसलाइन्स (अंदाजे JanVayu वर्किंग बेसलाइन्स, प्रकाशित CREA किंवा IQAir आकडेवारी नाही):**

| City | Oct–Mar (Winter) | Apr–Sep (Summer/Monsoon) |
|------|-----------------|--------------------------|
| Delhi | 95 µg/m³ | 55 µg/m³ |
| Mumbai | 45 µg/m³ | 45 µg/m³ |
| Kolkata | 80 µg/m³ | 35 µg/m³ |
| Chennai | 40 µg/m³ | 40 µg/m³ |
| Bengaluru | 40 µg/m³ | 40 µg/m³ |

## महत्त्वाचे डिझाईन निर्णय

**एकच वाक्य का?**
अनोमलीचे स्पष्टीकरण UI मध्ये टूलटिप किंवा इनलाइन ॲनोटेशन म्हणून दिसते. वापरकर्त्याच्या फ्लोमध्ये व्यत्यय न आणता वाचता येईल एवढे जास्तीत जास्त एकच वाक्य असू शकते. यापेक्षा जास्त मजकूर असल्यास तो परिच्छेद बनतो, ज्यासाठी वेगळ्या UI उपचाराची आवश्यकता असते.
**प्रॉम्प्टमध्ये महिना आणि तास का समाविष्ट केला आहे?**
प्रदूषणाच्या कारणांचे श्रेय हे दिवसाची वेळ आणि ऋतूवर खूप अवलंबून असते:
मॉडेल काय म्हणू शकते याची उदाहरणादाखल माहिती (ही मूळ स्रोतानुसार केलेली विभागणी नाही):
- नोव्हेंबरमधील सकाळी ७ वाजता दिल्ली → बहुधा शेतातील अवशेष जाळणे + सकाळची हवेची दाटी
- एप्रिलमधील दुपारी २ वाजता दिल्ली → बहुधा धुळीची वादळे
- मध्यरात्री मुंबई → बहुधा औद्योगिक/शिपिंगची हालचाल
मॉडेलला केवळ संभाव्य कारणांची सामान्य यादी देण्याऐवजी उपयुक्त स्पष्टीकरण देण्यासाठी या वेळेच्या संदर्भाची आवश्यकता असते.

**ऐतिहासिक डेटावरून बेसलाइन्स मोजण्याऐवजी त्या हार्डकोड का केल्या आहेत?**
सोपेपणा आणि विश्वासार्हता. रोलिंग बेसलाइन मोजण्यासाठी सतत चालणाऱ्या टाईम-सिरीज डेटाबेसची आवश्यकता असेल — किरकोळ अचूकतेच्या फायद्यासाठी ही अनावश्यक पायाभूत सुविधा आहे. हार्डकोड केलेल्या या किमती JanVayu च्या अंदाजित वर्किंग बेसलाइन्स आहेत, CREA किंवा IQAir ने प्रकाशित केलेले आकडे नाहीत, आणि त्या मॅन्युअली अपडेट केल्या जातात. वर्षानुवर्षे होणारा बदल मोठा असू शकतो (IQAir च्या दिल्लीच्या वार्षिक सरासरी २०१७ ते २०२५ दरम्यान ८४.१ ते ११३.५ µg/m³ पर्यंत आहेत), त्यामुळे या बेसलाइन्सना केवळ ढोबळ मर्यादा माना.

**Groq API कॉल्स समांतर (`Promise.allSettled`) का चालवले जातात?**
अनोमली चेकमध्ये एकाच वेळी अनेक शहरांमध्ये अचानक वाढ झालेली आढळू शकते. ते एकापाठोपाठ एक चालवल्यास ३-५ पट जास्त वेळ लागेल. `Promise.allSettled` ( `Promise.all` नाही) वापरल्यामुळे एका शहराच्या स्पष्टीकरणातील त्रुटीमुळे इतर शहरांची प्रक्रिया रद्द होत नाही.

## फॉलबॅक वर्तन

```javascript
if (!s.explanation) {
  s.explanation = `PM2.5 is ${s.ratio}x above JanVayu's approximate working baseline (not a published figure).`;
}
```

जर Groq API उपलब्ध नसेल, तरीही रिस्पॉन्समध्ये स्पाइकला डेटा आणि गुणोत्तर समाविष्ट असते — फक्त AI ने तयार केलेले कारण असलेले वाक्य नसते.
