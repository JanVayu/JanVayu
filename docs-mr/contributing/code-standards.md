# कोड स्टँडर्ड्स

JanVayu मध्ये साधे HTML, CSS आणि JavaScript वापरले जाते. यात कोणतीही बिल्ड स्टेप, फ्रेमवर्क किंवा बंडलर नाही. ते तसेच राहू द्या.

---

## HTML

- **सिमँटिक HTML5 एलिमेंट्स** वापरा — `<article>`, `<section>`, `<nav>`, `<main>`, `<header>`, `<footer>`
- सर्व इमेजेस आणि आयकॉन्ससाठी `alt` टेक्स्ट असणे आवश्यक आहे
- फॉर्म्समध्ये योग्य `<label>` एलिमेंट्स असणे गरजेचे आहे (स्क्रीन रीडर्ससाठी)
- जिथे सिमँटिक HTML पुरेसे नाही तिथे `aria-label` आणि `role` ॲट्रिब्युट्स वापरा
- WCAG 2.1 AA ॲक्सेसिबिलिटी गाईडलाईन्स फॉलो करा

---

## CSS

- रंग आणि स्पेसिंगसाठी **CSS कस्टम प्रॉपर्टीज (व्हेरिएबल्स)** वापरा — `:root` ब्लॉकच्या बाहेर हेक्स व्हॅल्यूज हार्डकोड करू नका
- मोबाईल-फर्स्ट CSS लिहा — बेस स्टाईल्स लहान स्क्रीन्सना टार्गेट करतात, आणि मीडिया क्वेरीज मोठ्या ब्रेकपॉईंट्स हाताळतात
- CSS फ्रेमवर्क्स (Bootstrap, Tailwind) वापरू नका — साधेपणा आणि परफॉर्मन्ससाठी हा प्रोजेक्ट व्हॅनिला CSS वर चालतो

---

## JavaScript

- **फक्त व्हॅनिला JavaScript** — React, Vue, jQuery किंवा इतर कोणतेही फ्रेमवर्क्स नाहीत
- सर्व असिंक्रोनस ऑपरेशन्ससाठी `async/await` वापरा (कॉलबॅक्स नकोत)
- API कॉल्स `try/catch` मध्ये रॅप करा — एरर्स नेहमी व्यवस्थित हँडल करा
- ज्या लॉजिकवरून लगेच अर्थ लागत नाही तिथे कमेंट्स द्या
- सफारीवर सपोर्ट नसलेले ES2022+ फीचर्स वापरू नका — शंका असल्यास [caniuse.com](https://caniuse.com) तपासा

---

## Netlify Functions

- प्रत्येक फंक्शन **फोकस्ड आणि सिंगल-पर्पज** ठेवा
- योग्य HTTP स्टेटस कोड्स रिटर्न करा (200, 400, 404, 500)
- सिक्रेट्स कधीही हार्डकोड करू नका — `process.env.VARIABLE_NAME` वापरा
- सर्व API फंक्शन्सवर CORS हेडर्स (`Access-Control-Allow-Origin: *`) समाविष्ट करा
- `OPTIONS` प्रीफ्लाइट रिक्वेस्ट्स हँडल करा
- PR सबमिट करण्यापूर्वी `netlify dev` वापरून लोकली टेस्ट करा

---

## एन्व्हायर्नमेंट व्हेरिएबल्स

- नवीन एन्व्हायर्नमेंट व्हेरिएबल्स खालीलप्रमाणे असले पाहिजेत:
  - प्लेसहोल्डर व्हॅल्यू आणि कमेंटसह `.env.example` मध्ये ॲड केलेले असावेत
  - `docs/technical/environment-variables.md` मध्ये डॉक्युमेंट केलेले असावेत

---

## परफॉर्मन्स गाईडलाईन्स

- चर्चेशिवाय नवीन npm डिपेंडन्सीज ॲड करू नका — `package.json` मुद्दाम कमीत कमी ठेवले आहे
- मोठे थर्ड-पार्टी स्क्रिप्ट्स सिंक्रोनसली लोड करणे टाळा — `defer` किंवा `async` वापरा
- इमेजेस ऑप्टिमाईज्ड असाव्यात आणि योग्य फॉरमॅट्समध्ये सर्व्ह केल्या जाव्यात
- Lighthouse CI परफॉर्मन्स (टार्गेट 0.6) आणि ॲक्सेसिबिलिटी (टार्गेट 0.85) ॲडव्हायझरी बजेट्स म्हणून ट्रॅक करते: ते वॉर्निंग देतात, बिल्ड फेल करत नाहीत. शक्य तिथे आणखी चांगली कामगिरी करण्याचे ध्येय ठेवा

## कमिट मेसेजेस

कमिट सब्जेक्ट्स `.githooks/commit-msg` द्वारे लागू केलेल्या प्रीफिक्सेसपैकी एकाने सुरू झाले पाहिजेत:
```
Prefix: संक्षिप्त वर्णन

Prefixes: Add, Fix, Update, Translate, Docs, Refactor, Test, CI, Chore, Merge

उदाहरणे:
Add: city cards वर PM10 toggle
Fix: email digest मध्ये city नसल्यास हाताळणे
Docs: code standards page जोडणे
Chore: dependencies अद्ययावत करणे
```

72 अक्षरांपेक्षा जास्त असलेल्या Subjects मुळे hook कडून वॉर्निंग येते (ब्लॉक होत नाही). `feat(dashboard): ...` सारख्या Conventional Commits स्टाईलला hook रिजेक्ट करतो.
