# স্কিল: অটোমেশন

JanVayu-এর শিডিউলড টাস্ক, ক্যাশ আর্কিটেকচার এবং রিকারিং মেইনটেন্যান্স ডিজাইন ও প্রম্পট করার জন্য এই প্যাটার্নগুলো ব্যবহার করা হয় — প্ল্যাটফর্মের এই অংশগুলো মানুষের সাহায্য ছাড়াই চলে।

---

## মূল নীতি: ফেইল ভিজিবলি, ডিগ্রেড গ্রেসফুলি

JanVayu-এর প্রতিটি অটোমেটেড সিস্টেম দুটি বৈশিষ্ট্যের কথা মাথায় রেখে ডিজাইন করা হয়েছে:

১. **ফেইল ভিজিবলি (Fail visibly)** — যখন কোনো কিছু ভেঙে যায়, তখন এটি নীরবে 500 রিটার্ন না করে পরিষ্কারভাবে লগ করে এবং একটি অর্থপূর্ণ রেসপন্স দেয়।
২. **ডিগ্রেড গ্রেসফুলি (Degrade gracefully)** — ইউআই (UI) ফাঁকা হয়ে যাওয়ার বদলে পুরোনো বা আংশিক ডেটা দিয়ে রেন্ডার হয়।

এই নীতিটি প্রতিটি অটোমেশন প্রম্পটের প্রাথমিক শর্ত ছিল:

```
Write a [scheduled/on-demand] Netlify Function for [task]. 
Requirements:
- If any external call fails, log the error with context (function name, 
  city/feed, error message) and continue — do not abort the entire run
- Always return a response body (never a raw 500)
- Stale data is better than no data — if a cache read fails, try a live 
  fetch; if the live fetch fails, return whatever stale data exists
- Log the start and end of every scheduled run with a timestamp
```

## শিডিউলড ফাংশন প্যাটার্ন

### "ক্যাশ ওয়ার্মার" প্যাটার্ন (`scheduled-fetch.mjs`)

যে ফাংশনগুলো শিডিউল অনুযায়ী আগে থেকে ডেটা ফেচ করে, তাদের জন্য:

```
Write a Netlify Scheduled Function that fetches [list of feeds] and stores 
results in Netlify Blobs. Requirements:
- Fetch all feeds in parallel (Promise.allSettled — not Promise.all, 
  so one failure doesn't cancel the others)
- Write a "last-fetch-time" key to Blobs after each run (ISO timestamp)
- Write a "last-fetch-log" key summarising which feeds succeeded/failed 
  and how many items were retrieved
- If a feed fetch fails, write the previous cached value back with an 
  error flag rather than writing nothing
- The on-demand functions that serve these feeds should check the age 
  of the cache and serve it without making a live call if < 4 hours old
```

"last-fetch-log" কি (key) থেকে `feed-status.js` ফাংশনটি অ্যাডমিনকে দেখানোর জন্য "Data last updated: X minutes ago" তথ্যটি পড়ে — নীরব অটোমেশনের চেয়ে দৃশ্যমান অটোমেশন ডিবাগ করা অনেক সহজ।

**`Promise.all`-এর বদলে `Promise.allSettled` কেন?**
`Promise.all` কোনো একটি প্রমিস বাতিল (reject) হওয়ার সাথে সাথেই বাকি সব পেন্ডিং প্রমিস বাতিল করে দেয়। ৫ বা তার বেশি সোর্স থাকা একটি ফিড ওয়ার্মারে, একটি Reddit টাইমআউট যেন নিউজ ফিড ক্যাশ হতে বাধা না দেয়। `Promise.allSettled` সবকিছু শেষ পর্যন্ত চালায় এবং প্রতিটির জন্য একটি ফলাফল রিটার্ন করে, তা সফল হোক বা ব্যর্থ।
### "Daily Digest" প্যাটার্ন (`daily-digest.mjs`)

যে ফাংশনগুলো নির্দিষ্ট সময়সূচি অনুযায়ী ব্যক্তিগতকৃত যোগাযোগ পাঠায়, সেগুলোর জন্য:

```
একটি Netlify Scheduled Function লিখুন যা:
1. Blobs থেকে গ্রাহকদের একটি তালিকা পড়বে (ইমেইল, শহরের পছন্দ, থ্রেশহোল্ড)
2. প্রত্যেক গ্রাহকের জন্য, তাদের শহরের বর্তমান AQI আনবে
3. যদি AQI গ্রাহকের থ্রেশহোল্ড ছাড়িয়ে যায়, তবে Resend-এর মাধ্যমে একটি ইমেইল পাঠাবে
4. লগ করুন: মোট গ্রাহক, পাঠানো ইমেইল, বাদ দেওয়া ইমেইল (থ্রেশহোল্ড পূরণ হয়নি), 
   এবং ব্যর্থ ইমেইল
5. রান শেষ হওয়ার পর লগটিকে Blobs-এ "last-email-log" হিসেবে লিখবে
6. কোনো একজন গ্রাহকের ব্যর্থতার কারণে লুপটি কখনোই বন্ধ হতে দেবেন না — 
   প্রত্যেক গ্রাহকের জন্য আলাদাভাবে এরর ধরুন এবং চালিয়ে যান
```

"কোনো একজন গ্রাহকের ব্যর্থতার কারণে লুপটি কখনোই বন্ধ হতে দেবেন না" - এটি একটি ডাইজেস্ট পাঠানোর জন্য সবচেয়ে গুরুত্বপূর্ণ শর্ত। একটি ভুল ইমেইল অ্যাড্রেসের কারণে অন্য ২০০ জন গ্রাহক যেন তাদের ডাইজেস্ট না পান, তা নিশ্চিত করতে হবে।

## ফিড ফ্রেশনেস আর্কিটেকচার

ক্যাশ ফ্রেশনেস চেক হলো এমন একটি প্যাটার্ন যা সব অন-ডিমান্ড ফিড ফাংশনে ব্যবহার করা হয়:

```javascript
// ফেচ লাইভ ডেটা লাগবে কি না, তা সিদ্ধান্ত নেওয়ার আগে ক্যাশের বয়স চেক করুন
const cacheAge = Date.now() - new Date(lastFetchTime).getTime();
const FOUR_HOURS = 4 * 60 * 60 * 1000;

if (cacheAge < FOUR_HOURS && cachedData) {
  return cachedData; // ক্যাশ থেকে সার্ভ করুন
}
// অন্যথায়: লাইভ ফেচ করুন, ক্যাশ আপডেট করুন, তারপর রিটার্ন করুন
```

**৪ ঘণ্টা কেন?**
Reddit এবং নিউজ ফিডগুলো মোটামুটি প্রতি ৪ ঘণ্টার চক্রে অর্থপূর্ণভাবে পরিবর্তিত হয়। এর চেয়ে বেশি ঘন ঘন রিফ্রেশ করলে রেট লিমিটে গিয়ে সমস্যা হয়; আর কম ঘন ঘন রিফ্রেশ করলে দূষণের সক্রিয় সময়ে প্ল্যাটফর্মটিকে সেকেলে মনে হয়।

**HTTP Cache-Control হেডারগুলো কেন ব্যবহার করা হবে না?**
Netlify-এর CDN HTTP রেসপন্স ক্যাশ করে, কিন্তু ফিডগুলোতে ডাইনামিক JSON থাকে। অ্যাপ্লিকেশন-লেভেল ক্যাশ হিসেবে Blobs ব্যবহার করলে এক্সপায়ারির ওপর সরাসরি নিয়ন্ত্রণ পাওয়া যায় — আপস্ট্রিম CDN ক্যাশ হেডার ভুলভাবে সেট করা থাকার কারণে সেকেলে রেসপন্স সার্ভ করার কোনো ঝুঁকি থাকে না।

## মনিটরিং প্যাটার্ন

JanVayu একটি লাইটওয়েট হেলথ এন্ডপয়েন্ট হিসেবে `feed-status.js` ব্যবহার করে:

```
একটি Netlify Function লিখুন যা Blobs-এর এই key-গুলো পড়বে:
- "last-fetch-time" (শেষ শিডিউলড ফেচের ISO টাইমস্ট্যাম্প)
- "last-fetch-log" (JSON: প্রতি-ফিডের সাফল্য/ব্যর্থতা/কাউন্ট)
- "last-email-log" (JSON: ডাইজেস্ট পাঠানোর পরিসংখ্যান)

এগুলোকে একটি JSON রেসপন্স হিসেবে রিটার্ন করুন। পেজ লোড হওয়ার সময় ক্লায়েন্ট এই এন্ডপয়েন্টটিকে কল করে দেখায় "Feeds last updated: <time> (auto-updates every 4h)"। এখানে সেকেলে হওয়ার কোনো সতর্কবার্তা নেই।
```

এটি ফ্রন্ট এন্ড থেকে অটোমেশনটিকে পর্যবেক্ষণযোগ্য করে তোলে — একজন ব্যবহারকারী (বা মেইনটেইনার) Netlify ড্যাশবোর্ডে অ্যাক্সেস না করেই প্ল্যাটফর্মের ডেটার ফ্রেশনেস চেক করতে পারেন।

## Cron টাইমিং প্যাটার্ন
সব নির্ধারিত ফাংশন UTC cron এক্সপ্রেশন ব্যবহার করে। IST অফসেট সবসময় স্পষ্টভাবে হিসাব করা হয়, ধরে নেওয়া হয় না:

```
IST = UTC + 5:30
8:00 AM IST = 2:30 AM UTC → cron: "30 2 * * *"
প্রতি ৪ ঘণ্টা = "0 */4 * * *" (UTC, অর্থাৎ 05:30, 09:30, 13:30 ... IST)
```

**নির্ধারিত ফাংশন ডিপ্লয় করার আগে UTC কনভার্শন যাচাই করতে সবসময় Python বা কোনো নির্ভরযোগ্য কনভার্টার ব্যবহার করুন।** ভারতে ডেলাইট সেভিং টাইম (DST) পালন করা হয় না, তাই সারা বছর IST অফসেট একটি নির্দিষ্ট +5:30 থাকে; ভুলগুলো সাধারণত আধা ঘণ্টা ভুলে যাওয়ার কারণেই হয়।

## অন্যান্য প্রজেক্টের জন্য মানিয়ে নেওয়া

ক্যাশ-ওয়ার্মার + অন-ডিমান্ড-সার্ভার প্যাটার্নটি এমন যেকোনো প্রজেক্টের জন্য পুনরায় ব্যবহারযোগ্য যা:
- রেট-লিমিটেড বা অবিশ্বস্ত থার্ড-পার্টি API থেকে ডেটা প্রদর্শন করতে চায়
- এমন ইউজার আছে যারা API অ্যাভেইলেবিলিটি নির্বিশেষে দ্রুত পেজ লোড আশা করে
- একটি স্থায়ী ডেটাবেস রাখার সামর্থ্য নেই (Netlify Blobs সার্ভারলেস এবং ফ্রি-টিয়ার)

মূল আর্কিটেকচারাল সিদ্ধান্ত: **ফেচ এবং সার্ভকে আলাদা করুন**। নির্ধারিত ফাংশন ফেচ করে; অন-ডিমান্ড ফাংশন সার্ভ করে। তারা কেবল Blobs ক্যাশের মাধ্যমে যোগাযোগ করে। এটি উভয়েরকেই স্বাধীনভাবে টেস্ট করা এবং স্বাধীনভাবে ডিবাগ করা সহজ করে তোলে।
