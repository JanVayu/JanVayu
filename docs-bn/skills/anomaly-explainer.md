# স্কিল: অ্যানোমালি এক্সপ্লেইনার

**ব্যবহৃত হয়:** `netlify/functions/anomaly-check.mjs`  
**মডেল:** Groq-এর মাধ্যমে `openai/gpt-oss-120b` (ডিফল্ট, যা `GROQ_MODEL` দ্বারা সেট করা হয়; ১৬ আগস্ট ২০২৬-এ Groq এটি বাতিল করার আগ পর্যন্ত Llama 3.3 70B)  
**ট্রিগার:** অন-ডিমান্ড ইনভোক করা হয়; পাঁচটি প্রধান শহরের রিডিংকে সিজনাল বেসলাইনের সাথে মিলিয়ে চেক করে

---

## এই স্কিলটি কী কাজ করে

এটি লাইভ রিডিংগুলোকে হার্ডকোড করা সিজনাল বেসলাইনের সাথে তুলনা করে পাঁচটি প্রধান শহরে PM2.5-এর স্পাইক শনাক্ত করে। যখন কোনো স্পাইক ধরা পড়ে (রিডিং বেসলাইনের 2× এর বেশি), তখন এটি Groq-হোস্টেড মডেলকে একটি মাত্র, ভারত-ভিত্তিক বাক্যে এর সবচেয়ে সম্ভাব্য কারণ ব্যাখ্যা করতে বলে।

চারটি স্কিল ফাইলের মধ্যে এটি সবচেয়ে সীমাবদ্ধ — একটি বাক্য, একটি কারণ এবং সর্বোচ্চ নির্দিষ্টতা।

---

## সিস্টেম প্রম্পট (প্রতি-শহর, হুবহু)

```
In one sentence, explain why PM2.5 in {city} might be {pm25} µg/m³ right now 
— {month}, {hour}. Give the most likely cause. Be specific to the Indian context.
```

দ্রষ্টব্য: এটি একটি **ইউজার মেসেজ** হিসেবে পাঠানো হয়, সিস্টেম ইনস্ট্রাকশন হিসেবে নয়। যেহেতু আউটপুটটি একটি স্পষ্ট তথ্যভিত্তিক কাঠামোর সাথে একটি মাত্র বাক্য, তাই একটি ইউজার-টার্ন প্রম্পটই যথেষ্ট — একটি সম্পূর্ণ সিস্টেম ইনস্ট্রাকশন কোনো সুবিধা ছাড়াই কেবল ওভারহেড বাড়াবে।

## স্পাইক ডিটেকশন লজিক (প্রি-এআই)

```javascript
const ratio = d.pm25 / baseline;
if (ratio > 2) {
  // flag as spike, then explain via Groq
}
```

থ্রেশহোল্ড: **সিজনাল বেসলাইনের 2×** (কোনো নির্দিষ্ট পরম সংখ্যা নয়)। এটি গুরুত্বপূর্ণ কারণ:
- দিল্লির শীতকালীন বেসলাইন হলো ~95 µg/m³ — জানুয়ারিতে 120 µg/m³ রিডিং অস্বাভাবিক নয়
- মুম্বাইয়ের বেসলাইন হলো ~45 µg/m³ — সেখানে 120 µg/m³ রিডিং অত্যন্ত অস্বাভাবিক
- একটি নির্দিষ্ট থ্রেশহোল্ড (যেমন, "150 µg/m³ এর ওপর যেকোনো কিছু ফ্ল্যাগ করো") ফলস পজিটিভ (দিল্লির শীতকাল) এবং ফলস নেগেটিভ (উপকূলীয় শহর) উভয়ই তৈরি করবে

**সিজনাল বেসলাইন (আনুমানিক JanVayu-এর ওয়ার্কিং বেসলাইন, প্রকাশিত CREA বা IQAir-এর পরিসংখ্যান নয়):**

| শহর | অক্টোবর–মার্চ (শীতকাল) | এপ্রিল–সেপ্টেম্বর (গ্রীষ্ম/বর্ষা) |
|------|-----------------|--------------------------|
| দিল্লি | 95 µg/m³ | 55 µg/m³ |
| মুম্বাই | 45 µg/m³ | 45 µg/m³ |
| কলকাতা | 80 µg/m³ | 35 µg/m³ |
| চেন্নাই | 40 µg/m³ | 40 µg/m³ |
| বেঙ্গালুরু | 40 µg/m³ | 40 µg/m³ |

## মূল ডিজাইন সিদ্ধান্ত

**একটি বাক্য কেন?**
অ্যানোমালি এক্সপ্ল্যানেশনটি UI-তে একটি টুলটিপ বা ইনলাইন অ্যানোটেশন হিসেবে দেখানো হয়। একটি বাক্য হলো সর্বোচ্চ পরিমাণ যা ব্যবহারকারীর ফ্লো ব্যাহত না করেই পড়া সম্ভব। এর চেয়ে বড় কিছু হলে তা একটি অনুচ্ছেদে পরিণত হয়, যার জন্য ভিন্ন একটি UI ট্রিটমেন্ট প্রয়োজন।
**প্রম্পটে কেন মাস এবং ঘণ্টা অন্তর্ভুক্ত করা হয়?**
দূষণের উৎস নির্ণয় (cause attribution) দিনের সময় এবং ঋতুর ওপর ব্যাপকভাবে নির্ভর করে:
মডেলটি কী বলতে পারে তার কিছু দৃষ্টান্তমূলক উদাহরণ (এগুলো উৎস-নির্ণয়ের চূড়ান্ত ফলাফল নয়):
- নভেম্বরে সকাল ৭টায় দিল্লি → সম্ভবত খড় পোড়ানো + সকালের ইনভার্সন (morning inversion)
- এপ্রিলে দুপুর ২টোয় দিল্লি → সম্ভবত ধূলিঝড়
- মধ্যরাতে মুম্বাই → সম্ভবত শিল্প/জাহাজ চলাচল কার্যক্রম
মডেলটির একটি সাধারণ সম্ভাব্য কারণের তালিকার পরিবর্তে একটি কার্যকর ব্যাখ্যা দেওয়ার জন্য এই সময়ের প্রেক্ষাপট প্রয়োজন।

**ঐতিহাসিক ডেটা থেকে হিসাব করার বদলে কেন হার্ডকোড (hardcode) করা বেসলাইন ব্যবহার করা হয়?**
সহজবোধ্যতা এবং নির্ভরযোগ্যতার জন্য। একটি রোলিং বেসলাইন হিসাব করতে হলে একটি পার্মানেন্ট টাইম-সিরিজ ডেটাবেস লাগবে — যা সামান্য নির্ভুলতা বৃদ্ধির জন্য অপ্রয়োজনীয় অবকাঠামো। হার্ডকোড করা মানগুলো হলো আনুমানিক JanVayu ওয়ার্কিং বেসলাইন, CREA বা IQAir-এর প্রকাশিত কোনো পরিসংখ্যান নয়, এবং এগুলো ম্যানুয়ালি আপডেট করা হয়। বছরের পর বছর পার্থক্য অনেক হতে পারে (২০১৭ থেকে ২০২৫ সাল পর্যন্ত IQAir-এর দিল্লির বার্ষিক গড় ৮৪.১ থেকে ১১৩.৫ µg/m³ এর মধ্যে রয়েছে), তাই বেসলাইনগুলোকে মোটামুটি থ্রেশহোল্ড হিসেবে বিবেচনা করুন।

**কেন Groq API কলগুলো প্যারালালে (parallel) চালানো হয় (`Promise.allSettled`)?**
অ্যানোমালাই (anomaly) চেক করার সময় একাধিক শহরে একই সাথে দূষণের মাত্রা বেড়ে যাওয়ার বিষয়টি ধরা পড়তে পারে। পরপর চালালে ৩-৫ গুণ বেশি সময় লাগবে। `Promise.allSettled` ( `Promise.all` নয়) ব্যবহার করার অর্থ হলো, একটি শহরের ব্যাখ্যার ক্ষেত্রে ব্যর্থ হলেও তা অন্যগুলোর কাজ বাতিল করে দেয় না।

## ফলব্যাক আচরণ (Fallback Behaviour)

```javascript
if (!s.explanation) {
  s.explanation = `PM2.5 is ${s.ratio}x above JanVayu's approximate working baseline (not a published figure).`;
}
```

Groq API যদি কাজ না করে, তবুও রেসপন্সে স্পাইক ডেটা এবং অনুপাত অন্তর্ভুক্ত থাকে — শুধু এআই-উত্পাদিত কারণের বাক্যটি থাকে না।
