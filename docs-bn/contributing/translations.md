# অনুবাদ

ভারতের ভাষাগত বৈচিত্র্যের মধ্যে সবার কাছে পৌঁছানোর ব্যাপারে JanVayu প্রতিশ্রুতিবদ্ধ। প্ল্যাটফর্মটি বর্তমানে ইংরেজি, হিন্দি, তামিল, মারাঠি এবং বাংলা ভাষা সাপোর্ট করে। ইন্টারফেসটি এই পাঁচটি ভাষাতেই পুরোপুরি অনুবাদ করা হয়েছে; আর ডকুমেন্টেশনের একটি অংশ অনুবাদ করা হয়েছে (প্রতিটি অনুবাদ করা ট্রির ৬5 পৃষ্ঠার মধ্যে 47 পৃষ্ঠা)।

## কীভাবে অনুবাদে অবদান রাখবেন

### নতুন ভাষা যোগ করা

1. `Translation: Add [Language Name] support` শিরোনামে একটি Issue খুলুন
2. এর মধ্যে যা যা দেবেন:
   - আপনার নাম (বা ইউজারনেম) এবং ভাষার দক্ষতা
   - আপনি নিয়মিত কনটেন্ট আপডেটের সাথে সাথে অনুবাদগুলো আপডেট রাখার দায়িত্ব নিতে পারবেন কি না
3. একজন মেইনটেইনার একটি ব্রাঞ্চ তৈরি করে অনুবাদ করার জন্য সোর্স স্ট্রিংগুলো দিয়ে দেবেন

### বিদ্যমান অনুবাদের উন্নতি করা

যদি আপনি কোনো ভুল বা বেমানান অনুবাদ দেখতে পান:

1. `Translation: Fix [Language Name] — [specific section/string]` লিখে একটি Issue খুলুন
2. এর মধ্যে যা যা দেবেন:
   - বর্তমান লেখা, সংশোধিত লেখা এবং একটি সংক্ষিপ্ত ব্যাখ্যা

---

## অনুবাদের নীতি

- **আক্ষরিক অনুবাদের চেয়ে সঠিকতা** — আক্ষরিক অনুবাদের বদলে স্বাভাবিক ভাষায় সঠিক অর্থ তুলে ধরুন
- **প্রযুক্তিগত শব্দগুলো অপরিবর্তিত রাখুন** — PM2.5, AQI, NCAP, GEMM-এর মতো শব্দগুলো যেমন আছে তেমনই থাকবে (এগুলো আন্তর্জাতিকভাবে প্রমিত)
- **সহজ ভাষা ব্যবহার করুন** — অনুবাদগুলো ইংরেজি সংস্করণের মতোই সাধারণ পাঠকদের জন্য সহজবোধ্য হতে হবে: শিক্ষিত সাধারণ মানুষ, বিশেষজ্ঞ নয়
- **ধারাবাহিকতা** — একই ধারণার জন্য পুরো লেখায় একই অনুবাদ ব্যবহার করুন (যেমন, "air quality index"-কে সবসময় একইভাবে অনুবাদ করতে হবে)
- **একই টোন** — অনুবাদে যেন ইংরেজি লেখার কোনো রাজনৈতিক দল বা মতাদর্শকে সমর্থন বা বিরোধিতা না করার নীতি বজায় থাকে

## সংবেদনশীল পরিভাষা

| ইংরেজি | নোট |
|---------|-------|
| Non-Attainment City | এমন একটি শহর হিসেবে অনুবাদ করুন যা জাতীয় বায়ুমান মান অর্জন করতে (পূরণ করতে) ব্যর্থ হয়েছে |
| Graded Response Action Plan (GRAP) | প্রথমে পুরো নাম দিয়ে GRAP সংক্ষিপ্ত রূপটি ব্যবহার করুন |
| PM2.5 | সব ভাষায় PM2.5 হিসেবেই রাখুন |
| NCAP | NCAP হিসেবেই রাখুন; প্রথমে National Clean Air Programme হিসেবে বানান করে লিখুন |
| CPCB | CPCB হিসেবেই রাখুন; প্রথমে Central Pollution Control Board হিসেবে বানান করে লিখুন |

## লাইভ ট্রান্সলেটেড ডকুমেন্টেশন
রেপোতে প্রতিটি ভাষা `docs-{lang}/` ডিরেক্টরিতে থাকে এবং এটি `/docs/` এ একটি একক Docsify শেল দ্বারা সার্ভ করা হয়, যা হ্যাশ রুটের মাধ্যমে ভাষা-নির্দিষ্ট কনটেন্ট রাউট করে।

| ভাষা | লাইভ URL | সোর্স ডিরেক্টরি |
|----------|----------|------------------|
| English | [/docs/](/docs/) | `docs/` |
| Hindi | [/docs/#/hi/](/docs/#/hi/) | `docs-hi/` |
| Bengali | [/docs/#/bn/](/docs/#/bn/) | `docs-bn/` |
| Marathi | [/docs/#/mr/](/docs/#/mr/) | `docs-mr/` |
| Tamil | [/docs/#/ta/](/docs/#/ta/) | `docs-ta/` |

`.github/workflows/translations.yml` এর `auto-translate` জব দ্বারা অনূদিত ডকস রিফ্রেশ করা হয় (এটির জন্য একটি Sarvam API key প্রয়োজন) এবং এটি English ডকগুলোর চেয়ে কিছুটা পিছিয়ে থাকতে পারে।

## CI: Translation Coverage

`docs` টাচ করে এমন `main` এ প্রতিটি পুশের সময় একটি GitHub Actions ওয়ার্কফ্লো (`.github/workflows/translations.yml`) রান করে। এটি চেক করে:

- **File coverage** — প্রতিটি ভাষায় কি সব English ডক মিরর করা আছে?
- **SUMMARY.md parity** — সব ভাষার কি পেজ কাউন্ট সমান?
- **Stale detection** — যখন একটি English ডক পরিবর্তন করা হয়, কোন অনুবাদগুলো আপডেট করা হয়নি?

প্রতিটি রানের জন্য GitHub Actions **Job Summary** ট্যাবে ফলাফলগুলো দেখা যায়।

## Directory Structure

প্রতিটি ট্রান্সলেশন ডিরেক্টরি English `docs/` স্ট্রাকচারকে মিরর করে, শুধু `api/` এবং `wiki/` এর কনটেন্ট শুধুমাত্র English-এ থাকে:

```
docs-{lang}/
├── README.md
├── SUMMARY.md
├── about/
├── claude-code/
├── contributing/
├── data-sources/
├── skills/
├── tech-stack/
├── technical/
└── user-guide/
```

যখন একটি নতুন English ডক যোগ করা হয়, তখন সমস্ত ট্রান্সলেশন ডিরেক্টরিতে সংশ্লিষ্ট ফাইলটি তৈরি করুন (এমনকি যদি এটি প্রাথমিকভাবে English-এও থাকে — পরে এটি অনুবাদ করা যেতে পারে)।
