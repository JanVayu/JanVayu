# Claude Code সেটআপ — সম্পূর্ণ সক্ষমতার রেফারেন্স

এই পেজটি JanVayu Claude Code সেটআপের সব সক্ষমতার একটি বিস্তারিত রেফারেন্স — যেখানে ডেভেলপমেন্ট টুলস, এনফোর্সমেন্ট মেকানিজম, AI ফিচার, CI/CD অটোমেশন, ডিপ্লয়মেন্ট ইনফ্রাস্ট্রাকচার এবং ডকুমেন্টেশন ওয়ার্কফ্লো অন্তর্ভুক্ত রয়েছে।

---

## 1. কোর ডেভেলপমেন্ট ক্যাপাবিলিটিজ

### ফাইল অপারেশনস
- রিপোজিটরির **যেকোনো ফাইল পড়া** — `index.html`, Netlify Functions, কনফিগস, ডকুমেন্টেশন
- **নতুন ফাইল তৈরি করা** — Netlify Functions, ডকুমেন্টেশন পেজ, কনফিগ ফাইল তৈরি করা
- **বিদ্যমান ফাইল এডিট করা** — অপ্রাসঙ্গিক কোড না লিখেই টার্গেটেড ইনলাইন এডিট করা
- **ফাইলের নামের প্যাটার্ন দিয়ে সার্চ করা** — গ্লোব ম্যাচিং (যেমন, `**/*.mjs`, `docs/**/*.md`)
- **কন্টেন্ট দিয়ে সার্চ করা** — কোডবেস জুড়ে রেজেক্স (regex) ভিত্তিক ফুল-টেক্সট সার্চ

### শেল ও টার্মিনাল অ্যাক্সেস
- ডিপেন্ডেন্সি ম্যানেজ করতে `npm install` রান করা
- লোকাল ডেভেলপমেন্ট সার্ভারের জন্য `netlify dev` রান করা
- যেকোনো নন-ডেস্ট্রাকটিভ শেল কমান্ড এক্সিকিউট করা
- `git`, `gh` (GitHub CLI), `ls`, `mkdir` ব্যবহার করা
- **কনভেনশন অনুযায়ী ব্লক করা**: `rm -rf`, `git push --force`, `git reset --hard`

### মাল্টি-ফাইল কোঅর্ডিনেশন
একটি Claude Code সেশন একবারে এই সবগুলো ফাইল স্পর্শ করতে পারে:
- `index.html` (মার্কআপ), `app.js` (লজিক) এবং `styles.css` (স্টাইলিং)
- Netlify Functions (`netlify/functions/*.mjs` বা `*.js`)
- কনফিগারেশন ফাইল (`netlify.toml`, `package.json`, `.editorconfig`)
- ডকুমেন্টেশন (`docs/**/*.md`, `CHANGELOG.md`, `README.md`)
- Git হুকস (`.githooks/pre-commit`, `.githooks/commit-msg`)
- GitHub ওয়ার্কফ্লো (`.github/workflows/*.yml`)

## 2. Git ওয়ার্কফ্লো ক্যাপাবিলিটিজ

### ব্রাঞ্চিং এবং কমিটস
- ফিচার ব্রাঞ্চ তৈরি করা (যেমন, `claude/feature-name`)
- নির্দিষ্ট ফাইল স্টেজিং করা (অপ্রয়োজনে `.env` বা সিক্রেট অন্তর্ভুক্ত হওয়া এড়ায়)
- এনফোর্সড প্রিফিক্স কনভেনশন মেনে মেসেজ দিয়ে কমিট করা:
  - `Add:` — নতুন ফিচার বা ফাইল
  - `Fix:` — বাগ ফিক্স
  - `Update:` — বিদ্যমান ফিচারের উন্নতি
  - `Translate:` — ট্রান্সলেশনের কাজ
  - `Docs:` — ডকুমেন্টেশনের পরিবর্তন
  - `Refactor:` — কোড রিস্ট্রাকচারিং (কোনো আচরণগত পরিবর্তন নেই)
  - `Test:` — টেস্ট যোগ করা
  - `CI:` — CI/CD পাইপলাইন পরিবর্তন
  - `Chore:` — রক্ষণাবেক্ষণের কাজ
- ৭২ ক্যারেক্টারের বেশি সাবজেক্ট লাইনে হুক থেকে একটি ওয়ার্নিং ট্রিগার হয় (ব্লক হয় না); `Merge`-ও একটি অনুমোদিত প্রিফিক্স

### পুল রিকোয়েস্ট ম্যানেজমেন্ট
- স্ট্রাকচার্ড টাইটেল, সামারি এবং টেস্ট প্ল্যান দিয়ে PR তৈরি করা
- মাল্টি-PR ওয়ার্কফ্লো ম্যানেজ করা (যেমন, প্রথমে ব্যাকএন্ড, তারপর ফ্রন্টএন্ড, তারপর ডকুমেন্টেশন)
- PR ডিফস রিভিউ করা এবং পরিবর্তনের পরামর্শ দেওয়া
- কমেন্ট যোগ করা এবং রিভিউ ফিডব্যাকের উত্তর দেওয়া
### গিট হুক এনফোর্সমেন্ট
এই সেটআপে দুটি কাস্টম গিট হুক আছে যেগুলো স্বয়ংক্রিয়ভাবে রান হয়:

**প্রি-কমিট হুক** (`.githooks/pre-commit`):
| চেক | অ্যাকশন |
|-------|--------|
| `.env`, `.env.local`, `.env.production` | **কমিট ব্লক করা** |
| `credentials.json`, `*.pem`, `*.key` | **কমিট ব্লক করা** |
| `debugger` স্টেটমেন্ট, `breakpoint()` | **কমিট ব্লক করা** |
| মার্জ কনফ্লিক্ট মার্কার (`<<<<<<<`, `>>>>>>>`) | **কমিট ব্লক করা** |
| `console.log`, `console.debug`, `console.warn` | **সতর্ক করা** (`// keep` দিয়ে বাইপাস করা যাবে) |
| ৫০০ কেবি-এর বেশি বড় ফাইল | **সতর্ক করা** |

**কমিট মেসেজ হুক** (`.githooks/commit-msg`):

|-------|--------|
| প্রয়োজনীয় প্রিফিক্স না থাকা | **কমিট ব্লক করা** |
| সাবজেক্ট লাইন ৭২ ক্যারেক্টারের বেশি হলে | **সতর্ক করা** |

## ৩. এআই-চালিত ফিচার (Groq-হোস্টেড মডেল)

> **আপডেট, ২ অক্টোবর ২০২৬: Groq ১৬ আগস্ট ২০২৬-এ Llama 3.3 70B বন্ধ করে দিয়েছে (Groq ডেপ্রিকেশন পেজ); ফাংশনগুলো এখন ডিফল্টভাবে `openai/gpt-oss-120b` ব্যবহার করে, যা `GROQ_MODEL` এনভায়রনমেন্ট ভেরিয়েবল দিয়ে পরিবর্তন করা যেতে পারে।**

এই সেটআপে চারটি প্রোডাকশন এআই ফিচার আছে, যার প্রতিটি একটি স্ট্রাকচার্ড স্কিল ফাইল সহ নেটলাই (Netlify) ফাংশন হিসেবে ইমপ্লিমেন্ট করা হয়েছে:

### ৩.১ এয়ার কোয়ালিটি অ্যাসিস্ট্যান্ট (`air-query.mjs`)
- **ইনপুট**: শহরের নাম + স্বাভাবিক ভাষার প্রশ্ন
- **আউটপুট**: বাস্তব তথ্যের ওপর ভিত্তি করে উত্তর (প্রায় ১৫০ শব্দের লক্ষ্য), যেখানে আসল AQI নম্বর উল্লেখ থাকবে
- **ভাষা**: ইংরেজি এবং ভারতের নয়টি ভাষা (হিন্দি, তামিল, বাংলা, মারাঠি, তেলুগু, গুজরাটি, কন্নড়, মালয়ালম, পাঞ্জাবি)
- **মূল শর্ত**: অবশ্যই বাস্তব ডেটা উল্লেখ করতে হবে — কোনো সাধারণ পরামর্শ নয়
- **ফলব্যাক**: Groq-এ রেট-লিমিট হলে এটি র (raw) AQI ডেটা রিটার্ন করে
- **স্কিল ফাইল**: `docs/skills/air-quality-assistant.md`

### ৩.২ হেলথ অ্যাডভাইজরি (`health-advisory.mjs`)
- **ইনপুট**: শহর + বয়স + শারীরিক অবস্থা + বাইরে কাটানো সময়
- **আউটপুট**: কালার-কোডেড ঝুঁকির মাত্রা + বাস্তবসম্মত পরামর্শ (৩-৪ বাক্য)
- **মূল শর্ত**: সরাসরি পরামর্শ দিতে হবে, কোনো অস্পষ্টতা নয় — "Consider staying indoors"-এর বদলে "Stay indoors"
- **প্রি-এআই ধাপ**: এআই-এর উত্তর আসার আগেই একটি জাভাস্ক্রিপ্ট ফাংশন ঝুঁকির মাত্রা হিসাব করে, যার ফলে UI-তে সাথে সাথে কালার-কোডিং দেখানো যায়
- **ফলব্যাক**: এআই-এর ব্যাখ্যা দিতে ব্যর্থ হলেও ঝুঁকির মাত্রা দেখানো হয়
- **স্কিল ফাইল**: `docs/skills/health-advisory.md`
### 3.3 জবাবদিহিতা ব্রিফ (`accountability-brief.mjs`)
- **ইনপুট**: শহর + ওয়ার্ড/এলাকা + সময়কাল
- **আউটপুট**: আটটি লেবেলযুক্ত সেকশনসহ স্ট্রাকচার্ড ব্রিফ (এলাকা, সময়কাল, বর্তমান PM2.5, স্ট্যাটাস, ডেটা কী বলছে, সম্ভাব্য উৎস, স্থানীয় সংশ্লিষ্টরা কী করতে পারে, ডেটার সীমাবদ্ধতা)
- **সর্বোচ্চ আউটপুট**: ১,০২৪ টোকেন
- **অডিয়েন্স**: ওয়ার্ড কাউন্সিলর, স্থানীয় সাংবাদিক, RWA (রেসিডেন্ট ওয়েলফেয়ার অ্যাসোসিয়েশন)
- **মূল বৈশিষ্ট্য**: নির্দিষ্ট স্থানীয় রেগুলেটরি মেকানিজম (GRAP, RTI এবং মিউনিসিপ্যাল অভিযোগের নম্বর) অন্তর্ভুক্ত করে
- **ফলব্যাক**: AI অ্যানালিসিস ছাড়া র (raw) ডেটা রিটার্ন করে
- **স্কিল ফাইল**: `docs/skills/accountability-brief.md`

### 3.4 অ্যানোমালি ডিটেকশন (`anomaly-check.mjs`)
- **ইনপুট**: স্বয়ংক্রিয় — দিল্লি, মুম্বাই, কলকাতা, চেন্নাই, বেঙ্গালুরু মনিটর করে
- **থ্রেশহোল্ড**: PM2.5 > ২× মৌসুমী বেসলাইন = অ্যানোমালি
- **আউটপুট**: প্রতি স্পাইকের জন্য একটি বাক্যের ব্যাখ্যা
- **মৌসুমী বেসলাইন**: JanVayu-এর হার্ডকোডেড আনুমানিক ওয়ার্কিং বেসলাইন, প্রকাশিত CREA বা IQAir-এর ফিগার নয় (ডায়নামিক্যালি হিসাব করা হয় না)
- **ফলব্যাক**: AI ব্যাখ্যা ছাড়া অ্যানোমালি ফ্ল্যাগ রিটার্ন করে
- **স্কিল ফাইল**: `docs/skills/anomaly-explainer.md`

### শেয়ার্ড AI আর্কিটেকচার
চারটি ফিচারের মধ্যেই যা সাধারণ:
- শুধুমাত্র সার্ভার-সাইড এক্সিকিউশন (ক্লায়েন্টের কাছে কোনো API key প্রকাশ করা হয় না)
- CORS প্রিফ্লাইট হ্যান্ডলিং (OPTIONS → 204)
- উপযুক্ত স্ট্যাটাস কোডসহ JSON রেসপন্স
- প্রতিটি এক্সটার্নাল কলে try/catch
- গ্রেসফুল ডিগ্রেডেশন — প্রতিটি AI ফিচারের একটি নন-AI ফলব্যাক আছে

## 4. Netlify Functions (২৮টি সার্ভারলেস হ্যান্ডলার)

নিচের টেবিলগুলোতে কোর ফাংশনগুলো তালিকাভুক্ত করা হয়েছে। রিপোজিটরিতে ২৮টি হ্যান্ডলার ফাইল এবং একটি শেয়ার্ড হেল্পার (`blob-store.js`) রয়েছে; এর মধ্যে পাঁচটি হ্যান্ডলার শিডিউল করা।

| ফাংশন | শিডিউল | উদ্দেশ্য |
|----------|----------|---------|
| `scheduled-fetch.mjs` | প্রতি ৪ ঘণ্টা পরপর | Netlify Blobs ক্যাশে সব সোশ্যাল মিডিয়া এবং নিউজ ফিড প্রি-ফেচ করে |
| `daily-digest.mjs` | প্রতিদিন সকাল ৮:০০ টা IST | Resend API-এর মাধ্যমে সাবস্ক্রাইবারদের কাছে AQI ইমেইল ডাইজেস্ট পাঠায় |

## 7. MCP সার্ভার ইন্টিগ্রেশন

Claude Code এমন Model Context Protocol (MCP) সার্ভার সাপোর্ট করে যা লোকাল ফাইলসিস্টেমের বাইরে এর টুল অ্যাক্সেস বাড়ায়। JanVayu ডেভেলপমেন্টের সময় এগুলোর মধ্যে কোনগুলো ব্যবহার করা হয়েছিল তা রিপোজিটরিতে রেকর্ড করা নেই; তবে নিচের টেবিলে দেখানো হয়েছে যে এগুলো কী কাজে ব্যবহার করা যেতে পারে:
| MCP Server | Tools Available | Use Case for JanVayu |
|------------|----------------|---------------------|
| **GitHub** | PR management, issue tracking, code search, CI checks | PR, রিভিউ এবং ইস্যুর কমেন্ট ম্যানেজ করে |
| **Notion** | পেজ তৈরি, ডেটাবেস কোয়েরি, সার্চ, আপডেট | প্রজেক্ট প্ল্যানিং, টাস্ক ট্র্যাকিং, মিটিং নোটস |
| **Gmail** | মেসেজ সার্চ, থ্রেড পড়া, ড্রাফট তৈরি | ফিচার নিয়ে ইমেইল আলোচনাগুলো রেফারেন্স হিসেবে ব্যবহার |
| **Figma** | ডিজাইন কনটেক্সট, স্ক্রিনশট, মেটাডেটা পাওয়া | ডিজাইন মকআপগুলোকে HTML/CSS-এ রূপান্তর |
