# Claude Code ডেভেলপমেন্ট ওয়ার্কফ্লো

এই পেজে Claude Code ব্যবহার করে JanVayu তৈরির দৈনন্দিন ওয়ার্কফ্লো ডকুমেন্ট করা হয়েছে — ফিচার ডেভেলপমেন্ট থেকে শুরু করে বাগ ফিক্সিং এবং ডকুমেন্টেশন পর্যন্ত।

---

## ফিচার ডেভেলপমেন্ট ওয়ার্কফ্লো

### ধাপ ১: ফিচার নির্ধারণ করা

একটি স্পষ্ট এবং সীমাবদ্ধতা-সচেতন বর্ণনা দিয়ে শুরু করুন:

```
> একটি ওয়ার্ড-লেভেল অ্যাকাউন্টেবিলিটি ব্রিফ ফিচার যোগ করুন।
> এটি একটি Netlify Function (ES মডিউল, .mjs) হতে হবে যা:
> - ইনপুট হিসেবে একটি শহরের নাম নেবে
> - WAQI থেকে লাইভ AQI আনবে
> - একটি স্ট্রাকচারড প্রম্পট সহ Groq-হোস্টেড মডেলে ডেটা পাঠাবে
> - বর্তমান স্ট্যাটাস, NCAP টার্গেট এবং ৫টি অ্যাকাউন্টেবিলিটি প্রশ্নসহ একটি ব্রিফ রিটার্ন করবে
> - Groq রেট-লিমিটেড হলে একটি ফলব্যাক থাকবে
> বিদ্যমান প্যাটার্নগুলো অনুসরণ করে index.html-এ UI সেকশনটিও যোগ করুন।
```

### ধাপ ২: ক্লড এক্সপ্লোর করে

Claude Code পড়ে:
- `index.html` — বিদ্যমান UI প্যাটার্ন, CSS ভেরিয়েবল, JS কনভেনশন
- বিদ্যমান Netlify Functions — কোড স্টাইল, CORS হ্যান্ডলিং, এরর প্যাটার্ন
- `package.json` — উপলব্ধ ডিপেন্ডেন্সি
- `netlify.toml` — ডিপ্লয়মেন্ট কনফিগারেশন

### ধাপ ৩: ক্লড ইমপ্লিমেন্ট করে

Claude ফাইল তৈরি বা পরিবর্তন করে:
১. `netlify/functions/accountability-brief.mjs` — সার্ভারলেস ফাংশন
২. `index.html` — নতুন HTML সেকশন, CSS স্টাইল, JS ফেচ লজিক

### ধাপ ৪: রিভিউ এবং ইটারেট

```
> ব্রিফটি অনেক বড় হয়ে গেছে। মডেলের আউটপুট ১,০২৪ টোকেনে (max_tokens) সীমাবদ্ধ করুন।
> ব্রিফ জেনারেট হওয়ার সময় একটি লোডিং স্পিনারও যোগ করুন।
```

Claude অপ্রাসঙ্গিক কোড পুনরায় না লিখে নির্দিষ্ট পরিবর্তনগুলো করে।

### ধাপ ৫: কমিট এবং PR

```
> এটিকে "Add ward-level accountability brief feature" মেসেজ দিয়ে কমিট করুন
> এবং একটি PR তৈরি করুন
```

Claude `git add`, `git commit`, `git push`, এবং `gh pr create` রান করে।

## যেসব প্রম্পট প্যাটার্ন ভালোভাবে কাজ করে

### নতুন ফিচারের জন্য

```
[feature] যোগ করুন। রিকোয়ারমেন্টস:
- [Constraint 1]
- [Constraint 2]
[reference file]-এর বিদ্যমান প্যাটার্নগুলো অনুসরণ করুন।
বিদ্যমান কোনো ফাংশনালিটি পরিবর্তন করবেন না।
```

### বাগ ফিক্সের জন্য

```
[condition] হলে [Function] [error] রিটার্ন করে।
প্রত্যাশিত: [correct behaviour]।
এটি ঠিক করতে ন্যূনতম পরিবর্তন করুন।
আশেপাশের কোড রিফ্যাক্টর করবেন না।
```

### ডকুমেন্টেশনের জন্য

```
[topic]-এর জন্য ডকুমেন্টেশন তৈরি করুন।
অন্তর্ভুক্ত করুন: [specific sections]।
রেপো থেকে আসল কোড এবং কনফিগারেশন রেফারেন্স দিন।
[existing doc file]-এর মতো একই টোন ব্যবহার করুন।
```

### কোড রিভিউয়ের জন্য

```
নিচের বিষয়গুলোর জন্য [file] রিভিউ করুন:
- সিকিউরিটি ইস্যু (বিশেষ করে API key এক্সপোজার)
- CORS হ্যান্ডলিং
- এরর রিকভারি
- অ্যাক্সেসিবিলিটি
লাইন রেফারেন্সসহ নির্দিষ্ট ইস্যুগুলোর তালিকা করুন।
```

## এই ওয়ার্কফ্লোটি কেন কার্যকর

১. **ফুল কোডবেস কনটেক্সট** — ক্লড কোড লেখার আগে আপনার কোড পড়ে
২. **কনস্ট্রেইন্ট-ফার্স্ট প্রম্পট** — ক্লডকে কী *করতে হবে না* তা বলা ফ্রেমওয়ার্ক ব্লট প্রতিরোধ করে
৩. **ইটারেটিভ রিফাইনমেন্ট** — একই সেশনে রিভিউ, অ্যাডজাস্ট, কমিট
৪. **Git-নেটিভ** — ব্রাঞ্চ, কমিট, PR একই টুলের ভেতরে ঘটে
৫. **মাল্টি-ফাইল কোঅর্ডিনেশন** — একটি একক প্রম্পট ফাংশন, HTML, CSS, JS এবং ডকস স্পর্শ করতে পারে
৬. **রিপ্রোডিউসিবল** — প্রতিটি সেশনের কাজ পরিষ্কার মেসেজসহ git-এ কমিট করা হয়
